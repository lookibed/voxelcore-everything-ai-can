# ADR 0005: роли admin/agent и drain-upgrade (02.10.2026)

**Контекст.** Субагент сделал `lab daemon restart` ради своей правки ядра, пока у другого агента было пять живых аренд:
Job Objects убили чужую сессию. Первая заплатка на стороне CLI обходилась `--force`.

**Решение.** Решает демон (`vclab/daemon/admin.py`). Владелец из `[roles] admins` (по умолчанию `user`, `claude`) — `admin`,
остальные — `agent`; заголовок роли только понижает. Операции уровня демона (`stop/restart/upgrade/drain/undrain/reload-core`,
`release --all --force`, `gate accept`, `golden promote`) — только admin. Немедленная операция при чужой аренде —
`foreign-leases`, при живых — `live-leases`. `upgrade` = drain (новые аренды — 503, ждём конца живых, заданий, сеансов play)
+ перезапуск через WMI с `--after-pid`. Всё — в `audit.jsonl`.

**Последствия.** Правки ядра применяются только главной сессией и только когда это никому не мешает. MCP-мост общий, поэтому
в нём нет операций уровня демона, а субагенты передают `as_agent`. Подмену `owner=claude` предотвратить нельзя (локальный
HTTP без секрета) — она видна в аудите.
