# ADR 0007: замеры — только через ворота простоя (01.10.2026)

**Контекст.** Агенты снимали fps, пока шли чужие движки, серверы и пользователь работал; отчёты приходилось помечать
«ПК был занят». Пользователь: проверка ресурсов перед замером должна быть свойством софта.

**Решение.** `lab perf <проект> <сценарий>` (`vclab/quality/perf.py`): ждёт простоя (`[perf]` в `lab.toml`: окно 30 с, не
дольше 600 с; нет чужих движков/Java, CPU посторонних < 15 %, GPU < 15 % до старта своих, ввод пользователя старше 120 с, нет
других работ лаборатории); не дождался — отказ (код 4). Во время прогона снимает загрузку; хоть один занятый снимок —
`contended`. Перф-сценарий пишет проект (`api.perf`), аренды — тестовой сборкой с часами `realtime`.

**Последствия.** `contended`-прогоны не становятся основанием и не сравниваются; перф-регрессия ворот по умолчанию — `warn`.
Пиксельные прогоны на занятом ПК допустимы, их тайминги — не перф.
