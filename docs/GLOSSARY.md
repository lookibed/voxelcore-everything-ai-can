# Словарь

| слово | значение |
|---|---|
| **демон, labd** | процесс лаборатории на Windows-Python (`vclab/daemon`): владеет всеми экземплярами, портами, журналом, прогонами. Общий — порт 25700 |
| **изолированный демон** | второй демон на порту 25800–25849 со своими данными и портами аренд (`lab daemon start --isolated`) — для проверок и правок ядра |
| **starter** | тот, кто поднял изолированный демон; у него права уровня демона на этом демоне |
| **admin / agent** | роли владельца: `admin` — `[roles] admins` (по умолчанию `user`, `claude`), остальные — `agent`; `X-Lab-Role: agent` только понижает |
| **владелец (owner)** | имя из `LAB_OWNER` (`X-Lab-Owner`); чужие аренды менять нельзя (`not-owner`) |
| **аренда (lease)** | один экземпляр одного вида проекта: имя `<проект>-<вид>-<n>`, владелец, TTL (продлевается действиями), порты из пула, каталог `inst\<имя>`, Job Object |
| **вид (kind)** | описание экземпляра в `project.toml` (`[kinds.<вид>]`): exe, аргументы, порты, prepare, готовность, остановка |
| **роль вида** | `test` (умолчание: тестовая сборка, ввод изолирован), `headless` (без окна; сток разрешён), `runtime` (стоковое окно; только `lab play`) |
| **сток, стоковый рантайм** | неизменённый релиз `VoxelCore.exe`; окно — только пользователю (`lab play --user`) и разово главной сессии (`--final-check`) |
| **тестовая сборка, F2F** | VoxelCore с патчем frame-to-frame (`f2f/`): управление по TCP, шаг кадра, снимок из FBO, синтетический ввод, изоляция от ОС |
| **hello** | первая команда F2F: `version`, `flags {clock, input, window}`, размер кадра, GL, сборка. Демон сверяет `flags.input == "isolated"`, часы и `version` |
| **часы virtual / realtime** | `virtual` — кадры только по `step`, время детерминировано; `realtime` — время идёт само (замеры), `step` запрещён |
| **шаг (step)** | F2F `step {ticks, frames}`: N тактов, затем M кадров; в сценарии — любой элемент `steps` (F2F, ядра или плагина) |
| **mode** | F2F `mode {fixed, seed}`: фиксирует время, сидирует ГСЧ, сбрасывает таймеры — кадр после него не зависит от предыстории |
| **слой** | часть кадра (sky, terrain, water, entities, particles, hand, hud...), которую F2F `render` включает отдельно; паритет доказывается послойно |
| **сценарий** | JSON (шаговый или таймлайн) или Lua-тест движка; исполняет интерпретатор демона (`lab run`) |
| **таймлайн** | сценарий по тактам с вводом в заданные такты, ключевыми кадрами `kf_NNNN` и дампами `states.jsonl` |
| **lockstep** | режим, где сервер шагает такт в такт с клиентом через барьер — без настенных часов и случайности |
| **прогон (run)** | каталог `<runs_dir>\<время>_<проект>_<сценарий>` с `report.json`, `journal.jsonl`, логами и снимками |
| **задание (job)** | прогон, идущий в демоне (`lab jobs`, `lab cancel`) |
| **возможность (feature)** | функция плагина, вызываемая `lab call <проект>.<имя>` (MCP `lab_call`, при `mcp=True` — `lab_<проект>_<имя>`) |
| **плагин** | `projects/<p>/plugin.py`: возможности, хуки и шаги сценариев, перф-сценарии; перезагружается горячо |
| **golden** | эталонные снимки сценария: `golden.json` (ключ входов, происхождение, снимки) + PNG + CAS |
| **fresh / stale / unverified** | golden соответствует текущим входам / вход изменился (причина названа) / происхождение части входов неизвестно |
| **CAS** | хранилище по содержимому `<golden_store>\sha256\ab\<sha>.png`: прежние эталоны не теряются |
| **ε (шум эталона)** | насколько эталон расходится сам с собой (прогоны эталона против golden); допуск ворот |
| **храповик ворот** | основание `lab gate`: принятое (`lab gate accept`) или лучшее значение после обновления golden той же версии движка; ворота его не поднимают сами |
| **contended** | прогон, во время которого ПК был занят (`lab perf`, `sysload`): в ворота и сравнения не идёт |
| **foreign** | процесс движка/Java вне аренд и сеансов: сторож показывает его в `lab ps`, не убивает |
| **drain** | состояние демона: новые аренды/прогоны — 503 `draining`, ждём конца живых, потом отложенное действие (`upgrade`, `restart`, `stop`) |
| **upgrade** | drain + перезапуск демона на код с диска; только admin |
| **stale (демон)** | код демона в памяти не совпадает с файлами на диске (`lab daemon status`) |
| **incident** | запись supervisor о смерти службы: `<data>\incidents\<время>_<группа>_<роль>\` (причина, хронология, хвосты логов) |
| **supervisor, группа, служба** | надстройка над арендами: группа служб с порядком старта, health, перезапуском с бэкоффом |
| **коляска (sidecar)** | вид-процесс в `[play].order`, который поднимает составной стек через возможность проекта и печатает строку готовности |
| **play** | `lab play <p> --user`: игра пользователя на стоке с отчётом `play_report` |
| **dry-run** | `lab play <p> --dry-run`: тот же стек, но клиент — тестовая сборка (агентам можно) |
| **final-check** | `lab play <p> --final-check --reason`: разовый запуск стока главной сессией, запись `runtime_session` |
| **work_root** | корень данных этой машины (`machine.toml`): `<work_root>\lab` — данные общего демона, `isolated\<P>` — изолированных, `mcp\` — журнал MCP |
| **vc_root** | (до волны 7) мост к рабочему каталогу паков другой установки; убран — репозиторий самодостаточен: паки `{repo_root}\packs`, `vc_start` — `<work_root>\vc_dev` |
| **engines_root / builds_root** | корни стоковых релизов и тестовых сборок F2F этой машины |
| **версия движка** | id из `engines/registry.toml` (`v031`, `v032`, `v0327`): измерение аренд, истории, ворот и панели |
| **снимок (workbench snapshot)** | приватный репозиторий `lookibed/voxelcore-workbench-snapshot-2026-10`: рабочий каталог, из которого вырос этот репозиторий |
