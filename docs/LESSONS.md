# Грабли

Выжимка из опыта работы с лабораторией, тестовой сборкой и VoxelCore 0.31–0.32.7. Каждый пункт: **симптом** → причина →
что делать. Проектные подробности (порт Minecraft, Olife, wasmrt) переедут в документы проектов; здесь — то, на что
наступит любой агент. Правила пользователя — `docs/RULES.md`; сначала проверь, не ожидаемое ли это поведение.

## 1. Демон и аренды
- **Чужой прогон оборвался `aborted: daemon restart`, аренды стали `dead`.** Процессы аренд живут в Job Object с
  `KILL_ON_JOB_CLOSE` и умирают вместе с демоном. → Общий демон не перезапускать; правки ядра — на изолированном
  (`lab daemon start --isolated`), применяет admin через `lab daemon upgrade` (drain). Мёртвые аренды остаются в `lab ps`
  до `lab release` — освобождать свои явно.
- **Правка ядра «не действует».** Демон исполняет код, загруженный при старте. → `lab daemon status`: `stale`,
  `stale_files {reloadable, restart_only}`. Безопасные модули — `lab daemon reload-core` (admin), остальное — `upgrade`.
  Клиентские правки (`vclab/cli`, `vclab/mcp`, `daemon/client.py`) действуют сразу (MCP — после `/mcp`).
- **`WinError 32` на `leases.json.tmp → leases.json` при параллельных прогонах.** Запись состояния аренд из нескольких
  потоков через один временный файл без замка и повтора (`service._save_state`). **Исправлено 29.10**: снимок под
  `self.lock`, запись под своим замком через уникальный `leases.json.<pid>.<n>.tmp` и `os.replace` с повтором (10 попыток,
  20→500 мс; `decode.write_json_atomic`); не вышло — `state save failed` в `labd.log` и журнал, запрос не падает. Тем же
  путём пишутся `engine_hello.json`, `daemon.json`, `watch_*.json`. Тест — `tests/test_state_stdin.py`.
- **`lab stdin` не видит ответ, хотя строка в логе есть.** Новые строки искались как срез окна последних 512 КиБ лога: когда
  лог больше, число строк в окне не растёт. **Исправлено 29.10**: размер файла лога запоминается перед отправкой, ответ —
  строки после этого смещения (`decode.read_since`), без зависимости от длины лога. Тест — `tests/test_state_stdin.py`.
- **`lab stdin` к VoxelCore `--stdin-cmd` молчит.** На Windows читатель команд движка ждёт `_kbhit()` консоли, а не данных
  канала. → Вид с `stdin_poke = "console"`: демон один раз кладёт событие клавиши в буфер невидимой консоли процесса (без
  окна и фокуса). Всё, что привязано к процессу (консоль, F2F-соединение, pid), сбрасывать при каждом старте, не на аренде.
- **Имена аренд переиспользуются** (`<проект>-<вид>-1` снова и снова). Кэш «что уже отправлено» по имени аренды молча не
  отправил данные новому процессу; фоновый незавершённый скрипт перехватил аренду с тем же именем. → Ключ кэша — аренда + pid;
  перед прогоном проверять, что старые фоновые скрипты не висят; свою группу/аренду брать из ответа `start`/`up`, не из `ps`.
- **Каталог экземпляра переживает аренду.** Флаги и файлы прошлого прогона в `<inst>\export\` включились в следующем. →
  Удалять свои флаги перед стартом или писать их шагом `prepare` каждый раз.
- **Простаивающая аренда грузит GPU** (пак пересчитывает кадры, пока экземпляр жив) — другие агенты видят «GPU busy». →
  Освобождать аренду сразу по окончании.
- **Вид с проваленным `ready` показан `exit 0`.** Демон сам остановил экземпляр. → Смотреть `state` аренды и причину в
  ответе `lease --start`, а не код выхода.
- **БД supervisor и golden общие для всех агентов.** Тестовые ключи тарифов после проваленного прогона сломали следующий. →
  Сценарий убирает свои записи и при провале (хук `stop`); тестовые идентификаторы — свои; писать в БД только через демон.
- **Здоровье службы `{port: "<имя>"}` всегда ложно** у вида с фиксированным портом не из пула — supervisor убивает службу по
  кругу. → Проверять порт, который есть в аренде.

## 2. Тестовая сборка F2F
- **Экземпляр убит `isolation-failed`: `flags.clock want 'realtime', got 'virtual'`.** Ключи `--f2f-clock/--f2f-window`
  оказались после `--` (аргументы проекта), движок их не видел и открыл видимое окно. → Ядро ставит их до `--`; свои
  аргументы проекта — после `--`. `--f2f` после `--` ключом изоляции не считается.
- **`step` отвечает `clock-realtime`.** На часах `realtime` кадры идут сами. → `ready` с `pump_log` в realtime не
  дождётся маркера; для realtime — `{log = маркер, timeout}`.
- **Под `--f2f` тест `--test` не завершается сам.** Цикл F2F не проверяет конец тестового скрипта. → Раннер vctest ставит
  маркер `[lab-vctest] script finished` в копию теста и шлёт `quit`; тест с `return` на верхнем уровне так не обернуть.
- **Ошибка теста 0.32: `0xC0000409` вместо кода 1.** Непойманная ошибка Lua = `abort()`. В часах `virtual` под F2F —
  ошибка приходит ответом `step` (корутина мертва), процесс жив. → Вердикт по коду/ошибке шага; сообщение — в stderr.
- **Кадры одного сценария отличаются на ±1 в 0.1–0.5 % (облака, вода).** Таймер шейдеров копится от открытия мира, а число
  кадров до снимка зависит от реального времени. → Перед снимками паритета всегда `mode` (сбрасывает `u_timer`, анимации,
  сидирует ГСЧ).
- **Своя команда пака перестала отвечать.** Новая команда движка перехватывает одноимённую команду пака (так `perf` пака
  стал `am_perf`). → Команды пака — с префиксом; после обновления сборки проверять лог на `frame error`.
- **Обработчик F2F пака отвечает `{"ok":true,"result":null}` на всё, даже на ошибки.** Обработчик зарегистрирован из
  корутины сценария и запомнил её `lua_State`; корутина кончилась. → Регистрировать из главного состояния Lua (скрипт мира,
  `on_world_open`); см. §4.
- **F2F-ответ с ошибкой ОС роняет движок `utf8 decode error`.** Текст ошибки Windows в cp1251 попадал в JSON. → Санитайзер
  ответа есть в сборках F2F; сообщения Lua, которые попадают в лог, держать в ASCII.
- **Простой F2F рвёт сетевую игру.** Без команд движок не шагает, пак не шлёт пакеты, сервер закрывает сокет через 60 с. →
  `f2f_idle = {cmd = "keepalive", every_s = 1}` у вида; в lockstep — выключить (`--param f2f_idle=false`).
- **Двойной клик через `lab f2f` не срабатывает.** Каждый вызов CLI — старт Windows-Python (~0.2 с), окно двойного клика
  0.5 с. → Постоянный процесс (`bin/labpipe.py`, мост MCP): клик 20–40 мс.
- **`input.keys {"3": true}` выбирает не тот слот.** У движка цифровая строка — имя клавиши «3», у эталона LWJGL — код
  (KEY_2). → Харнесс, работающий с двумя реализациями, переводит цифровые коды.
- **Мышь `input.mouse.dx` теряется при `step{1, frames:0}`.** Движок съедает дельты в каждом проходе, пак применяет взгляд
  только в кадре с отрисовкой. → Держать дельты до шага с кадром.
- **Клик F2F по меню после закрытия мира не доходит.** Курсор остался захваченным (активен «нулевой» фрейм). → Перед
  страницей меню `gui.set_active_frame("core:main")`.
- **`gui.create_frame` даёт белую текстуру при 854×480.** Фрейм рисуется, только если окно не ниже фрейма. → Для таких
  проверок — явный `size` вида/сценария (например, 1408×902), стандарт 854×480 к ним неприменим.

## 3. Плагины и сценарии
- **Правка модуля плагина не действует, ошибки нет.** Демон перезагружает плагин по mtime `plugin.py`; модули, которые
  плагин грузит сам, перечитываются только вместе с ним. → `touch plugin.py` и подождать > 1 с перед `lab run`.
- **Шаг ушёл «как F2F-команда» миру (`kind … has no F2F port`).** Новый шаг ещё не зарегистрирован: plugin.py перечитался,
  когда файла модуля ещё не было, загрузка упала, осталась прежняя версия. → Сначала файл модуля, потом строка в plugin.py;
  `lab projects` → `plugin_error`; `lab journal` → `lab.plugin_load_failed`.
- **Возможность плагина зовёт старый код модуля.** `api.feature("x", mod.f)` связывает функцию при загрузке. →
  Регистрировать обёртку `lambda ctx, a: _mod().f(ctx, a)`.
- **Тест, копирующий плагин во временный проект, падает у всех сразу.** Скопирован только `plugin.py`. → Копировать все
  `*.py` каталога проекта.
- **Поле сценария `params` не дошло до аренды** на демоне со старым кодом. → `lab daemon status`; путь через плагин надёжнее.
- **Демон держит импортированные модули проекта** (сгенерированные кодеки) после их перегенерации. → `importlib.reload` по
  mtime в плагине.
- **Пустая Lua-таблица в ответе F2F приходит объектом `{}`**, таблица с индексами и именованными полями — массивом без
  ключей. → Нормализовать в плагине; в ответах — только именованные поля.
- **`cut -c` по выводу `lab run` обрезал JSON.** → Доказательства — из `report.json` прогона.
- **Ожидание «готово» сработало мгновенно на мусоре.** `lab logs --grep` при пустом результате печатает заголовок `# …`. →
  Фильтровать строки своим `re.search`.
- **Слои в одной сессии расходятся с отдельными прогонами.** Предыдущий слой поменял мир (предмет, меню, слот). → Тело каждого
  слоя начинается с возврата состояния и `mode`; изменения откатывать в конце.

## 4. VoxelCore-Lua и API (проверено запуском)
- **Колбэк из корутины перестаёт работать / роняет процесс («cannot resume dead coroutine» → `0xC0000409`).**
  `f2f.set_handler`, `console.add_command`, сокеты и их колбэки, `set_active_frame` с функцией запоминают `lua_State`
  корутины. → Создавать из главного состояния (скрипт мира, `on_world_open`, первый такт); сценарий только «просит»;
  `set_active_frame` — через `time.post_runnable`. (В меню 0.32 колбэки `network.*` вызываются из главного состояния —
  из корутины app-скрипта их создавать можно.)
- **`package.loaded["pack:name"]` всегда nil.** Модуль лежит под ключом пути: `package.loaded["pack:modules/name.lua"]`. →
  Ленивые ссылки — по полному ключу или `pcall(require, …)`.
- **Непойманная ошибка app-скрипта 0.32 = abort процесса `0xC0000409`.** → Весь app-скрипт под `xpcall`.
- **`app.reconfig_packs({"base", …})` в окне 0.32 — «pack duplication [base]».** Меню уже загрузило `base`. → Добавлять
  только то, чего нет в `app.get_content()`.
- **App-скрипт 0.32 не видит модули пака сразу после `reconfig_packs`.** Контент грузит открытие мира или
  `app.load_content()`. → Сначала загрузка контента, потом `require`. У модуля пака нет `app` — передавать параметром.
- **После `app.close_world()` страница пака падает «expected string, got none».** Закрытие мира выгружает модули и контент
  паков (как и `reopen_world` в этом пути). → Состояние — в таблицах app-скрипта; после закрытия — `reconfig` +
  `load_content` заново. Свежий мир перед `reopen_world` — `app.save_world()`.
- **`app.delete_world` вне headless — не удаление, а невидимый диалог**, первый Enter где угодно удаляет открытый мир. →
  Не звать в оконном режиме; `new_world` поверх папки.
- **`time.uptime()` не годится для замеров.** В F2F — виртуальные часы, в обычном запуске — время начала кадра, внутри
  долгого кадра стоит. `os.clock` шагает по 1 мс. → `time.precise_time()` (0.32, шаг 0.1 мкс) или `time.precise_utc_time()`.
- **`ffi` пакам недоступен**, `Bytearray` — FFI cdata: `ba[i]` — через `__index` на каждый байт. → `ba.bytes[i]` (0-based);
  `FLTview`/`DBLview` поверх Bytearray для перевода float↔байты в трассе LuaJIT отдают устаревшие значения — переводить
  арифметически.
- **`json.tostring` VoxelCore медленный (~16 МБ/с).** → Горячие сообщения склеивать `table.concat` вручную; мерить в
  движке (`lab run <p> bench.lua`).
- **Такт мира «в 10 раз дороже стенда».** Стоковых `maxtrace=1000`/`maxmcode=2048` движку с паком мало: кэш трасс LuaJIT
  сбрасывается целиком десятки раз. → `jit.opt.start("maxtrace=8000", "maxmcode=65536")` в стартовом скрипте; признак —
  `jit.attach(fn, "trace")` и счётчик `flush`. Ветки по данным в горячей арифметике и короткие вложенные циклы плодят
  трассы/чёрный список; ключи таблиц около 1..n рвут трассы — сдвигать в большие числа.
- **Доступ `user:` из пака — `access denied`.** Запись в `user:` — только с правом проекта `write-to-user` (`--project
  vcproject`). `config:<пак>/` — сначала `file.mkdirs`.
- **Ресурсы с одинаковыми именами подменяют друг друга.** Имена моделей и текстур 0.32 глобальные; предметы и сущности
  0.32 — одно пространство имён; текстуры атласа совпали с `base` (`leaves` → `leaves_opaque`). → Уникальный префикс пака.
  Модели, которые ставятся из Lua, — в `preload.json`.
- **Длинного тире «—» нет в шрифте движка** (квадрат). → В текстах UI — «-».
- **Атрибуты XML молча игнорируются:** `pos-func` (верно `position-func`), id у корня макета (корень всегда `root`),
  `visible` корня постоянного HUD-элемента. `color` из Lua — только массив RGBA 0..255. `node.focused = true` у уже
  сфокусированного узла снимает фокус.
- **`get_viewport()` возвращает таблицу `{w, h}`**, `vc.get_version()` 0.32 — два числа; `x and false or y` даёт `y`;
  `res.until` — синтаксическая ошибка (ключевое слово).
- **stdlib 0.32 (`network.get_binary`, `network.post`) не вызывает колбэки** (ошибка внутри stdlib), `network.get` принимает
  только статус ровно 200. → `network.request` и своя проверка `200 <= status < 300`.
- **Консоль движка превращает аргумент `none` в nil**, аргумент, начинающийся с цифры, — не строка, `/` — недопустим. →
  Префиксы и другие слова; проверять ответ команды.
- **`audio.play_stream` 0.32.1 навсегда занимает источник** (лимит 255). → Короткие звуки — `PCMStream` → `create_sound` →
  `play_sound`; массовые `block.place` — тоже звук каждого.
- **Пустой аргумент проекта (`--auth ""`) сдвигает следующие** — они не доходят до `vc.get_project_arg`. → Новые аргументы
  ставить до пустых или не передавать пустые.
- **`network.tcp_open` 0.32 слушает все интерфейсы.** → Закрывать не-loopback соединения в обработчике; проверять netstat.

## 5. Паритет и детерминизм
- **Повтор эталона расходится с самим собой.** Состояние «за кадр» (сглаживание, таймеры) не сбрасывается `mode`, а число
  кадров до `mode` разное. → Сначала эталон против эталона и порт против порта, потом порт против эталона; искать поля,
  которые обновляются в рендере.
- **Частицы движка между прогонами разные.** Генератор эмиттера сидируется адресом в куче. → Случайность, от которой
  зависит кадр, — из своего сидированного генератора пака.
- **`HashSet`/`HashMap` с плохим `hashCode` недетерминирован между запусками JVM.** → Ловится только сравнением потоков по
  тактам; сервер — в lockstep с харнессом.
- **Сервер недетерминирован, пока догенерирует мир.** → Тестовый мир — полностью сгенерированный и сохранённый (`/stop`),
  неподвижный под случайными тактами.
- **1 пиксель расходится в одной паре из трёх.** → Не списывать на «шум»: держать в списке открытых, пока не найдено.
- **«N одинаковых кадров подряд» — ложная готовность**: меши за спиной перестраиваются невидимо. → Ждать по событию/счётчику,
  а не по стабильности кадра.
- **«Регрессия» оказалась ожиданием**: высокополигональный скин, лёд ближе тумана, реальное время против виртуальных часов,
  заставка-переход Doom. → Числовой зонд/отладочный шейдер/сверка с записями прежде правок.

## 6. Производительность и замеры
- **Замер при занятом ПК неотличим от регрессии** (23 fps вместо 59 при чужих сборках). → Только `lab perf`; `contended` в
  выводы не идёт. Фон GPU рабочего стола бывает 23–40 % — `GPU busy` в `lab sysload` ещё не чужая аренда: смотреть `lab ps`.
- **Своя аренда сама даёт «GPU busy»** (в том числе хвост прошлого прогона и экземпляр без vsync). → Судить по снимкам до/после
  и посторонним процессам.
- **Сравнение exe между процессами бессмысленно** (разброс 10–30 %). → A/B внутри одного процесса чередованием или
  подряд одним сценарием; 2–3 прогона.
- **Первый прогон в свежем `--dir` медленнее** (мир генерируется, шейдеры компилируются). → Сравнивать со второго.
- **Профиль «по Lua» не показал узкое место** — оно в движке (свет, меши). → Мерить профилировщиком тестовой сборки (F2F
  `perf`), а не догадками.

## 7. Windows, WSL, кодировки, пути
- **Из WSL не подключиться к F2F-порту.** WSL в NAT не видит `127.0.0.1` Windows. → Всё сетевое к экземплярам — через
  демон (Windows-Python): CLI, мост, labpipe.
- **Переменная окружения не дошла до Windows-Python** (`LAB_SKIP_ENGINE`). → `WSLENV=<имя>` (обёртка `bin/lab` передаёт
  `LAB_OWNER`, `LAB_PORT`, `LAB_ROLE`, `LAB_TTY`, `LAB_MACHINE`).
- **Шаблон по логу Windows не совпадает.** Логи консоли — cp866, сообщения Windows — cp1251, движок — UTF-8. → Лаборатория
  декодирует построчно (`vclab/scenario/decode.py`); вручную — `iconv -f cp866`.
- **Python на Windows падает на выводе (`◐`).** → `python.exe -X utf8`.
- **SQLite через `/mnt/d` из WSL портит/блокирует.** → Историю и БД supervisor пишет только демон.
- **Правка файла Python-скриптом превратила CRLF в LF** — дифф на весь файл. → Читать/писать с `newline=''` или в бинарном
  режиме; `git -c core.autocrlf=input`.
- **Часы WSL уплывают от Windows на секунды.** → Возраст строк логов Windows считать по времени Windows.
- **`.bat`: `--dir "%~dp0"` экранирует кавычку.** → `"%~dp0."`.
- **Брандмауэр не фильтрует соединение с собственного LAN-адреса** — тест «друг по сети» на одной машине проходит без правила.
  → Для настоящей сети — правило по портам.
- **Петля — весь 127.0.0.0/8**: разные «IP игроков» на одной машине — привязка клиента к `127.0.0.x`. Никогда не банить
  `127.0.0.1` и `127.0.0.0/24` целиком.

## 8. Процессы, фоновые задачи, ожидания
- **`pkill -f <шаблон>` / `kill $(pgrep -f …)` убил свою же оболочку (exit 144).** Шаблон есть в командной строке самого
  `bash -c`. → Останавливать по pid или шаблоном `[x]yz`, отдельным вызовом.
- **`Monitor`/фоновый `grep` молчал до таймаута** (четыре раза по 2–30 мин): шаблон не совпадал или лог в cp866. → Шаблон
  проверить на существующем логе; ждать инструментами с условием.
- **Фоновый Bash убит через 10 минут.** → Долгое на Windows — отдельным процессом с логом (`Start-Process
  -RedirectStandardOutput`), ждать по логу.
- **Инструменты «зависали» по секунде на вызов.** Новый `powershell.exe` на каждый вызов стоит ~0.9 с. → Постоянный
  процесс-воркер (так устроен MCP `voxelcore`).
- **`latest.log` прошлой сессии потерян.** Движок перезаписывает его при старте. → Демон зеркалит `[watch]`-логи в
  `<data>\logs\`; чужой лог копировать до своего запуска.
- **`/tmp` WSL очищается при перезапуске сессии.** → Вспомогательные скрипты — в scratchpad задания или в репозитории.

## 9. Субагенты и параллельная работа
- **Два агента дрались за движок; закончивший агент продолжал действовать.** → Один владелец, очередь; закончивший, но
  активный агент — остановить, не переписываться.
- **Убитый агент оставил незакоммиченные правки и собранный непроверенным бинарником артефакт.** → В начале сессии — `git
  status` и сверка артефактов с исходниками, прежде чем собирать поверх.
- **Общие файлы правили несколько агентов одновременно** — замена не нашла текст и ничего не записала, или пакетная правка
  упала на середине. → Точечные замены с проверкой `count == 1`, свежее чтение прямо перед правкой, новое — в свои модули;
  проверять, что дошли все замены.
- **Свои `CARGO_TARGET_DIR` и черновики съели десятки ГБ.** Диск WSL не сжимается сам. → Общий каталог сборки,
  временное — в scratchpad, крупные удаления — сообщать пользователю.
- **Агент запустил стоковое окно «для оценки» по формулировке задания.** → В заданиях не просить стоковое окно; запрет ввода
  ОС — явной строкой.

## 10. Сборка движка
- **Сборка MSVC дала другой LuaJIT.** → Только релизный рецепт (MSYS2 CLANG64, vcpkg `x64-mingw-static`, снимок vcpkg на дату
  релиза → тот же LuaJIT), сверка `--version`, `jit.version`, дампа окружения, импортов DLL (`f2f/README.md`). Побайтно не
  совпадёт (другой снимок MSYS2) — это нормально.
- **Зеркала MSYS2 отваливаются по таймауту.** → Первым поставить рабочее зеркало, `--disable-download-timeout`.
- **`VCPKG_ROOT` указывает не на тот vcpkg** — линкуется не та LuaJIT. → Тот vcpkg, которым ставились пакеты.
- **MSYS git на worktree из WSL не видит путь `/mnt/d/...` в `.git`.** → Переписать в `d:/...`, `--git-dir`,
  `core.autocrlf=input`.
- **C++: `"a\x01b"` — это `\x01b`.** Шестнадцатеричные escape жадные → разбивать литерал.
- **Незакоммиченные правки пользователя в исходниках движка** — не включать в коммиты F2F.

## 11. Паки
Выжимка из `agents/LESSONS.md` старого каталога (копия — `projects/_snapshot_agents_docs/LESSONS.md`, разделы «LuaJIT»,
«VoxelCore», «Фреймы GUI в текстуру», «Порт паков и мира на 0.32.1», «gpu_compute», «LLM на wasmrt»). Каталог паков —
`docs/PACKS.md`, перенос на свежий движок — `docs/PORTING.md`.

### Spider и LuaJIT
- **`function or expression too complex` / `control structure too long` / `chunk has too many syntax levels` /
  `too many upvalues` при загрузке модуля wasm-пака.** Лимиты LuaJIT: > 250 слотов кадра, прыжок > ±32767 инструкций,
  > 200 уровней вложенности, > 60 upvalue. → Это чинится в Spider (разбиение функций, таблица кадра), не в паке: пересобрать
  модуль свежим Spider (ветка `voxelcore-bytearray-memory`), сгенерированный Lua руками не править.
- **Функция wasm-пака целиком идёт в интерпретаторе (в 10–100 раз медленнее).** Замыкания на каждый вызов (`FNEW`) LuaJIT
  не компилирует; короткие вложенные циклы (1–3 итерации) попадают в чёрный список; таблица трасс переполняется. →
  `jit.opt.start("maxtrace=8000", "maxmcode=65536", …)` в стартовом скрипте (smollm: `wasm.json` против
  `wasm_jitdefault.json`), горячий код — плоским; в Java (TeaVM) — `double`, не `float`.
- **Лимит LuaJIT другой версии.** Обычный `luajit` в WSL — не та версия, что в движке (2.1.1771261233 у 0.31). → Поведение
  проверять только запуском движка (`docs/RULES.md`).

### Bytearray, `bit`, память
- **Память wasm медленная или значения float «старые».** `Bytearray` — FFI cdata без доступа к `ffi` у пака: `ba[i]` идёт
  через `__index`; `FLTview`/`DBLview` поверх той же памяти в трассе отдают устаревшее значение. → `ba.bytes[i]` (0-based),
  float↔байты — арифметикой; `Bytearray:copy/fill/move` (0.32) — только с проверкой бит в бит.
- **`bit` ведёт себя не как в стоковом LuaJIT.** В VoxelCore свой `bit` (с `compile`/`execute`), обёртка `error` подменяет
  место ошибки. → Стек — `debug.traceback(co)`; wasmrt пишет `[wasmrt] crash` со стеком.
- **`crypto.*` / `assets.parse_model` «string expected» на Bytearray.** → Переводить в строку (`Bytearray_as_string`) кусками.

### GUI в текстуру, шейдеры UI как GPU
- **Экран ПК (`pc_wasmrt`) белый/серый в кадре 854×480.** `gui.create_frame` рисует фрейм, только если окно не ниже фрейма
  (1024×724). → Для ПК — `--param size=1408x902`; это не поломка порта.
- **Два GPU-пака вместе — один перестаёт считать.** Движок берёт `shaders/ui.glslf` только одного пака. → Все GPU-клиенты —
  через `gpu_compute` (общий `ui.glslf` — артефакт сборки, пересобрать при добавлении клиента); цена — регистры по
  максимуму программ (~5 % ток/с у LLM).
- **Фреймы рисуются не в том порядке / данные фрейма пропали.** Порядок — `unordered_map` движка; фрейм очищается каждый
  кадр. → Зависимые проходы — в один кадр по явной цепочке, постоянные данные — в canvas-текстурах, не во фреймах.
- **Результат GPU не совпадает с C бит в бит.** → fp64 (`GL_ARB_gpu_shader_fp64` в `ui.glslf` работает на 0.31 и 0.32),
  целые < 2^47 в double, фиксированная точка для параметров.
- **canvas «вверх ногами».** Строка 0 canvas-текстуры — внизу; на 0.32 `canvas:encode` PNG больше не переворачивает. →
  Golden кадров после 0.32 сверять с этим в уме.
- **Постэффект пака не виден в меню.** Постэффекты работают только в мире. → В меню — бэкенд `canvas` (`wasm_canvas.json`).

### Аудио
- **После ~255 звуков «limit is 255», звук пропадает (0.32.1).** `audio.play_stream` не освобождает источник OpenAL. →
  Короткие звуки — `audio.PCMStream` → `create_sound` → `play_sound` (так в `blackhole`).
- **Прогоны слышно у пользователя.** Экземпляры без `settings.toml` играют звук на устройство по умолчанию. → `[audio]
  enabled = true`, `volume-master = 0` в подготовке вида; звук в аренде wasmrt — `--param audio='"true"'` (строка JSON).

### Ресурсы ПК и данные
- **Замер тяжёлого пака «упал» на 10–30 %.** ПК занят (ввод, GPU другого процесса), JIT не прогрет, виртуальные часы. →
  Только `lab perf` (не `contended`), сверка с README/OPTIMIZATION пака; Doom 120 fps старого пака — виртуальные часы.
- **smollm/smollm_gpu/eaglercraft/halflife занимают сотни МБ кучи и минуты загрузки.** → Не гонять параллельно с другими
  тяжёлыми прогонами; вес и данные — в `catalog/packs.toml` (`size_mb`, `depends_external`).
- **Пак после клона не запускается: нет `doom1.wad`, `pak0.pak`, весов, `eaglercraft.lua`.** Данные игр (`*.wad`, `*.pak`,
  `*.epk`), веса и большие сгенерированные модули — вне git (`.gitignore`). → Брать из снимка
  `lookibed/voxelcore-workbench-snapshot-2026-10` или пересобрать Spider; список — `depends_external` в каталоге.
