# Грабли и решения

## LuaJIT (движок: 2.1.1771261233, коммит 1c3b5a4d)
| Ошибка LuaJIT | Причина | Решение в Spider |
|---|---|---|
| `function or expression too complex` | > 250 слотов кадра (широкие вызовы, упакованные зависимости) | `rt_call_spread(f, {args}, n)`, зависимости `Scoped` одной таблицей (`frame_slots`, `WIDE_CALL_ARGUMENTS = 40`, `FRAME_SLOT_BUDGET = 220`) |
| `control structure too long` | прыжок > ±32767 инструкций | куски длинных последовательностей в `do (function() … end)() end` (4000/2000 строк, ≤ 50 имён); у TeaVM-функций — кадровый режим |
| `chunk has too many syntax levels` | > 200 уровней: вложенные `else` (TeaVM проверяет исключение после каждого вызова) **и** подряд идущие метки (`parse_label` рекурсивен) | плоский `if … goto skip end … ::skip:: do end` глубже 48 отступов; кадровый режим (локальные в `__spider_frame`, ветви в `__spider_parts`) при вложенности > 40 |
| `too many upvalues` (> 60) | замыкание видит много локальных | упаковка зависимостей в таблицу; в кадровом режиме — одна таблица кадра |
| ambiguous syntax | строка с `(` продолжает предыдущее выражение | префикс `do` перед вынесенным куском |

## TeaVM 0.10.2 (Java → wasm, legacy backend с линейной памятью)
- Нет JSO/WebGL — нужна своя платформа (`src/vc`). Нет `Class.newInstance` (рефлексия) — генерировать
  фабрики (`VcReflect`). В classlib нет `java.nio.file` и некоторых методов (`Integer::sum`,
  `Map.merge` с ним) — ошибка «Method … was not found» при `generateWasi`.
- Инлайнинг раздувает функции до 56 КБ wasm — `optimization = OptimizationLevel.NONE`.
- Куча по умолчанию мала: `maxHeapSize = 160` (МБ). Полная сборка мусора с дефрагментацией на Lua идёт
  минутами — явный `System.gc()` убран (в эталоне TeaVM JS он ничего не делает).
- Приведение `(int)` float→int выдаётся ловушечным `trunc` — нужен `--saturating-truncation`
  (иначе `(int)NaN` роняет игру: `MathHelper.sin` ← `EntityRenderer.hurtCameraEffect`).
- Баг: `switch` в `try` внутри `while` с `continue` → невалидный wasm (сервер `IntegratedServer`).
- `System.err` → WASI fd 2 работает; сообщение исключения печатается перед стеком.
- Импорт `teavm.nanoTime` должен возвращать **миллисекунды** (double): `TSystem.nanoTime()` для wasm
  умножает его на 1e6 (`javap -c` по `teavm-classlib.jar`). Хост отдавал наносекунды — таймер
  Minecraft получал время в 10⁶ раз больше и выдавал ~40 тиков/с. `System.currentTimeMillis()` →
  WASI `clock_time_get(0)` → у хоста `time.utc_time()` с шагом 1 с — для `steadyTimeMillis` не годится,
  берём `CLOCK_MONOTONIC` через `Wasi.clockTimeGet` самого TeaVM (второй `@Import` с тем же именем
  TeaVM не собирает).
- Функции с вложенностью > 40 Spider печатал в «кадровом режиме» с замыканиями на каждый вызов —
  байткод `FNEW` LuaJIT не компилирует, и вся функция плюс вызывающий цикл шли в интерпретаторе
  (VcGL.emitClipped, World.updateLightByType и ещё 181 функция). Теперь части создаются один раз
  фабрикой и получают таблицу кадра параметром. Держать горячие Java-методы маленькими и плоскими
  всё равно полезно: проверки TeaVM на каждом доступе к массиву дают глубокую вложенность.
- В lua-no-ffi каждая операция над `float` — распаковка и упаковка битов (`math.log` и т. д.),
  а `double` — нативные операции LuaJIT. Горячую математику в Java писать на `double`.
- HUD Eaglercraft (хотбар, чат, F3) рисуется во FBO (`GameOverlayFramebuffer`, `EntityRenderer`),
  а не прямо на экран, как в ванильной 1.5.2; прицел — с инвертирующим смешиванием
  `(ONE_MINUS_DST_COLOR, ONE_MINUS_SRC_COLOR)`. `ConfigConstants.panoramaBlur` перезаписывается в
  `GuiMainMenu.initGui` по наличию ресурса `title/no-pano-blur.flag` — выставлять флаг в коде бесполезно.

## Eaglercraft
- Браузерная платформа (`src/teavm`) — эталон семантики; десктопная (`src/lwjgl`) — только сигнатуры.
  Стаб, вернувший «безопасное» значение, может сломать логику: `connectionOpen()` (не пускал пакеты входа),
  `clientLANClosed()` (без LAN должно быть `true`).
- Обратная глубина: `glClearDepth(1)` → `_wglClearDepth(-1)` (WebGL зажимает в 0), `LEQUAL` → `GEQUAL`.
- Пиксели текстур приходят ARGB-числами (байты B,G,R,A): шейдер берёт `.bgra`, при `CC_swap_rb` — `.rgba`.
- Экран на 1 кадр/с — не «зависание»: `Timer.updateTimer` при кадре > 1 с сбрасывает часы и не даёт
  тиков, поэтому пакеты не читаются, загрузка не завершается.
- `GuiSlot.drawScreen` вычитывает очередь мыши, пока кнопка не зажата: внедрённый клик должен держаться
  несколько кадров (`VcInput.injectClick`, 3 кадра).
- Первый запуск всегда показывает «Edit Profile» (хранилище не сохраняется); changelog отключён
  флагом `seenAcknowledgementsSP2` в `MinecraftMain`.

## VoxelCore
- Постэффекты работают только в мире; uniform-массивы до ~1018 `vec4`; значения по умолчанию векторов —
  JSON (`[160, 100]`). `packed` — зарезервированное слово GLSL.
- Шейдер `ui.glslf` из пака подменяет шейдер UI движка — режимы включаются цветом-маркером картинки
  (`#FF00FF80` палитра, `#FF01FF80` треугольники); текстура canvas перевёрнута (строка 0 внизу).
- `app.config_packs` требует явный `base`; эффект из пака грузится без префикса.
- Обёртка движка над `error` (`core:modules/internal/debugging.lua:149`) подменяет место ошибки —
  стек смотреть через `debug.traceback(co)` (wasmrt пишет `[wasmrt] crash`, переводит `eag_crash`).
- Данные сокета: `Bytearray_as_string(socket:recv(n))`; разбор буфера — по индексу, не `sub` на каждый
  кадр (квадратично на мегабайтах).
- `pkill -f <шаблон>` из той же оболочки убивает саму оболочку, если шаблон есть в её командной строке.

- Панорама меню: `makeViewportTexture` заполняет текстуру остатками общего буфера `RenderEngine.imageData`;
  пока копия экрана (`glCopyTexSubImage2D`) не сделана, финальный квад показывает эту «резкую повёрнутую
  картинку со швом». В WebGL копия всегда раньше чтения, у нас снимок считается на CPU — первую цепочку нужно
  досчитывать в том же кадре.
- Захват курсора на странице меню: `gui.set_active_frame("")` (null-фрейм захватывает курсор). **Отпускать —
  `gui.set_active_frame(gui.main_frame_id)` (`"core:main"`)**: `gui.get_active_frame()` возвращает id корневого
  элемента (`"root"`), а `set_active_frame("root")` оставляет null-фрейм — курсор так и оставался захваченным
  (проверено пробой). Дельты — `input.get_mouse_delta()`. Esc на странице меню движок обрабатывает как «назад»
  (`stdlib.lua`), перехватывается обработчиком с владельцем `document.root`, возвращающим `true`.
- Колеса мыши в Lua нет (`input`: только кнопки/курсор). Прокрутку получает `panel scrollable="true"
  max-length=... scroll-step="1"` под курсором (±1 за щелчок, свойство `scroll`; сброс в середину, -1000 —
  -100000 уже не прокручивалось); при захваченном курсоре GUI прокрутку не отдаёт вовсе.

## Браузерная вёрстка (пак `html`, litehtml, 29.09)
- Имена клавиш VoxelCore: `page-up` / `page-down` (не `pageup`), `home`, `end` — `vc_key_down("pagedown")`
  молча всегда 0. Проверено в движке: PageDown прокрутил страницу только после смены имени.
- `vc_time_ms` (= `time.uptime()`) внутри одного тика движка не растёт: замеры программы по нему в движке
  грубые (`events+js 0 ms`), сравнивать с прогоном в стоковом LuaJIT.
- Вызов `run_tool.py` идёт ~1–2 с: состояние, живущее меньше (уведомление на 1.8 с), скриншот не застаёт —
  не баг вёрстки.
- litehtml upstream: `refresh_styles` (`:hover`) терял стили из атрибутов (`<img width>`), `var()` в
  шорткате перекрывал более поздние правила, у flex-контейнеров не было `get_placement`, `position::round`
  несимметричен относительно нуля — всё в `patches/0001-litehtml-wasmrt.patch` Spider.

## Фреймы GUI в текстуру (`gui.create_frame`, компьютер pc_wasmrt:pc, 29.09)
- `gui.create_frame(id, текстура, {w, h})` рендерит документ в FBO каждый кадр (до 2048²); текстуру
  можно дать скелету (`set_texture("$0", ...)`), ориентация правильная (верх документа — v=1 модели).
  Подменённый паком `ui.glslf` действует и во фрейме: палитра Quake на GPU и треугольники Eaglercraft
  рисуются в текстуре экрана. Фрейм не удаляется (API нет): повторный `create_frame` с тем же id заменяет.
- Активный фрейм (`set_active_frame(id, locator)`) = курсор ОС отпущен (`Engine::renderFrame`), игрок
  не управляется (`LevelScreen`: inputLocked); locator отдаёт точку в координатах фрейма, GUI сам
  прибавляет сдвиг фрейма (`viewport.y - h`); `wpos` элементов фрейма уже со сдвигом.
- **locator — каждый раз новое замыкание.** Движок хранит функцию в таблице лямбд под именем из её
  адреса и стирает запись при уничтожении прежнего поставщика: та же функция второй раз → запись
  стёрта, locator вернул nil → `uncaught exception: invalid value returned from locator`, движок
  падает. Ошибка внутри locator тоже роняет движок — `pcall`.
- `set_active_frame` с функцией нельзя звать из корутины app-скрипта: лямбда запоминает lua_State
  корутины, вызов из GUI портит её («cannot resume dead coroutine» каждый кадр) — через `time.post_runnable`.
- `element:add(xml)` берёт один корневой элемент: несколько подряд — добавится только первый.
  `onclick` у `<image>` без `interactive="true"` не срабатывает (наведение у контейнеров есть).
  `events.on/emit` — только с префиксом установленного пака (`pc_wasmrt:...`), иначе «pack prefix required».
- `input.add_callback` в мире живёт до выхода из мира (владелец игнорируется, если HUD есть);
  обработчики вызываются от последнего к первому; движковый Esc назначается до `on_hud_open` паков.
- Eaglercraft падает в мире с дождём/снегом: `StrictMath.log` из `EaglercraftRandom.nextGaussian`
  (`EntityRenderer.renderRainSnow`) получает nil вторым аргументом (строка 1835543 модуля) — и на
  странице wasmrt (`eag_saved_world`), и на компьютере; баг трансляции, не хоста. **Причина (Spider):**
  каждая поднятая функция несёт хвостовой «trap token» (упорядочивает эффекты в графе), и прямые вызовы
  передавали его и импортам хоста — Lua-функция хоста видела на один аргумент больше, чем в типе wasm.
  Большинство импортов лишний аргумент игнорируют, а `math.log(x, token)` — логарифм по основанию `nil`.
  Фикс (импорты без токена: `load_call_arguments` в Builder всех трёх целей, Lifter, IR) и регрессионный тест
  `Conformance/tests/host_imports.rs` лежат в Spider **незакоммиченными и непроверенными** — агент был
  убит на середине (см. STATUS). Сценарий воспроизведения: `scenario_run("eag_rain")`.

## AlphaMine (сборка движка и F2F, 30.09)
- **Собирать только релизным рецептом** (`.github/workflows/windows-clang.yml`): MSYS2 CLANG64 + vcpkg `x64-mingw-static`,
  `MinGW Makefiles`, Release. MSVC-сборка из `CMakePresets` даёт другой LuaJIT (vcpkg `2.1.0-beta3`) и DLL — для
  паритета с рантаймом не годится (первая попытка была такой, выброшена).
- Ревизии: рантайм `VoxelCore.exe` — CI-сборка `main` 26.02 (время линковки в PE: `objdump -p | grep Time/Date`,
  15:23Z); vcpkg брать master на этот момент (GitHub API `commits?until=`) — `29f10019`, его `ports/luajit` = `1c3b5a4d`
  = `LuaJIT 2.1.1771261233`. Исходник того же дня — `454aa205`; у `main` (30.03) в Lua есть лишнее
  (`file.__seek_descriptor`). Сравнивать окружение дампом (`engine/tests/env_dump.lua`) рантайма и сборки, адреса вычищать.
- Побайтно не совпадёт без снимка MSYS2 на ту дату (рантайм: clang 21.x, CRT с `.debug_*`, +560 КБ); сегодня clang 22.1.8.
- MSYS2 без инсталлятора: `msys2-base-x86_64-latest.sfx.exe -y -oC:\`. С этого ПК mirror.msys2.org/repo.msys2.org
  отваливаются по таймауту — первым поставить `mirror.yandex.ru` в `mirrorlist.mingw/msys`, `--disable-download-timeout`.
- `src/CMakeLists.txt` при static-триплете линкует `$VCPKG_ROOT/packages/luajit_<triplet>/lib/libluajit-5.1.a` —
  `VCPKG_ROOT` обязан указывать на тот vcpkg, которым ставились пакеты. Первый configure (22 порта) ~18 мин, сборка ~2 мин.
- Ветка в исходниках — `main` (не `master`); незакоммиченные правки пользователя (`libquat.cpp`, `Entity.cpp`) в коммиты
  F2F не включать. Вторая ревизия — через `git worktree` (`voxelcore-454aa205`), патч переносится `cherry-pick` без конфликтов.
- Офскрин-кадр без правки рендера: заменить указатель GLEW `__glewBindFramebuffer` обёрткой «0 → наш FBO» (работает и с
  DLL-, и со статическим GLEW). Кадр побайтно одинаков при обычном, перекрытом и свёрнутом окне; MSVC- и MinGW-сборки
  дали один и тот же sha256 снимка меню.
- Из WSL (NAT) нельзя подключиться к `127.0.0.1` Windows: TCP-клиенты F2F запускать Windows-питоном (`C:\Python313`).
- `dv::object` неупорядочен: порядок ключей JSON теряется. `dv::object({{"k", "literal"}})` не компилируется —
  нужен `std::string("literal")`.
- Синтетическая мышь: реальная позиция курсора в `GLFWInput` на старте (0,0) — не сравнивать новую позицию с
  «предполагаемой» (так клик в центр сначала потерялся); после `toggleCursor` первый сдвиг без дельты — F2F взводит его.
- GLFW-окно в F2F: `GLFW_FOCUSED=false`, `GLFW_FOCUS_ON_SHOW=false` — не отбирает фокус у пользователя.
- Слои рендера F2F (§7): `ChunksRenderer::drawChunks` не только рисует — он строит меши и порядок видимых чанков, по
  которому идёт прозрачный проход. Выключив его целиком для `terrain:false`, получил пустую воду (100 % фона); ворота —
  только на `mesh->draw`. Там, где у отрисовки есть побочные эффекты (`particles->render` удаляет умершие частицы,
  `entities->render` считает матрицы скелетов, блок-обёртки), слой гасить `glColorMask`/`glDepthMask` (`render::Mask`),
  а не пропуском вызова. Внимание: при `glDepthMask(false)` `glClear(DEPTH)` не чистит — не заворачивать в маску блоки
  с `clearDepth()` (рука).
- `lighting:false` без правки шейдеров: свет вершины чанка = 1.0 и emission = 1.0 (в `BlocksRenderer::vertex`),
  `u_torchlightColor = 0`; deferred-проход берёт `max(ssao*тени, emission)` = 1. Меши строятся в потоках — при
  переключении эпоха++, `clear()` и отброс результатов старой эпохи; перестройка идёт ≤ 4 чанка за кадр, поэтому
  после переключения нужно ≥ чанки/4 кадров (1513 чанков → ~480). «N одинаковых кадров подряд» — ложная готовность:
  чанки за спиной меняются невидимо (так «all → слои → all» сперва дал 2.4 % разницы на горизонте).
- Туман выключается uniform'ами (`u_fogFactor=0`, погодный туман `opacity 0`) — `calc_fog()` даёт 0. Облака между
  процессами отличаются на ±1 в 0.1 % пикселей — это шум, не патч (одинаков для старого и нового exe).
- `clear` = байты 0..255, как у Java `F2FRender`; без неба кадр заливается треугольником на глубине фона неба (`1-1e-6`),
  в меню — повторной очисткой в `MenuScreen::draw`. Глобально перехватывать `setBgColor` нельзя: им же чистят
  превью блоков и UI-фреймы в текстуры.
- Файлы движка с CRLF (`ChunksRenderer.cpp`): правка Python-скриптом в текстовом режиме переводит весь файл в LF —
  `git diff` на 800 строк. Открывать с `newline=''`.

- **Java-сторона слоёв (30.09).** Лишний `RenderGlobal.loadRenderers()` для перестройки света прячет сущности на 2 кадра
  (`renderEntitiesStartupCounter`) — слой `entities` дал пустые снимки; а `updateAllRenderers` пропускает чанки без неба
  (`isChunkLit`). Нужна своя пометка всех чанков (`f2fMarkAllDirty`). Рамка выделения альфы чёрная — на чёрном `clear`
  её нет, сценарий слоя снимать на белом.
- **Сервер альфы недетерминирован, пока догенерирует/заселяет чанки**: заселение соседа меняет блоки и свет уже
  отправленного чанка, а клиент узнаёт это то данными чанка, то пакетами блоков — 12 пикселей света на дальнем склоне в
  1 из 2 прогонов. Лечится миром, где всё уже сгенерировано и заселено (`golden\world_b` = прогон + `/stop` оператором:
  сервер сохраняет всё), а не масками. Заодно ожидание чанков после `/tp` втрое короче: ~3.5 чанка/с было генерацией,
  а не сетью. Автосейв сервера (раз в 4 тика, частичный) и `Stop-Process -Force` не дают полного мира — только `/stop`.
- **Launchwrapper (mcphackers 1.2.4) перекачивает «custom»-ассеты при каждом старте**: у 13 записей индекса a1.0.14
  хэш не сходится (по url отдаётся страница «301 Moved», 536 байт) → 26 https-запросов ≈ 20 с до `main`. Копия индекса
  с `url: file:///…` на локальную копию тех же байтов — 2 с до F2F `hello`, игра получает те же файлы.
- **RetroMCP 1.2 `recompile --side=client` пересобирает и сервер** (параметр игнорируется) — пока у другого агента работает
  сервер из `minecraft_server\bin`, собирать клиент `ref/compile_client.ps1` (javac, JDK 8, только указанные файлы).
- **`am_server stop` раньше убивал все серверы Java** (`MinecraftServer` в командной строке) — с двумя агентами это
  чужой сервер. Теперь сервер помечается `-Dalphamine.dir=<каталог>` и останавливается только свой.
- **F2F `input.keys`**: строка из цифр — код клавиши, не имя (`"3"` = `KEY_2`), об этом легко споткнуться при выборе слота.
- В одной сессии слои идут подряд: тело каждого слоя начинается с `look` (вернуть взгляд) и `mode` — тогда снимки
  побайтно равны отдельному прогону сценария; то, что слой меняет в мире (выброшенный предмет, открытое меню, слот),
  должно либо не влиять на следующие слои, либо откатываться в конце (меню закрывается ESC, слот возвращается).

## AlphaMine — пак и сеть (фаза 2, 30.09)
- **Обработчик F2F регистрировать только из главного состояния Lua** (скрипт мира, `on_world_open`). `f2f.set_handler`
  из корутины сценария (`alphamine_f2f.lua`) запоминает `lua_State` корутины (`lua::create_lambda`): после конца
  сценария каждая команда отвечает `{"ok":true,"result":null}` — и ошибки тоже, без записи в лог. То же для колбэков
  `network.tcp_connect`: подключаться с первого такта мира (`game.request_connect`), а не из корутины сценария.
- **`on_world_tick` при шаге 50 мс идёт через кадр**: `Clock::update` срабатывает при `timer > 1/20` строго, а
  `LevelScreen` ещё режет дельту уровня до 0.2 с. Такты альфы считать по `time.uptime()` (в F2F — виртуальные часы) и
  догонять пачкой; в F2F дополнительно догонять в начале каждой команды обработчика (харнесс зовёт её после каждого
  `step`). Без этого пакеты уходили раз в 100 мс парами, и сервер (шлёт по одному MapChunk на пакет движения,
  `EntityPlayerMP.onUpdateEntity`, очередь < 2) отдавал 441 чанк за 27 с вместо 15 с.
- **Java шлёт движение дважды за такт**: `runTick` → `thePlayer.onPlayerUpdate()` (всегда) и `world.updateEntities` →
  `onUpdate` (только если чанки в ±16 блоков есть, `World.updateEntity`/`checkChunksExist`), пакеты читаются после них
  (`WorldClient.tick`). Порядок и число пакетов влияют на скорость загрузки мира.
- **Простой F2F рвёт соединение с сервером**: без команд движок не шагает, Lua не работает, пакеты не уходят, сервер
  альфы через 1200 тактов тишины (60 с) закрывает сокет. Java-клиент шлёт KeepAlive из своего потока; здесь —
  поток в харнессе (`alpha_vc.py`: раз в секунду простоя команда `keepalive` → пакет 0). `wait` при потере связи
  (`GuiConnectFailed`) должен падать сразу (`fatal`), иначе ждёт до `max_frames` (6000 кадров = 5.5 мин впустую).
- **Атлас `blocks` общий для всех паков**: имена текстур пака совпали с `base` (`leaves`, `grass`, `dirt`...), а
  `ContentGfxCache` берёт `<имя>_opaque`, если такой есть в атласе (у base есть `leaves_opaque`) — листва альфы стала
  тёмной и сплошной. Текстурам пака — свой префикс (`am_`).
- **Атлас движка с mipmap (`GL_LINEAR_MIPMAP_NEAREST`)**, у альфы `GL_NEAREST` без mipmap: вдали текстуры размыты.
  `texelFetch` уровня 0 в `main.glslf` пака (`floor(uv·size)`) — terrain_flat с 30–58 % до 99.2–99.5 %.
- **Камера альфы отодвинута на 0.1 назад** (`orientCamera`: `glTranslatef(0,0,-0.1)` до поворотов) — без этого ближние
  блоки съезжали на 5 пикселей. Нижняя грань: у VoxelCore «верх» картинки на −Y-грани смотрит в +Z, у альфы в −Z
  (остальные 5 граней совпадают) — нижней грани нужна отражённая текстура.
- Своя камера пака (`resources.json` → `alphamine:view`, `player.set_camera`) не встроенная: движок не трогает её FOV,
  не применяет к ней мышь, покачивание и инерцию — поворот и позицию ведёт пак. Встроенной камере FOV из настроек
  ставится каждый кадр (проба 7).
- `am_scenario` для `impl=vc` не запускать, пока Java-агент работает: сессия сценария перезапускает сервер порта из
  `setup` (25565 — чужой). Свой прогон — `tools/alphamine/run_vc_scenario.py` (сервер :25566, `server_v.py`).
- Мир сценария — `golden\world_b` (не `world_a`: на `world_a` сервер во время прогона достраивает соседние чанки).

## AlphaMine — HUD/GUI в XML, рука, частицы (фаза 3, агент U, 30.09)
Что XML-документы движка 0.31 могут пиксель в пиксель, а что нет (проверено запуском, `runs\*_vc_u_*`):
- **Может**: текстурированные прямоугольники `<image region>` с NEAREST (увеличение ×2 — точное), сплошные заливки
  `<container color>` с альфой, тонирование `color` (умножение, в т.ч. альфы), порядок = порядок детей. HUD/GUI альфы на
  854×480 — 100 % пикселей. Масштаба GUI у движка нет (1 единица = 1 пиксель) — `ScaledResolution` считать самому.
- **`region` картинки — снизу вверх**: `Image::draw` передаёт `flippedY`, текстуры лежат перевёрнутыми → строки PNG t0..t1
  сверху = `region="u0, 1−t1, u1, 1−t0"` (документация говорит «0,0 — левый верхний», это неверно для подобластей; целая
  картинка 0,0,1,1 выглядит правильно). С прямым region шрифт был кашей, хотбар — белым.
- **Нет режимов смешивания**: инверсию прицела не выразить; умножение (виньетка `GL_ZERO, ONE_MINUS_SRC_COLOR`) выражается
  чёрной картинкой с альфой = яркость. Прицел — движковый (`Hud::draw`, `inversion` = `ONE_MINUS_DST_COLOR,
  ONE_MINUS_SRC_ALPHA`), текстура `gui/crosshair` подменяется паком (ResPaths ищет с последнего корня): при бинарной альфе и
  RGB 0 под прозрачным совпадает с Java. Он скрыт, когда открыт инвентарь/оверлей.
- **Градиент** (`drawGradientRect`) — столбец 1×H с альфой по строкам; GPU Java округляет интерполированную альфу как
  a(y−0.5) (переход 12→13 над чёрным на строке 226 из 480, а не 217 «по центру пикселя»).
- **Шрифт**: движковые шрифты моноширинные — каждый глиф `default.png` отдельным `<image>` (23 глифа строки версии × 2 с
  тенью — без просадки). Ширины — как FontRenderer: `getRGB() & 255` = **синий** канал, альфа не смотрится. LuaJIT
  понимает `"\u{2302}"`.
- `container:add` берёт один корень — группы детей оборачивать в `<container>`; пересобирать группу только при смене
  ключа состояния (слот, здоровье, предметы, строки чата), иначе каждый кадр — сотни элементов.
- Хотбар движка (`Hud::hotbarView`, id `hud.hotbar` в `gui.root`) `Hud::update` каждый кадр делает видимым и двигает —
  `gui.root["hud.hotbar"]:moveInto(<скрытый контейнер документа>)` убирает его навсегда.
- Слои F2F: `hud.open_permanent` = слой `hud`, `hud.show_overlay` = слой `gui` (INVENTORY-режим). Оверлей делает
  `is_inventory_open()`: курсор отпущен, ввод игрока заблокирован (как `currentScreen != null`).
- Esc в мире обрабатывает `stdlib.lua` (`input.add_callback("key:escape")` → `hud.pause()`); колбэк пака, добавленный позже,
  вызывается раньше и `return true` останавливает цепочку.
- **Рука**: `WorldRenderer` рисует скелет `hand` только если текущая камера — `core:first-person`, копией камеры в начале
  координат с FOV **0.9 рад** и far 10; кость — в мировой ориентации (матрица = поворот камеры · поза). Меш `shading off`
  получает свет 1 и `emission 1`: пиксель = тексел × tint скелета — свет альфы запекается в canvas-текстуры
  (`Canvas({16,16})`, `create_texture`, `set_data`, `update`; строки canvas снизу вверх). `hud.hand_controller` вызывается
  **после** кадра (on_hud_render) — поза отставала бы на кадр при повороте; Lua между `CameraControl::update` и
  `renderFrame` — только `stdcomp.render` (компоненты сущностей), его и оборачивать, и **после** оригинала (компонент
  P крутит взгляд там же; первая версия копировала камеру до него — вся картинка отставала на кадр, terrain_flat 8–37 %).
- `Tessellator.setNormal` альфы: `(int)(x*128)` → +1 становится байтом −128 (грань +X освещается как −X), байты
  знакорасширяются перед `|` (y, z = −1 у нормали −X). Полоски предмета это подтверждают; одна грань руки на yaw 90/270 и
  грань ±X 3D-иконки всё равно светлее GPU на 0.5–1 % — причина не найдена.
- `gfx.particles.emit(pos, 1, preset)` со `spawn_interval 0` рождает частицу в ближайшем `update` с delta>0 и сразу рисует
  без сдвига; сдвиг/гравитация — движка (без сопротивления), под-UV (`random_sub_uv`) — ГСЧ с сидом = адрес эмиттера:
  частицы между прогонами не повторяемы, сравнивать покрытие и средний цвет.
- F2F движка: `input.keys {"3": true}` — клавиша «3» (имя), у Java `"3"` — код LWJGL (KEY_2): сценарии со слотами на двух
  сторонах выбирают разные слоты.

## AlphaMine — инвентарь, взмах, покачивание, окно 1390×855 (фаза 3, агент U, 01.10)
- **Клавиша инвентаря Alpha 1.0.16 — I** (`keyBindInventory` = 23), не E: у Java-эталона на E ничего не открывается. E у
  пользователя из options.txt — в паке обе. Перед сценарием с клавишами — смотреть `GameSettings` эталона, а не память.
- **`package.loaded` пака — под ключом `"alphamine:modules/<имя>.lua"`**, не `"alphamine:<имя>"`: проверка
  `package.loaded["alphamine:game"]` всегда nil (так partial камеры в обычном запуске был 0). Ленивый `pcall(require, ...)`.
- **`UINode::calcPos` обрезает позицию элемента до int** (`glm::ivec2`), размер остаётся float. Дробные `pos` в XML не
  работают; для дробного масштаба GUI элемент ставится на пиксели, которые покрыл бы GL (центры в [a, b)), а region
  текстуры сдвигается так, чтобы каждый центр пикселя брал тексель Java (`ui.quad`). Итог при 1390×855: HUD 99.61 → 100 %.
- **Java-GUI при размерах, не кратных масштабу, растянут**: `glOrtho(0, w/sf, h/sf, 0)` на весь кадр → 1390/463 = 3.00216
  пикселя на единицу. Всё, что предрисовано под целый масштаб (3D-иконки, прицел, градиент фона на 480 строк), при 1390×855
  расходится — растеризовать по месту (Lua-растеризатор `inv_preview.lua`) или canvas под текущий размер.
- **Прицел движка рисуется размером своей текстуры** по центру с целочисленным делением: иконка масштаба 3 требует другой
  текстуры. `assets.to_canvas("gui/crosshair")` даёт canvas на отдельную текстуру (не только регион атласа) — `set_data` +
  `update` перезаливают её без правок движка.
- **Байтовые нормали Tessellator**: декодирование по правилу GL 1.x/2.x (2b+1)/255 (−127 → −0.99216, 0 → 1/255), без
  перенормировки (GL_RESCALE_NORMAL). Превью в инвентаре это доказало (все грани −Z на уровень темнее, чем при b/127);
  один кадр руки (pitch −60) предпочитает «0 → 0» — правило окончательно не сошлось, варианты в `AM_NORMAL_RULE`.
  Искать такие вещи — отладочным дампом растеризатора (грань, тексель на пиксель) и интервалом допустимого множителя по
  пикселям golden (`[(g−0.5)/t, (g+0.5)/t]`), а не перебором гипотез по процентам.
- **`GuiInventory` смотрит на мышь предыдущего кадра** (`xSize_lo/ySize_lo` пишутся после `super.drawScreen`), в первом кадре
  после открытия — на (0, 0). Без этого превью поворачивалось бы на кадр раньше.
- **Камера на ходьбе**: `orientCamera` берёт prevPos + (pos − prevPos)·partial; при F2F partial 0 кадр показывает положение
  начала последнего такта. Камера пака без интерполяции была бы на тик впереди — весь кадр съезжает (видно только при движении).
- **Рамка выделения движка** считается его лучом по его камере (после поворота мыши — другой блок) и рисуется линиями без
  альфа-смешивания: подменой `shaders/lines.glsl*` геометрию Alpha получить можно, цвет и блок — нет.
- `run_u.py` слал `input.keys {"3": …}` как есть — у движка это клавиша «3», у Java код KEY_2: «не тот слот» выглядел как
  ошибка рендера руки (92 % на `u_hand_items`). Любой харнесс с `input.keys` обязан переводить цифровые коды.
- Общие модули правят несколько агентов одновременно: править точечной заменой строки с проверкой `count == 1` и перечитывать
  файл перед правкой (у меня `gui.lua` поменяли между чтением и записью — первая замена не нашла текст и ничего не записала).

## AlphaMine — слои мира: тексели, свет, туман, небо, вода (фаза 3, 30.09–01.10)
- **Lua может писать в атлас блоков**: `assets.to_canvas("blocks:<текстура>")` даёт холст на регион атласа, `canvas:set_data
  (Bytearray)` — memcpy, `canvas:update()` — `glTexSubImage2D` региона + `glGenerateMipmap` всего атласа. Так в шейдер
  передаются данные мира (свет сервера, коды жидкостей, анимированные текстуры) без правок движка. Позицию региона шейдер
  не знает — её задаёт упаковщик: `LMPacker` сортирует по высоте и кладёт самую высокую текстуру в (0,0) + экструзия 2.
  Проверять маркером в регионе.
- **LMPacker: `height*height*1000` в int** — текстура выше ~1465 px переполняет оценку и перестаёт быть «первой»
  (регион 1344×2690 уехал, шейдер молча перешёл на запасной свет). Делать регионы широкими, а не высокими.
- Свет движка ≠ свет альфы не только у воды: под листвой и в тени тоже (27–53 % → 81–96 % с таблицей альфы поверх
  света движка, → 99.9 % со светом сервера).
- `fract(мировой координаты)` на шве блока «переворачивается» (координаты ~100 во float): тайл/клетку выбирать по мировой
  позиции, а локальную координату брать из координаты атласа и проверять диапазон [0,16].
- Проверка «плоская ли грань» по производным мировой позиции с малым порогом ломается у граней рядом с камерой (шум
  float ~1e-5 при изменении ~0.01 на пиксель) — у движка нормаль граней кубов и так точная; распознавать надо только
  спрайты (нормаль +Y у вертикальной плоскости).
- Модель неба/тумана проверять численной копией шейдера (numpy) против golden до запуска движка: разница вариантов
  (интерполяция на вершинах, диагональ квадов, квантизация) видна за секунды.
- `/tmp` WSL очищается при перезапуске сессии — вспомогательные скрипты анализа держать в `tools/alphamine/` или scratchpad.
- Прозрачный проход движка — списки треугольников по 6 вершин на грань (`BlocksRenderer::renderTranslucent`), поэтому
  `gl_VertexID % 6` = угол грани; в непрозрачном меше так нельзя (кастомные модели пишут вершины по 3).
- `Math.random()` в F2F-клиенте один на всех (`F2FRandom.MATH`): анимация воды совпала такт-в-такт только когда в Lua
  расходуется тот же поток в том же порядке (лава, вода, течение, течение лавы, огонь ×2 за такт). Другие пользователи
  `Math.random` (частицы, конструкторы сущностей) должны брать числа из `texfx.random()`.

## Процесс
- MCP-сервер запускал новый `powershell.exe` на каждый вызов (~0.9 с; скриншот 2.1 с) — это и было
  «зависание» инструментов `eag_*`. Один постоянный процесс PowerShell: PID 3 мс, скриншот 50 мс.
  Все вызовы журналируются автоматически (`artifacts/journal/`), путь по игре — сценарием
  (`scenario_run("eag_world")`), а не вручную.
- Слепые ожидания экранов с длинными таймаутами — плохо: пользователь видел, что агент «застревает».
  Инструменты должны возвращать состояние сразу и говорить, где застряли.
- Прежде чем «чинить» — снять профиль (`eag_profile`) или стек (`eag_crash`): так нашлись GC,
  `(int)NaN`, таймер.
- Ждать вслепую — самый частый затык прошлой сессии: `Monitor` истёк без событий четыре раза (2.5–30 мин),
  фоновые `grep`-ожидания заканчивались «No matches found», хотя событие давно случилось (не тот шаблон,
  лог Windows в cp866). Ждать условием (`eag_wait`, `vc_wait_log`, `scenario_run`), шаблон проверять на
  уже существующем логе. Фоновый `Bash` живёт ≤ 10 мин — длинное на Windows через `Start-Process` с логом.
- Агенты и движок (29.09): закончивший агент pc_wasmrt продолжал слать уведомления и остановил движок,
  которым пользовался агент-фикс; я отвечал письмами вместо `TaskStop`, пользователь кричал «стоп».
  Правило в AGENTS.md («Субагенты и движок»): один владелец движка, очередь, «стоп» = TaskStop всем + `vc_stop`.
- Перезапуск сессии: агентов прошлой сессии не возобновить («No transcript found»), фоновые команды теряются.
  Убитый агент оставляет незакоммиченные правки и, возможно, разложенный модуль от непроверенного
  бинарника (фикс дождя: `spider-cli` и `eaglercraft.lua` пересобраны 29.09 14:31, проверки не было).
  В начале сессии — `git status` в Spider и md5 модулей (ONBOARDING «Начало сессии»).

  замеров памяти это 12 ГБ, а vhdx WSL на `D:` не сжимается сам — пользователь заметил пропажу десятков
  гигабайт. Сборка — только в общем `target`; временное — в `$CLAUDE_JOB_DIR/tmp`.
- Ложные регрессии, на которые ушло время: «сломанная модель» на экране профиля (скин «Baby Charles»),
  «нет тумана» (лёд ближе начала тумана; доказал зонд `tris_verify: 3`), «Doom 69 fps вместо 120» (реальное

## AlphaMine — взаимодействие с миром (фаза 4, агент P, 01.10)
- **`package.loaded` в VoxelCore хранит модуль под ключом пути**: `require "alphamine:net"` кладёт результат в
  `package.loaded["alphamine:modules/net.lua"]` (`res/scripts/stdmin.lua __load_script`), а не `["alphamine:net"]`. Ленивые ссылки
  на модули (чтобы не ловить циклы require) — только по полному ключу. Первый прогон фазы 4 «работал» локально (блок ломался и
  через 80 тактов возвращался откатом), но ни одного пакета на сервер не ушло: `package.loaded["alphamine:net"]` = nil.
  (У `fpview.lua` агента U та же ошибка: `package.loaded["alphamine:game"]` -> `partial()` всегда 0.)
- **Движок F2F не пересылает `render` паку** (`f2f.cpp`: `render` отвечает сам, `mode` — с `lua`): что пак рисует сам, о слоях
  не знает. Харнесс (`run_vc_scenario.py`) после каждого `render` шлёт паку `layers {…}` — полное состояние из ответа движка.
- **Java-эталон слоёв**: `EntityPickupFX` — частица (слой `particles`), а подобранный предмет в такте Collect ещё в
  `loadedEntityList` (isDead) и рисуется слоем `entities` на месте. Со слоями без частиц golden показывает предмет на земле в
  кадре Collect и пустоту дальше — «полёта» нет вовсе.
- **`despawn()` сущности движка применяется в его обновлении мира** (в F2F при шаге 50 мс — через кадр): скелет успевает
  нарисоваться ещё раз. Сначала `skeleton:set_visible(false)`, потом `despawn()`.
- **Случайность сервера**: выпавший из блока предмет летит по `World.rand` сервера (не сидируется) — позиция и то, подберёт ли его
  стоящий рядом игрок, меняются от прогона к прогону. Сценарий ломает блок через один от игрока (вне `expand(1, 0, 1)`), а позицию
  предмета не сравнивает.
- **`Math.random` в F2F один на всех**: `EntityItem` при спавне берёт 4 числа (`hoverStart`, `rotationYaw`, `motionX/Z`),
  `EntityPickupFX` — 5, дверь — 1. Всё — из `texfx.random()`, иначе поворот предмета и анимация воды расходятся.
- **Протокол копания 1.0.16 ≠ поздний**: status 2 — это «отпустил» (`resetBlockRemoving`, координаты 0), «сломал» — 3; сервер
  не ломает по status 3, а считает урон сам по пакетам 0/1 и проверяет их лучом 4.0 со стороной. Стадия 9 трещин травы рукой при
  partial 0 не видна никогда.
- Рецепты крафта надёжнее снять **запуском** классов эталона (JDK 8, `minecraft\bin` + `deobfuscated.jar`, отражение на
  `CraftingManager.recipes`), чем переписывать `Recipes*.java`: `gen_interact.py` — 93 рецепта в порядке `RecipeSorter`.
- Правки общего `game.lua` делать точечными вставками (Edit со свежим чтением): в ту же минуту его меняли три агента
  (perf/autowalk, fpview, inventory_gui); обработчики пакетов фаза 4 не переписывает, а оборачивает (`interact.install`).

## AlphaMine — E2E-серия (агент E, 01.10)
- **Java против Java — сначала.** Первый же повтор эталона разошёлся на ±1 по всему кадру (дуги на diff): `mode` не сбрасывал
  `GuiIngame.prevVignetteBrightness` (сглаживание 1 %/кадр), а число кадров сетевых `wait` до `mode` у прогонов разное. Любое
  состояние «за кадр» должно сбрасываться `mode` на обеих сторонах — искать поля, которые обновляются в рендере, а не в такте.
- **Сервер альфы в E2E недетерминирован по событиям**: позиция/id выпавшего предмета (`World.rand` сервера, расходуется
  случайными тактами блоков — сид не поможет) и такт подбора (±1 такт сервера). Подбор тянет общий поток `Math.random`
  (`EntityPickupFX` — 5 чисел) → анимация воды отличается до конца прогона. Отсюда колонка «J/J» (шум эталона) в отчёте и
  golden = типичный исход из 3 прогонов. Настоящее лечение — сервер в lockstep с харнессом.
- **Таймлайн — с темпом стены 50 мс, но без догоняния.** Без темпа сервер видит игрока в 10–20 раз быстрее и отвечает на
  разных тактах; с догонянием (после паузы 3 с на Java — GC/снимок) пачка тактов сжимается для сервера. Сдвигать расписание.
- Счётчик `world_packets` — от connect, не от `mode`: подготовка приходит с разным числом MapChunk (779–807), сравнивать приращения.
- id сущностей — счётчик сервера, между запусками сервера разный: сравнивать тип и позицию, id — в деталях.
- У VoxelCore `yaw/pitch` в JSON — ~15 знаков от float: сравнивать как float32; позицию — по строкам `exact` (%.17g).
- F2F-клавиша T на VoxelCore открывает движковый чат/консоль (привязка `hud.chat` не выключена паком), Enter там роняет
  движок (`utf8 decode error`) — E2E нашёл это на такте 298. Причина — не чат, а оставленный `app.delete_world` диалог
  (раздел «AlphaMine — чат и падение движка на Enter»).

## AlphaMine — чат и падение движка на Enter (агент C, 01.10)
- **`app.delete_world` вне headless — не удаление, а диалог** (`EngineController::deleteWorld` → `guiutil::confirm`):
  страница меню `<confirm>` + **глобальный** `input.addKeyCallback(ENTER/ESCAPE)`, живой, пока жива страница. `launch.lua`
  звал его перед `app.new_world` из сценария: мир открывался поверх, диалог оставался невидимым весь мир, и **первый Enter
  где угодно** (чат, F2F `input {keys:{RETURN}}`) подтверждал удаление открытого мира. Доказано F2F без чата: голый Enter в
  мире → `deleting user:worlds/AlphaMine` → падение (2/2, `userdir_c`). Удалить мир паку нечем: `user:` пишется только с
  разрешением проекта `write-to-user`, `world:` есть только при открытом мире, а тогда файлы регионов уже открыты
  (`file.remove_tree("world:regions")` сразу после `new_world` → «файл занят другим процессом»). Решение — не удалять:
  `new_world` поверх папки, чанк с диска пак всё равно перезаписывает (`on_chunk_present loaded`). При запуске мир и раньше
  никогда не удалялся (в логе `could not read entity: UID #1 is already used` — сохранённый игрок движка).
- **«utf8 decode error» = текст ошибки Windows в cp1251, попавший в JSON.** `fs::remove_all` на открытых файлах бросает
  `filesystem_error` с системным сообщением в ANSI-кодировке (cp1251, русская Windows); в F2F-сборке исключение команды
  `step` (ввод применяется в её `pollEvents`) ловится обработчиком F2F и кладётся в ответ `{"error": what()}`;
  `json::stringify` → `util::escape` → `decode_utf8` на байте cp1251 бросает `utf8 decode error` уже из `catch` — оно
  вылетает до `main` («uncaught exception»). Это ошибка F2F-патча (не экранирует не-UTF-8 `what()`); в обычном запуске
  исключение шло бы из `pollEvents` в главный цикл без F2F-обработчика (не проверялось: ввод ОС запрещён). Lua-сообщения таких ошибок перед логом — только ASCII.
- **Ввод текста паком (в 0.31 нет Lua API кодовых точек)**: невидимый `<textbox>` документа с фокусом (`focused = true`)
  получает символы кадра в `GUI::act` (раскладка, повтор клавиш, F2F `input.chars` → `codepoints`) и Backspace/Enter
  (`consumer`); `GUI::act` идёт до `screen->update` (такты) в том же кадре. Текст поля держать равным стражу (`##########`):
  дописанное = набранное, стёртое = Backspace. `visible="false"` фокусу и вводу не мешает. Esc снимает фокус в `actFocused`
  (и прекращает разбор кадра) — закрывать экран колбэком `key:escape`.
- **Оверлей прячет прицел движка** (`Hud::draw`: `!inventoryOpen`). Экран, под которым у Java прицел виден (GuiChat), — документ
  `hud.open_permanent`, а не `show_overlay`; тогда движок не считает инвентарь открытым: курсор остаётся захвачен, F2F относит
  документ к слою `hud`, а при потере фокуса окна движок каждый кадр открывал бы страницу «pause» — в этот момент документ
  переводится в оверлей. Цифры движок обрабатывает и под оверлеем (`Hud::updateHotbarControl` → слот) — пак возвращает слот.
- Возраст строк чата — в начале такта (`GuiIngame.updateTick` первым в `runTick`), пакет чата — в конце: строка из пакета
  такта N рисуется с возрастом 0. Пак старил строки в конце такта — затухание шло на такт раньше Java.

## AlphaMine — мир разработчика и модели блоков (агент D, 01.10)
- **Сервер альфы не пересчитывает свет при загрузке чанка**: `ChunkLoader` строит карту высот и небо только если SkyLight нет, а
  отсутствующий BlockLight так и остаётся нулём. Свой мир — со своим светом: неподвижная точка `MetadataChunkBlock.updateLight`
  (`max(источник, max соседей − max(1, непрозрачность))`, небо 15 от HeightMap) совпала с пересветом сервера в 555 тыс. клеток из 555 тыс.
- **Мир для тестов должен быть неподвижен под случайными тактами** (80 клеток на чанк за такт в ±9 чанках от игрока): трава ест землю
  рядом, трава под непрозрачным блоком ночью становится землёй, посевы/саженцы растут при свете ≥ 9, грибы осыпаются при > 13, пашня
  без воды высыхает и без посевов становится землёй, листва без бревна в 4 клетках гниёт, 74 гаснет, 75 без питания загорается, кнопки
  отжимаются, кактус/тростник ниже 3 растут, лава поджигает горючее в 3 клетках, `SnowCovered` сыплет снег. Время сервера можно задать
  в `level.dat` (`Time` 13100 = ночь ≈ 8 мин), клиент SMP его не видит. Жидкости — источниками, растечь сервером и сохранить `/stop`.

## AlphaMine — тестовая сборка движка: perf, сброс таймеров, безопасный JSON (01.10)
- **«Облака ±1 между процессами» = `u_timer`.** Таймер `WorldRenderer` копится с открытия мира, а число кадров до снимка в
  пробах зависит от реального времени (`settle` ждёт стабильный кадр 97–115 кадров, загрузка чанков ограничена бюджетом
  `loadSpeed` мс по настенным часам — `ChunksController::update`). F2F `mode` теперь сбрасывает `u_timer`, прокрутку осадков и
  анимации текстур (эпоха, сброс в следующем кадре у владельца): кадр после `mode` одинаков в трёх процессах, без сброса — 0.13–0.46 %
  (облака). Перед снимками паритета всегда звать `mode`.
- **Санитайзер — на весь ответ, а не на `what()`.** Невалидный UTF-8 приходит не только из исключений ОС: результаты Lua-обработчика,
  ключи объектов, строки драйвера. `util::escape` ещё и пишет управляющие байты как `\1` (невалидный JSON), а ключи — `\uXXXXX` для
  символов вне BMP. Обход всего `dv::value` + `stringify` в `try` с ASCII-ответом на крайний случай. Участок cp1251, случайно
  образующий валидный UTF-8 («Вё» = `C2 B8`), не отличить — эвристика.
- **Шестнадцатеричные escape в C++ жадные**: `"a\x01b"` — это `\x01b` = 0x1B; разбивать литерал: `"a\x01" "b"`.
- **MSYS git на worktree из WSL**: в файле `.git` путь `/mnt/d/...` — Windows-git его не видит; переписать в `d:/...` и звать с
  `--git-dir`. И `-c core.autocrlf=input` (как у WSL-git в `/root/.gitconfig`), иначе CRLF-чекаут `main` даёт «823 изменённых файла».
- **Замер накладных расходов `perf` в одном процессе, чередованием.** Разброс «off» между прогонами 10–30 % (ПК занят пользователем),
  между процессами ещё больше (372 и 409 мс против 444 и 307 мс на 200 кадров в чередующихся запусках) — сравнивать exe между
  процессами бессмысленно. Внутри процесса off/on/trace ×7 вперемешку: медианы в пределах ±4 %, в тихом прогоне ±0.3 %.
- **`app.tick()` в `start.lua` проекта даёт Lua-работу каждый кадр** (корутина приложения возобновляется в `applicationTick`) — так
  тестовый проект `engine/tests/f2fperf` пишет свои события в трассу без пака. Обработчик проекта получает и `mode` — его надо
  обработать, иначе `mode` вернёт ошибку `unknown-command`.
- В первом прогоне в свежем `--dir` мир генерируется, и цикл «число чанков не меняется» срабатывает рано (1155 из 1513) — горизонт
  догружается во время снимков. Сравнивать с записями только после второго прогона (мир на диске).

## AlphaMine — изоляция ввода тестового движка, часы realtime (01.10)
- **Стоковый `VoxelCore.exe` для замеров агентом запускать нельзя**: его окно берёт мышь пользователя, захватывает курсор
  (`glfwSetInputMode(GLFW_CURSOR_DISABLED)` при входе в мир) и открывает паузу при потере фокуса (`Hud::processInput`:
  `!window.isFocused()` → `setPause(true)`). Замер «как у пользователя» — `VoxelCoreF2F.exe --f2f <порт> --f2f-clock realtime`
  (тот же цикл и пейсинг кадров, что `Mainloop::run`, ввод только по протоколу), при необходимости `--f2f-window hidden`.
- **Изоляция — в отсутствии колбэков, а не в проверках внутри них**: под `--f2f` `setup_callbacks` ставит только refresh и close
  (close отменяет закрытие), `glfwPollEvents` просто выбрасывает реальные события. Прочие пути реального ввода/ОС, найденные grep'ом
  `glfw` вне `GLFWWindow.cpp` и `Window::`-методов: `app.focus()` → `glfwFocusWindow`, `TextBox` → системный буфер обмена,
  `GUI` → `glfwSetCursor` (форма курсора), `setMode` → `glfwGetCursorPos`. Все отключены под `--f2f`.
- **GLFW 3.4 при первом показе окна берёт `STARTUPINFO.wShowWindow`** родителя (`_glfwShowWindowWin32`), и `SW_SHOWNORMAL`
  активирует окно, даже если `GLFW_FOCUS_ON_SHOW=false`. Поэтому окно создаётся с `GLFW_VISIBLE=false`, получает `WS_EX_NOACTIVATE`
  и показывается `ShowWindow(SW_SHOWNOACTIVATE)` напрямую (в `f2f_text.cpp` — единственном модуле F2F с `windows.h`).
- Проверка фокуса без ввода ОС: поток в пробе раз в 50 мс читает `GetForegroundWindow` → PID (только чтение) всё время жизни
  процесса движка, плюс `GetWindowLongPtr(GWL_EXSTYLE)` окна. Реальный ввод в тесте не воспроизводится (ввод ОС запрещён) —
  изоляция доказывается кодом (колбэки не установлены) + синтетическим `input{mouse:{dx}}`, который поворачивает игрока.
- Realtime на ноутбуке с vsync 144 Гц: `frame_ms_mean` 6.90–6.96 мс в меню и в мире (`f2fworld`, после загрузки), пока мир
  генерируется в первые секунды — 33 fps. `hidden` в меню: тоже 289 кадров за 2 с, 6.931 мс (vsync у невидимого окна драйвер
  NVIDIA соблюдает, ожидание в `present` 6.87 мс в обоих случаях) — на другом GPU проверить так же, прежде чем сравнивать.
- Python-пробы на Windows печатают JSON с заголовками чужих окон: без `python.exe -X utf8` вывод в cp1251 падает на `◐`.

## AlphaMine — пошаговый сервер (lockstep, 01.10)
- **Барьер — по накопленным байтам, а не «по пакетам такта».** Клиент сообщает `tx_total` (байты соединения, отданные в сокет/очередь
  с начала), сервер ждёт, пока его поток-читатель прочитает столько же, и наоборот. Пакеты вне тактов (чат харнесса, Handshake из потока
  подключения) так учитываются сами; `≥` вместо `==` переживает лишний KeepAlive. Java считает tx при постановке в очередь сериализацией
  пакета (поток-писатель пишет позже), rx — после того, как пакет целиком прочитан и поставлен в `readPackets`.
- **Сервер пишет синхронно, но не сам**: в конце такта очереди сериализуются (данные, потом чанки) в один `byte[]` и отдаются потоку-
  писателю. Синхронная запись из потока сервера повисла бы, если клиент не читает (буфер сокета), а харнесс ждёт ответа сервера.
- **`HashSet` с плохим `hashCode` недетерминирован между запусками JVM.** `ChunkCoordIntPair.hashCode = x<<8 | z`: отрицательные z
  схлопываются, Java 8 делает из корзины дерево и разбирает ничьи по `System.identityHashCode` → порядок обхода (и расход LCG случайных
  тактов) другой в каждом процессе. Ловится только сравнением потоков по тактам (CRC в ответе `step`): в 2 из 3 прогонов всё совпадало.
  Перечень «HashMap без identity-хэша» из исследования этого не учитывал — смотреть и на коллизии.
- **Пак обрабатывал все пакеты за такт, Java — ≤ 101 за вызов** (`NetworkManager.processReadPackets`, вызовы в `updateScreen` экранов
  входа и в `WorldClient.tick`). В реальном времени разница тонула в дрожании сети; в lockstep она видна сразу (448/490 пакетов за такт).
- **Движок VoxelCore съедает дельты мыши в каждом проходе `step`**, а пак применяет взгляд только в отрисованном кадре: `step{1, frames:0}`
  теряет `input.mouse.dx`. Разбивая `step{20,1}` на такты, дельты надо держать до шага с кадром (так у Java: дельты копятся до кадра).
- Python-правки Java-исходников через `open().read()/write()` молча меняют CRLF на LF — патч раздувается до целых файлов (11 590 строк
  вместо 1 863). Писать в бинарном режиме или восстанавливать CRLF перед `diff`.
- Сравнение «X против Y» без lockstep упирается в шум сервера; теперь первым делом — J/J и VC/VC на `e2e_walk1_ls` (100 %), и только
  потом VC/Java. VC/VC пока 59/73 (частицы копания) — это недетерминизм порта, не эталона.

## Лаборатория: lockstep, эталонный клиент, детерминизм частиц (этап 3б, 01.10)
- **Одного хука «шаг сервера после такта клиента» мало.** Такт lockstep — это барьер rx *до* шага клиента (Java — `rx_bytes` в `step`,
  VoxelCore — `sync {rx_bytes}`), шаг, `sync {}` (tx движка), шаг сервера; плюс отложенная мышь VoxelCore и `connect`/`wait`/`mode`
  через те же такты. В ядро добавлены хуки `lockstep_tick` (весь такт) и `lockstep_run` (забрать команду), а в плагин — тот же класс
  `f2f_server.Lockstep`, что у старых раннеров, с транспортом через аренды: последовательность команд побайтно прежняя (ожидания
  подготовки `[3, 262, 2, 201, 0, 2, 271, 0]`, 1341 такт, tx 17 866/17 874, rx 3 221 307 — как в `runs\…_ls2_*`).
- **Пошаговый сервер не выполняет `stop` из stdin**: консольные команды идут в конце такта, а такты — только по `step`. Мягкий стоп
  аренды в lockstep — F2F `quit` (шаг stop с `if_param = "f2f_args"`), иначе 15 с ожидания и TerminateJobObject.
- **Простойный keepalive демона** (`f2f_idle` вида engine) в lockstep надо выключать (параметр аренды `f2f_idle=false`): пакет в
  случайный такт сервера. Пак после `sync {keepalive:false}` его и так не шлёт, но команда всё равно приходит в случайный момент.
- **Генератор эмиттера частиц движка сидируется адресом в куче** (`Emitter.cpp`: `random.setSeed(reinterpret_cast<ptrdiff_t>(this))`,
  16-битное состояние `util::PseudoRandom`). Всё, что эмиттер берёт из него, разное в каждом запуске: окно `random_sub_uv`
  (`autoSub`), `particle.random` (множитель света 0.9…0.999 и `size_spread`). Доказано пробами `det_dig*` (два прогона vc каждой):
  без слоя particles 70/70, `random_sub_uv = 1` — 70/70, `lighting = false` — 14/70. Окно пак теперь выбирает сам (джиттер EntityFX
  из своего сидированного `Entity.rand`, вырезка 4×4 в Canvas-текстуру), `random_sub_uv = 1`. Множитель света на дневном свету
  пикселей не меняет (свет неба в альфа-канале вершины), при блочном свете (факел, лава) может — см. STATUS.
- **Ждать чужие замеры, а не мешать им**: рестарт демона (новый код ядра) возможен только при пустом `lab ps`/`lab jobs`; серия перф-
  прогонов другого агента шла ~1 ч (18:00–18:54), а любой наш прогон делал бы его замеры `contended`. Правки, не требующие движка
  (Java, патчи, тесты ядра на фейках), делать в это время.
- **Ворота сравнивают с «лучшим после обновления golden» — значит, должны знать, когда golden обновился.** Серии прогонов лаборатории
  писали в историю `golden_id` = id ключа, а не путь, и после regen прогоны старых golden (другой сервер, старый пак) оставались
  основанием: 27 «регрессий» по 0.001–0.15 п.п. Теперь `extra.golden_dir` + mtime `golden.json`; основание — только тот же `server_mode`.
- После снятия частиц у `e2e_walk1` vc/vc остался **один пиксель** на kf_0080 (просвет неба в листве) в одной паре из трёх — не частицы;
  не списывать такое на «шум», а держать в списке (STATUS), пока не найдено.

## Olife — протокол, мир, клиент на 0.32 (волна 2, агент olife_w2, 02.10)
- **Колбэки — только из главного состояния Lua, это касается и `console.add_command`.** Команды `--stdin-cmd`,
  зарегистрированные в стартовом сценарии (`--script`, корутина), работали десятки раз (`status`), а `kick` (с
  `player.delete`) и `olife.check_blocks` (file + json) роняли процесс: «cannot resume dead coroutine» → 0xC0000409.
  Колбэк привязан к `lua_State` корутины (`lua::create_lambda`, как `f2f.set_handler` в AlphaMine). Теперь сокеты
  (`tcp_open`/`tcp_connect`), их колбэки, команды и обработчик F2F создаются в `scripts/world.lua` (первый такт мира /
  `on_world_open`); сценарий только «просит» (`request_begin`/`request_connect`), а изменения состояния из команд
  (кик) ставятся в очередь и применяются в фазе такта.
- **`FLTview`/`DBLview` поверх Bytearray нельзя использовать для перевода float ↔ байты.** Запись байтов `scratch[i] = b`
  и чтение `F32[1]` из той же памяти в скомпилированной трассе LuaJIT давали старое значение (типовой анализ алиасов
  FFI): после ~100 декодирований `rot.z` приходил из прошлого вызова. Перевод теперь арифметический (`math.frexp`/
  `ldexp`, half-even как `struct.pack`), проверен краевыми значениями и 20 000 случайных в движке.
- **В окне 0.32 нельзя `app.reconfig_packs({"base", ...})`**: меню уже загрузило `base` → «pack duplication» → abort.
  Добавлять только то, чего нет в `app.get_content()` (оба стартовых сценария).
- **Логический такт клиента — по часам, а не по кадрам.** Оконный F2F-клиент вызывает цикл сценария на каждый кадр
  (≈ 40/с): `PlayerInput` на кадр превысил лимит шлюза 60/с, и шлюз законно выкинул обоих клиентов за флуд. Приём — каждый
  кадр (задержка p50 4.4 мс против 16–34 у бота), логика и ввод — шагом 50 мс с ограничением догоняния.
- **Закрывая сокет с непрочитанным входом, сервер шлёт RST, и клиент теряет последний кадр** (`Disconnect` с причиной):
  после бана за флуд повторный вход видел только обрыв. Шлюз теперь полузакрывает (`SHUT_WR`) и дочитывает до 1 с.
- **Изменений блоков без события в движке нет**: события 0.32 — только от игрока (`on_block_placed/broken/...`), по
  скриптам конкретных блоков и `on_chunk_present/remove`. Серверные изменения (трава, песок) ловит перехеширование
  `get_chunk_data` по кругу (1–2 переотправки на ~1000 проверок за 25–30 с), сущности движка — `on_entity_spawn/despawn`
  (в `world.lua` имена именно такие; в CHANGELOG — `on_entity_spawned`).
- **`world.set_chunk_data` работает только на существующем чанке** (возвращает `false`, если локально не загружен):
  клиенту нужен свой игрок движка, который грузит локальные чанки, и ожидание до `on_chunk_present`. Чанки грузит только
  игрок — серверу нужен «якорь» на спавне (`player.create` + `set_loading_chunks`), и `chunks.load-distance` надо
  уменьшить (по умолчанию 22 → 1119 чанков на одного игрока).
- **`get_chunk_data` детерминирован**: после `set_chunk_data` клиент читает назад побайтно те же байты (180/180, 334/334)
  — годится как проверка применения чанка без собственного разбора формата.
- `lab start --restart` аренды с `stdin_poke`: после рестарта процесса мягкий стоп `olife.stop` не дошёл (похоже, тычок в
  консоль делается раз на аренду, а не на процесс) → `TerminateJobObject`. Сообщено агенту лаборатории.
- Чужой рестарт демона лаборатории убивает все аренды (прогон `olife_sandbox_bin` 04:39 — `aborted: daemon restart`);
  мёртвые аренды остаются в `lab ps` до `lab release` — освобождать их явно.

## Лаборатория — supervisor (этап 6, olife_w3v, 02.10)
- **`stdin_poked` жил на аренде, а не на процессе.** Перезапуск аренды (`lab start --restart`, перезапуск supervisor'ом)
  давал новый процесс с новой консолью, но «тычок» читателю `--stdin-cmd` больше не делался — headless-мир после первого
  рестарта молчал бы на `status`, и health-проверка убивала бы его по кругу. Теперь флаг сбрасывается при каждом старте.
  Общее правило: всё, что привязано к процессу (консоль, F2F-соединение, pid), сбрасывать на старте, не на аренде.
- **Снимок «что пришло перед смертью» должен быть на диске заранее.** Кольцо журнала в Lua исчезает вместе с процессом;
  опрос `journal 256` через stdin раз в секунду забил бы лог мира. Мир сам пишет снимок раз в 20 тактов в два файла
  попеременно (`sup_state_a/b.json`): убийство посреди записи портит максимум один, supervisor берёт целый со свежим `ms`.
  Цена — до 1 с последних кадров (в прогоне снимку было 1.0 с; уменьшается `journal_every`).
- **Порт «жив» проверять по LISTEN дерева процессов, а не подключением.** Голое TCP-подключение к миру — это «шлюз без
  GatewayHello»: мир логирует, считает отброшенные шлюзы. `psutil.Process(pid).net_connections()` по pid Job — без побочных
  эффектов.
- **Health-проверки не писать в журнал лаборатории.** `lab.stdin` журналирует каждый вызов; проверка раз в 5 с на службу —
  сотни строк в час. `Lab.stdin(..., journal=False)`.
- **Учёт по дельтам с ключом «аренда + номер старта + сессия».** Счётчики шлюза и мира обнуляются при перезапуске процесса;
  ключ без номера старта дал бы отрицательные дельты (или задвоение после повторного роста). Сущности — датчик (set),
  не накопитель.
- **Забаненный бот выходит сам** (код 5 не переподключается, цикл `client_start.lua` завершается) — шаг сценария сначала
  проверял его `status` через stdin и падал на `instance-dead`; доказательство бана — строка лога и отсутствие
  `reconnecting` после неё.
- **Плагин olife правят несколько агентов одновременно** (w3s — песочница, w3g — шлюз на Rust): они выносят код в свои
  модули (`sandbox_real.py`, `gateway_rs.py`), а тесты, копирующие плагин во временный проект, должны копировать **все**
  `*.py` каталога, иначе `plugin_error` у всех тестов olife сразу.
- **Не запускать чужой exe без копии, пока его пересобирают.** `kinds.sandbox` (настоящий `olife-sandboxd.exe`) —
  `copy_exe = false`; запуск залочил бы файл и сломал сборку другого агента. Дымовой прогон supervisor — на `sandbox_stub`.

## Olife — настоящая песочница в сессии (волна 3a, olife_w3s, 02.10)
- **wasmtime под Windows списывает топливо за инстанцирование.** В Linux память инициализируется copy-on-write
  образом (memfd), в Windows сегменты данных копируются при `instantiate`, и копия стоит топлива. У нового `Store`
  топливо 0, поэтому Windows-сборка падала на первом же владельце («all fuel consumed by WebAssembly»): 13/13 тестов
  красные, Linux зелёный. Минимальная проба (цикл на wat) под Windows работала — разница была в сегментах данных
  настоящего модуля. Лечение: `set_fuel` до `instantiate`. Это топливо не тарифицируется: счётчики берутся как разница
  внутри такта. Под Windows сборку проверять её же тестами (`cargo test --no-run --target x86_64-pc-windows-gnu`,
  затем exe тестов в Windows), а не только Linux-тестами.
- **Админ-команды приходят по одной на такт — загрузка может попасть в замороженного владельца.** `spawn_scripted neg_find 14`,
  следом `spawn_scripted orbit 14`: к приходу второй загрузки владелец 14 уже заморожен (C-бэктрекинг). Сервис отвечал
  «owner is frozen», мир помечал сущность `error`, переставал слать её вход, и она молча пропадала. Driver этого не ловил:
  он грузит все сущности до первого такта. Теперь загрузка в замороженного владельца откладывается до свободной VM
  (переживает kill и откат), тест `load_while_frozen_is_deferred_not_lost`. Мораль: негативы гонять через настоящий
  путь мира (по одной команде), не только через пакетный драйвер.
- **Объём вывода одного владельца — это время такта мира.** Поток `oprint` 64×1 КБ за такт (сервис честно режет до
  `max_actions`) давал миру +1.4 мс на такт в среднем и пик 16 мс на `json.parse` строки TickResult. Лимит
  `max_text_bytes` (4 КБ на сущность за такт) в сервисе снял пик до 3.5 мс. Любой выход песочницы, который мир
  разбирает, надо ограничивать в байтах, а не только в штуках.
- **Цепочка `set_pos` — телепорт.** Мир проверял шаг ≤ 2 блоков от текущей позиции на каждое действие, а 64 действия
  за такт = 128 блоков. Теперь set_pos/rot/vel — по одному на сущность за результат (`dup`), всего ≤ 16 (`flood`).
- **`json.tostring` VoxelCore медленный: около 16 МБ/с.** TickInput на 500 сущностей с видом (351 КБ) кодировался 20–21 мс,
  и такт мира под нагрузкой был 32 мс из 50. Ручная склейка `table.concat` + `tostring` чисел даёт 2.95 мс (303 КБ),
  строка разбирается обратно. `json.parse` 139 КБ — 3.1 мс. Сначала мерить в движке (`tools/olife/tests/bench_tickinput.lua`
  под `lab run olife <file.lua>`), потом оптимизировать. `time.uptime()` под `--test` стоит на месте (виртуальное время),
  для замеров — `time.precise_utc_time()`.
- **Прогрев контрольных владельцев — от их первой строки.** Владельцы из `spawn_scripted` появляются на ~60-м такте.
  Общий прогрев «от первой строки» засчитывал их отсутствие как «не обновлён» (183 плохих строки из 428).
- **Демон перезагружает плагин по mtime раз в секунду.** Если править модуль, который плагин грузит сам
  (`sandbox_real.py`), нужно сделать `touch plugin.py` и подождать больше секунды перед `lab run`. Иначе прогон идёт
  на старом коде без ошибки.
- **`kinds.sandbox` — `copy_exe = true`**: лаборатория запускает копию `builds\olife-sandboxd-<sha>.exe`, wasm берётся по
  `OLIFE_LUA_WASM`. Поэтому `deploy_windows.sh` не упирается в залоченный exe, пока идут аренды (см. запись этапа 6 выше).

## Olife — Rust-шлюз `olife-gateway` (волна 3c, olife_w3g, 02.10)
- **`serde_json` по умолчанию разбирает float не точно.** Векторы из Python (`f64` вида `x/1024`) после `from_value` давали
  другой последний бит — `TickSync.server_ms` кодировался не побайтно. Нужна фича `float_roundtrip`. Проверка побайтно по
  общим векторам ловит это сразу; «примерно равно» — нет.
- **Генерировать Rust-кодеки из той же схемы, а не писать руками.** `gen_codecs.py --lang rust` + фазз-паритет
  (`/root/olife/gateway/tools/fuzz_parity.py`: те же 30 000 мутированных тел через Python и Rust) — 0 расхождений в решении
  «принять/отвергнуть» и в перекодировании. Порядок проверок заголовка (magic → версия → размер → тип) должен совпадать,
  иначе причины `Disconnect` в негативных тестах разойдутся.
- **Учёт байт очереди: всё, что кладёшь в канал, должно быть посчитано.** Кадр `Disconnect` уходил в очередь мимо счётчика
  `out_bytes`, писатель его вычитал → `usize` уходил в переполнение, drain ждал полный бюджет. Ловится тестом drain.
- **Лимиты «на IP» против лаборатории.** Все боты лаборатории идут с 127.0.0.1: прод-умолчания (64 соединения с IP, 20/с,
  всплеск 60) честно отказали 36 из 100 ботов кодом 13. Лимиты — параметры вида (`max_conns_per_ip`, `conn_rate_ip`,
  `conn_burst_ip`), поднимаются только в сценарии нагрузки через `setup.session.gateway_params`. Поле сценария
  `"params": {вид: {...}}` на общем демоне 02.10 до аренды не дошло (демон на старом коде, `stale`) — путь через плагин надёжнее.
- **Python-генератор нагрузки упирается в свой CPU раньше шлюза.** 20 ботов × 55/с: с кодированием каждого кадра отправилось
  73 % плана. Заранее закодированный `PlayerInput` (меняется только `seq`) и разбор только нужных типов → 103 % плана,
  100 ботов × 55/с держатся. Отношение «отправлено/план» — обязательная проверка шага (`min_ratio`), иначе мерится клиент.
- **`pkill -f '<шаблон>'` в той же команде Bash, что и запуск с этим шаблоном, убивает собственную оболочку** (exit 144):
  шаблон совпадает с командной строкой самого `bash -c`. Останавливать отдельным вызовом и шаблоном `[x]yz`.
- **Общий демон: `WinError 32` на `leases.json.tmp -> leases.json`** при параллельных прогонах нескольких агентов — сценарий
  падает на старте без вины проекта; повтор проходит. Это вопрос ядра лаборатории (атомарная запись с повтором).
- **Модуль, который грузит плагин (`gateway_rs.py`), перечитывается только при перезагрузке `plugin.py`** — после правки
  `touch plugin.py` (между прогонами, а не во время).
- **`lab stdin` не видит ответ, когда лог экземпляра больше 512 КиБ** (ядро, `service.stdin`): новые строки берутся как
  `read_tail(path)[before:]`, а `read_tail` отдаёт окно последних 512 КиБ — число строк в окне перестаёт расти, срез пуст.
  После 10 мин мира с 26 сессиями `olife_status` падает «world status missing», хотя мир ответил (строка в логе есть). С обоими
  шлюзами одинаково. Нужна правка ядра (смещение в байтах, не число строк) и перезапуск демона главной сессией; до тех пор
  шаг `olife_status` в длинных сценариях — `optional`.

## Olife — билеты, паки на лету, бинарная песочница (волна 4b, olife_w4b, 02.10)
- **HTTPS в 0.32 = curl + schannel без параметра CA.** `network.request` знает только `verify_ssl`; самоподписанный (и любой не
  из хранилища Windows) сертификат при `verify_ssl=true` → `status 0`, тело «SSL peer certificate or SSH remote key was not
  OK»; `network.get` (параметра нет) — то же. Свой CA в хранилище пользователя ставить нельзя → dev: `verify_ssl=false` +
  запечатывание запроса к закреплённому ключу (x25519/HKDF/ChaCha20-Poly1305 из `crypto`). Проба — `tools/olife/probes/probe_https.lua`.
- **stdlib 0.32 (`res/scripts/classes.lua` @ dc62ccfb): `network.get_binary` и `network.post` сломаны** — сравнивают
  `response.code` (поля нет: «attempt to perform arithmetic on field 'code'» внутри stdlib, твои колбэки не вызываются —
  ни успеха, ни ошибки, состояние «занято» навсегда); `network.get` принимает только статус ровно 200 (`status / 100 == 2` —
  дробное деление). Ходить через `network.request` и проверять `200 <= status < 300` самому.
- **`crypto.*` принимает только строки** («string expected» на Bytearray от `file.read_bytes`/`get_binary`); `crypto.sha256`
  возвращает 32 сырых байта, не hex; `base64.decode` возвращает Bytearray. Перевод Bytearray → строка — кусками через
  `string.char(unpack(t))`.
- **Сетевые вызовы — из главного состояния Lua.** Сообщение пришло в `client.tick()` (корутина стартового скрипта) → только
  запомнить, `network.*` звать из `on_world_tick` (как и `tcp_connect` раньше).
- **`app.reopen_world()` пересканирует источники контента** (пак из `world:content/<пак>` побеждает `user:content`,
  `pack.get_info().path` меняется), **но не сбрасывает кэш модулей стартового скрипта**: `require` после reopen возвращает те
  же таблицы — их состояние сбрасывать явно. *(16.10, olife_menu: в app-скрипте меню клиента это НЕ так — reopen выгружает
  модули пака, `require` даёт новые экземпляры; см. «Olife — меню клиента» ниже.)* Потоки `file.open` не переживают закрытие мира («unknown descriptor» на
  `flush`) — закрыть до reopen и открыть новый файл после. Частичный каталог пака в `world:content` закрыл бы весь пак —
  писать туда пак целиком.
- **Шаги плагина, отданные `api.scenario(steps=...)`, запоминаются при регистрации:** правка вынесенного модуля (`*_w4b.py`)
  без правки `plugin.py` не действует на шаги — регистрировать обёртку, которая берёт функцию из модуля в момент вызова.
- **Имена аренд переиспользуются между прогонами** (`olife-sandbox-1` снова и снова): кэш «что уже отправлено песочнице»
  по имени аренды молча не отправил тариф новому процессу — ключ кэша = аренда + pid.
- **БД supervisor общая для всех агентов:** тестовые ключи тарифов (`limits.owner.9101.*`) после проваленного прогона
  остались и тут же «сломали» следующий прогон; сценарий теперь удаляет свои ключи в `sc_stop` (и при провале), владельцы
  тестов — с номерами, которых нет у других (9101/9102/9201). Писать в БД — только через демон (`lab olife tariff set ... delete`).
- **«Следующий такт» для тарифа мерить по такту сервиса, а не по строкам мира:** в полёте до 3 TickInput, отправленных до
  смены; сервис отдаёт `limits.owners[].state.applied_tick` — первый такт с новыми лимитами (совпал с первым `throttled`:
  219 = 219). Порог 20 000 топлива/такт не делает «throttled каждый такт»: orbit дорабатывает такт за несколько тактов и
  чередует throttled/ok (36 % строк), а фиксированная цена вызова (~60 тыс. топлива) больше порога — топлива на строку
  117 тыс. → 92 тыс., сдвигов 2.0 → 1.3 на строку.
- **Бинарный контракт не ускоряет сам по себе:** первый прогон `bin` дал такт мира p50 23 мс против 14 у `jsonl` —
  `json.tostring` вида каждой сущности (19.4 мс на 500); после ручной склейки (`sbmeter.encode_view`) 4.7 мс и такт 9.6 мс.
  Сам кодек — 0.55 мс. На стороне сервиса вид остаётся JSON-строкой внутри кадра (287 КБ из 334 КБ) — разбирается так же.

## Olife — сетевой код: предсказание, дельты, инвентарь (волна 4c, olife_w4c, 02.10)

## Olife — производительность такта мира, LuaJIT и GC (волна 5p, olife_w5p, 02.10)
Подробно — `agents/research/OLIFE_WORLD_PERF.md`.
- **`jit` в 0.32 полный, кроме подмодулей**: `jit.on/off/flush/status/attach/opt.start` есть (`luaL_openlibs`), нет

  start/stop/abort/flush с функцией (`debug.getinfo(func, "S")` можно) и кодом причины — так видно, что JIT делает в живом
  мире. Таблица причин — `lj_traceerr.h` той же сборки (`D:\Prog\AlphaMine\engine\vcpkg-032\buildtrees\luajit`,
  LuaJIT 2.1.1788856981; у `/root/tools/luajit` другая версия, номера байткодов после `JMP` сдвинуты).
- **Стоковых `maxtrace=1000` / `maxmcode=2048` движку с паком мало**: мир Olife + скрипты base-пака (`grass_block`, `mob`,
  `events`) делят один кэш трасс и требуют ~1450 трасс → кэш сбрасывается целиком 17–18 раз за 25 с, перезаписывается
  ~20 000 трасс, такт p95 26–28 мс, max 71–86. «Код в мире в 10 раз дороже стенда» — это оно: стенд `snapdelta` с
  `jit.flush()` раз в 28 тактов — 0.95 мс против 0.03 (дороже, чем вовсе без JIT). Стенд в тугом цикле сброса не видит.
  Лечится `jit.opt.start("maxtrace=8000", "maxmcode=65536", ...)` в стартовом сценарии (мир: `jit=tuned` по умолчанию).
  Признак в любом паке: `jit.attach` + счётчик `flush`.
- **JIT решает для FFI-Bytearray**: без JIT `Bytearray:append`/индекс в 130–250 раз медленнее, `pcall` в 35; строки,
  `tostring`, `json`, `table.sort` с Lua-компаратором и C API JIT почти не ускоряет (`bench_w5p_constructs.lua`).
  `jit=off` — такт мира 125 мс вместо 11.
- **Ветка по данным в горячей арифметике плодит боковые трассы**: `if h < 0 then h = h + 2^32 end` в FNV (половина байтов)
  — 4 571 трасса с корнем в `fnv_ints` у стока. `bxor(h, b) % 2^32` — то же значение без ветки. Развёртывание такого кода
  в цикл по 500 сущностям дало 1 452 трассы с корнем в `replicate` — с веткой хуже, чем без развёртки.
- **Таблица с целыми ключами 1..n получает массивную часть**, и поиск вычисленным ключом рвёт трассу «NYI: mixed
  sparse/dense table». Ключ чанка `cx*65536+cz` у начала координат = 1, 2, 3 — сделать ключи ≥ 2^31 (`(cx+32768)*65536 +
  (cz+32768)`).
- **Короткие вложенные циклы (1–3 итерации) LuaJIT вносит в чёрный список** («leaving loop in root trace» → «blacklisted»),

- **Мусор = время такта**: 3.3 МБ/такт (виды TickInput таблицами и строками, копии действий TickResult) → цикл GC

  пул записей + действия на месте — 1.7 МБ/такт.
- **GC можно увести из такта**: `collectgarbage("stop")` после такта и `collectgarbage("step", 0)` в простое периода

- **`os.clock` в 0.32 шагает по 1 мс, `time.precise_time` — steady clock с шагом 0.1 мкс** (~40 нс вызов): профиль по

- **Перехеш чанков стоит не FNV, а `world.get_chunk_data`** (кодирование чанка в движке ~0.2–0.5 мс; FNV 736 Б — 9 мкс):

## LLM на wasmrt (smollm, 08.10, llm_port)
- **Бит в бит между нативным C и Lua достижимо, если libm не участвует**: `expf/sinf/cosf/powf` glibc и wasi-libc (musl)
  расходятся на ulp, а Spider эмулирует f32 точно (операция в double и округление — корректно для +,−,×,÷,√). Свои
  exp/sin/cos/pow на double (`src/fmath.c`), таблица cos/sin RoPE, явное округление «от нуля» при квантовании — и логиты
  24576 float из движка равны `cmp` нативным (`reference/logits_*.f32`), токены ответа те же.
- **У Spider f32 — битовый образ i32**: каждая f32-операция делает `from_bits_f32`/`into_bits_f32` (таблица степеней,
  умножения), константы f64 в цикле — `from_bits_f64(...)`, i32 → f64 — `force_s32` с двумя ветвлениями. Поэтому «считать в
  double» в C **медленнее** целочисленного пути в Lua (вариант matmul 3: 2316 против 809 мс/токен — ветвления по знаку
  плодят побочные трассы, LESSONS выше про ветку по данным), а `rt_multiply_i32` (умножение по 16-битным половинам) — 20 %
  профиля. Что помогло: загрузка весов словом по 4 int8 (`memcpy(&w, p, 4)` + сдвиги) вместо четырёх `buffer_read_i8` и
  вынос `/gs` из цикла — 1079 → 809 мс/токен, 0.83 → 1.21 ток/с, результат бит в бит (целые суммы те же).
- **Профилировать модуль Spider можно стоковым LuaJIT**: `LUA_PATH="/root/tools/luajit/src/?.lua;;" luajit -jp=fl run_luajit.lua`
  (`-jp` без LUA_PATH — «jit.* modules not installed»); `-jv` показывает `fallback to interpreter` и `inner loop in root trace`.
  Горячее по строкам модуля + метки `--[[fn:имя]]` — как `eag_profile`, но вне движка и за секунды.
- **Память 100 МБ весов в табличной памяти Spider**: `file.read_bytes` → строка 100 МБ → `fd_read` кусками по 4 МБ
  (`host.write_string`), загрузка 0.7 с в движке; куча Lua после ответа ~365 МБ (слова по 8 байт на 4 байта памяти +
  строка файла), процесс движка WS ~490 МБ, private ~800 МБ — движок держит.
- **`lab logs --grep` и парсер**: пустой результат grep — не пустой вывод (заголовок `# …`), поэтому «ждать строку» = фильтровать
  строки своим `re.search`, иначе ожидание срабатывает мгновенно на мусоре (первый прогон `smollm_check.py`).
- **В шрифте движка нет длинного тире «—»** (квадрат на экране): модель его любит; в ленте чата подменяется на «-» только для
  показа, лог хранит текст как есть.
- **Ввод промпта F2F без ОС**: клик `input {mouse}` по textbox даёт фокус, `input {chars}` печатает UTF-8, `input {keys:{RETURN}}`
  вызывает `consumer` textbox — так промпт попадает в пак тем же путём, что от пользователя; совпадение с логом `[smollm] prompt:`
  проверяется.

## LLM на GPU средствами пака (smollm_gpu, 11.10, llm_gpu)
- **Фреймы `gui.create_frame` рисуются каждый кадр в порядке `std::unordered_map` движка** — не по имени и не по созданию;

  округлением в float — 4096/4096. Произведения — без слияния в fma, суммы — в порядке `model.c`.
- **`assets.to_canvas` синхронный**: сразу после тяжёлого кадра даже 1×1 ждёт GPU 7–29 мс (это и есть время кадра);
  на холодную 1×1 — 0.003 мс, 1024² — 0.7 мс. 24576 float логитов — 18 мс на 0.31, 8 мс на 0.32; argmax считать на GPU.
- **`tonumber(hex, 16)` в LuaJIT насыщается на 2^32−1**: адрес Bytearray `0x0209…` из `tostring(ba.bytes)` превратился в
  4294967295 → падение движка в memcpy `Canvas:_set_data`. Разбирать по цифрам (`n = n*16 + digit`).
- **Простаивающая аренда с конвейером грузит GPU**: фреймы пересчитывают модель каждый кадр, пока экземпляр жив (другие
  агенты видят «GPU busy»). По окончании скрывать картинки (`el.visible = false`), освобождать аренду сразу; даже со
  скрытыми картинками экземпляр держит GPU 43–49 % против 25–40 % фона.
- **Фон GPU этого ПК без движка — 23–40 %** (рабочий стол: Wallpaper Engine, Edge, Steam — `nvidia-smi`), а `lab sysload`
  считает занятым от 30 %: «GPU busy» в выборке ещё не значит чужую аренду — смотреть `lab ps` и `nvidia-smi`.
- **Функция с двумя результатами в конструкторе таблицы**: `{ M.argmax() }` кладёт и индекс, и биты максимума — второй
  «токен» 1098010820 и мусорный ответ при верных логитах. `local first = M.argmax()` перед `{ first }`.
- **0.32 собирает документ фрейма в ~80 раз быстрее**: 418 фреймов / 979 `<image>` через `root:add` — 936 мс на 0.31,
  11 мс на 0.32.

## Генерация мира на GPU средствами пака (gpu_worldgen, 11.10, gpu_gen)
- **У Lua-генератора мира нет хука «готовые воксели»**: `generate_heightmap` (2D), `generate_biome_parameters`,
  `place_structures(_wide)` (структуры, `:line`, `:block` поштучно). Скрипт генератора — отдельное Lua-состояние
  `StateType::GENERATOR` без `gui/assets/world/time`. Путь — генератор пустоты (один слой `core:air`, без скрипта) +
  `world.set_chunk_data` по `on_chunk_present`; заполненные чанки помнить в `world:data/` (сохранённый пустой чанк
  при загрузке снова в очередь).
- **Шум, одинаковый на GPU и в Lua**: хэш узла вместо таблицы перестановок, умножения только на константы < 2^15 (сумма
  < 2^47 точна в double, `bit.tobit` = переполнение uint), параметры в фиксированной точке. Плотность расходится на
  ≤ 4.5e-6 (float32), знак — нигде, коды блоков — 1 воксель из 262144 у порога пещеры.
- **Пакет на GPU подтверждать эхом**: шейдер пишет `serial` пакета в отдельную строку FBO, Lua читает в следующем
  кадре и сверяет — без ожиданий GPU (`waits 0`) и без чтения старого кадра. Когда пакета нет, `ntiles = 0`, иначе
  фрейм пересчитывает чанки каждый кадр.
- **Скорость упирается в Lua, а не в GPU**: 30 чанков на GPU — +0.3 мс кадра; разбор+кодирование+`set_chunk_data` —
  0.59 мс/чанк, бюджет 6 мс/кадр ≈ 10 чанков. Фрейм 1408×861 (110 плиток) не быстрее 768×431.
- **`get_chunk_data` через секунды отличается от записанного**: `base:grass_block` под нависанием от случайных тиков
  становится землёй. Хэши детерминизма считать в момент записи (свой extrle16) или сразу после `set_chunk_data`.
- **Туман в кадрах 0.31 не выключить**: ключа `graphics.enable-fog` нет (`app.set_setting` бросает ошибку), а
  `graphics.fog-curve` 6 оставляет дымку — плотность тумана `15/(load-distance − 2)`. Для кадров рельефа на 0.31 — ближе
  камера или больше load-distance; на 0.32 `enable-fog = false`.
- **Два пака со своим `shaders/ui.glslf` (gpu_worldgen, smollm_gpu) вместе не подключать** — победит один. (12.10: решено паком
  `gpu_compute` — общий `ui.glslf`, собранный из тел программ клиентов; см. раздел gpu_compute ниже.)

## gpu_worldgen — пресеты-витрины, страница меню, свет (12.10, gpu_show)
- **Амплитуда fbm мала: std 0.16, p99 0.39** (улучшенный Перлин, 5 октав, нормировка). Плотность `fbm·AMP + (H−y)/HS`
  даёт смещение поверхности ≈ 0.16·AMP·HS блоков: classic (3·40) — ±19, это холмы. «Amplified»-башни и нависания
  появились только при AMP·HS ≈ 400 (8·50) и масштабе по y больше, чем по xz (80×110). Форму удобно подбирать
  срезами x–y на numpy-копии шума (тот же хэш, 2 с на 4 варианта), а не прогоном движка (минута).
- **Закрытие мира выгружает контент паков** (`unloaded gpu_worldgen:modules/...`): страница пака после `close_world`
  уже не существует — `menu.page = "<пак-страница>"` падает в `gui_util.lua:63` «expected string, got none» и роняет
  движок (uncaught exception). Перед возвратом на страницу — `app.config_packs` + `app.load_content` заново.
- **После мира курсор остаётся захваченным**, если мир закрыли не через меню паузы (сценарий `app.close_world`): кнопки
  страницы не нажимаются (клик F2F не доходит). На странице в `on_open` — `gui.set_active_frame(gui.main_frame_id)`
  (как в LESSONS про захват курсора). Обработчики `events.on` app-скрипта — заново на каждом круге «страница → мир».
- **Светящиеся блоки дороги для движка, не для пака**: caves без излучателей — 341 ч/с, 59 fps; светокамень 0.3 со
  светом 15 — 261 ч/с, 52 fps. `light_chunk` (F2F `perf`) на чанк: classic 1.0 мс, горы 1.5, пещеры 1.7, острова 2.2
  (небесный свет растекается под острова и нависания). GPU при этом 0.02–0.06 мс/чанк, Lua 0.58–0.75 мс/чанк. Рычаги
  пака: меньше излучателей, слабее `emission` (12 вместо 15 — объём заливки ~в 2 раза меньше) и `target_fps` 50.
- **Таблица байт→id вместо полубайтов в разборе плитки скорость не дала** (0.23 мс/чанк до и после): узкое место —
  65536 записей в таблицу Lua, а не `band/rshift`. `Bytearray:append(Bytearray)` вместо побайтной копии работает в 0.32.
- **Поиск точки спавна (тысячи `block.get`) — когда очередь пуста**: посреди генерации он добавлял кадр-ступеньку.
- В `base` нет снега, лавы, светокамня, аметиста — блоки пака с процедурными текстурами 16×16 (PIL), `emission` и
  `tags: core:liquid` для лавы. Вода и лава неподвижны: водопад — статичный столб воды.

## LLM на wasmrt — ускорение на CPU (smollm, 11.10, llm_cpu)
- **Сначала профиль по ядрам, потом правки.** Импорт `vc.llm_kprof(id, фаза)` вокруг каждого ядра C дал таблицу прямо из движка:
  матвек + логиты — 85 %, внимание — 10–22 % (у трансляции 1 мкс на MAC внимания против 77 нс у матвека). Самопроверка ядер
  по дампу входов/выходов нативной сборки (`reference/kernels`) ловит расхождение до сравнения логитов.
- **f32 как число Lua даёт много, но не везде.** `--f32 number` (округление Veltkamp `c = x*(2^29+1); c-(c-x)` после каждой
  операции — ties-to-even проверено на 2 млн половинных случаев) — smollm 869 → 683 мс/токен бит в бит, Quake в стоковом LuaJIT
  5.1 → 18.6 кадров/с, но в движке (tuned) у Quake разброс больше выигрыша. Теряются только знак и полезная нагрузка NaN
  (конформанс 272/40: `f32_bitwise`, `local_tee`), поэтому это опция, а не умолчание.
- **«Умножение i32 через double с проверкой диапазона» замедлило Quake в 1.5 раза** (24–29 против 38–41 кадров/с), и вариант
  без ветвления (два точных произведения) — тоже: прежнее умножение по 16-битным половинам LuaJIT сужает до целочисленных
  операций, а произведение 32-битных слов в double — нет. Откатили; smollm это не мешает (матвек ушёл в ручное ядро).
  Проверять правку рантайма Quake-timedemo в стоковом LuaJIT с `jit.opt` как у wasmrt — разброс там тоже есть (27–35 кадров/с
  у одного модуля), нужно 2–3 прогона.
- **`-loop` из `tuned` wasmrt вредит коротким горячим циклам**: smollm на трансляции 683 → 454 мс/токен от одного `+loop`
  (LICM выносит загрузки `buf.__w`/`__n` из цикла). Поле манифеста `jit_opt` — на программу, остальные паки не задеты.
- **Ручное Lua-ядро бит в бит с C возможно**: целые суммы групп int8 точны в double, а float-операции на группу округлять до
  binary32 (3 на 64 MAC — дёшево). Матвек 1.14 GMAC/с против 0.12 у трансляции. Батч: «два токена в одном double»
  (`x_a + x_b·2^21`, сумма группы < 2^20) — одна MAC-пара за умножение, 2.4 GMAC/с. `fm_exp` повторён на Lua теми же
  операциями — softmax внимания бит в бит.
- **Prefill считал логиты каждого токена промпта** (24576×768 MAC на токен) — у последнего токена они нужны, у остальных нет:
  155 мс/токен из 911 уходили впустую.
- **Каталог экземпляра аренды переживает аренды**: флаги прошлых прогонов в `<инст>\export\` (`smollm_kprof.txt`, манифест)
  включались в следующем — `smollm_check.py` теперь их удаляет перед стартом.

## smollm_gpu: чат на GPU-пути (12.10, llm_gpu_chat)
- **Скрытая картинка ≠ сохранённые данные фрейма**: фрейм `gui.create_frame` очищается каждый кадр, поэтому KV-кэш во фреймах
  переживает простой, только если копирование KA↔KB/VA↔VB оставить видимым; пишущую строку KVPUT при этом скрыть (её источник

- **`Bytearray` 0.31/0.32 — FFI cdata**: `ba[i]` идёт через `__index`-функцию на каждый байт; `ba.bytes[i]` (0-based) —
  прямой указатель. `Bytearray_as_string(ba)` даёт строку для `string.byte` (так один Lua-модуль работает и в движке, и на
  стоковом luajit-стенде).
- **«Чтение логитов 13 мс» на 0.31 — это ожидание кадра GPU**, а не стоимость чтения: на 0.32 то же чтение 1 мс, а время на токен
  одинаковое. Прежде чем оптимизировать readback (top-k на GPU), сравнить итоговые ток/с argmax и семплирования (40–45 против 40–43).
- **Замер рядом с чужой GPU-арендой несопоставим**: при живой аренде gpu_show (генерация мира) тот же чат давал 24–37 ток/с и
  prefill 26–38 мс/токен вместо 40–45 / 21–23. `lab ps` до и после — в отчёт; цифры только из прогонов без чужих аренд.
- **Таблица `bytes_to_unicode` GPT-2 в `tokenizer.bin` уже обращена** (`tokenizer_export.py` пишет сырые байты токенов): в
  кодировщике её нет, 256 однобайтовых токенов = 256 байтов. Не «добавлять» её второй раз.

## Half-Life: разгон ref_soft на LuaJIT (12.10, hl_gpu)
- **Сначала смотреть долю интерпретатора, не только функции**: `luajit -jp=vF` (или `HL_PROF_MODE=vF` в `run_luajit.lua`)
  показал «Interpreted 49–57%» — горячие функции рендера Xash не становятся трассами (рекурсия `R_ClipEdge`/
  `R_RecursiveClipBPoly`; функция, вызывающая растеризатор с внутренними циклами → «loop unroll limit»/«inner loop in root
  trace», потом чёрный список). Параметры JIT (`loopunroll`, `instunroll`, `maxrecord`, `recunroll`, `hotexit`) не помогли;
  убрать рекурсию (явный стек) или вынести внутренний цикл (отложенная вставка рёбер) — тоже нет. Помогло: (1) ручное ядро
  на Lua для самого горячего цикла; (2) разделить «настройку вершин» и «растеризацию» на два цикла — первый без
  внутренних циклов становится трассой; (3) **дешевле в интерпретаторе**: склеить помощники Spider (`rt_multiply_f32` →
  `round_f32`, `rt_load_f32` → `buffer_read_i32` + `from_bits_f32`) в одну функцию — 14.8 → ~21 fps без изменения кода C.
- **Микробенч помощника в трассе ничего не говорит о движке**: «быстрый» `into_bits_f32` без деления — те же 13 нс в цикле
  `luajit`, а склейка вызовов, незаметная в трассе, в движке дала +17%, потому что половина кода — интерпретатор.
- **Сброс всех трасс по `maxtrace`**: у большой программы (34 МБ Lua) за ~60 с набирается 8000 успешных трасс (`JIT_TUNED`
  wasmrt) → `jit.flush` всего → fps 22 → 12 и не возвращается. Видно счётчиком `jit.attach(..., "trace")` (событие `flush`;
  `"jit_stat": true` в манифесте halflife). Лечится `"jit_opt": ["maxtrace=40000", "maxmcode=262144"]` в манифесте.
- **Вне движка стоковый JIT (maxtrace 1000, maxmcode 2 МБ) в 3–4 раза медленнее движка** (мир ~300 мс/кадр против ~110):
  стенд должен ставить те же `jit.opt`, что `host.set_jit_tuned` (теперь — по умолчанию в `run_luajit.lua`).
- **Хэши кадров на виртуальных часах — доказательство паритета каждого шага** (кадры 1–845, мир — с ~740-го); время стенда
  шумит ±20% между запусками одной сборки (параллельные прогоны, другие агенты) — решения по скорости только A/B в движке
  подряд, одна сборка с переключателем (`"env": {"HL_SPAN_KERNEL": "0"}`) или два манифеста с разными `module`.


## gpu_worldgen — RLE на GPU и свет (13.10, gpu_pack2)
- **«Префиксная сумма» по 256 слоям — прямым суммированием в текселе** (≤ 255 выборок): один проход вместо 8–16 проходов
  дерева, GPU всё равно простаивает. Узкое место цепочки — поиск байта в кадре потока: двоичный поиск слоя + проход по слою
  на каждый байт стоил 0.155 мс/чанк (горы); один поиск на тексель и переход к следующей серии — 0.08.
- **Один сэмплер на картинку → данные едут по цепочке в самом кадре**: первый проход копирует слова параметров в верхние
  строки кадра, каждый следующий копирует вход и дописывает свою область. Эхо serial по всей цепочке делает неверный порядок
  фреймов безопасным (только задержка).
- **Блок другого пака можно переопределить из своего**: `content.json` `"blocks": ["base:stone"]` + `blocks/base/stone.json`
  с нужными ключами — движок дописывает их в существующее определение (id те же). Так выключается заливка неба
  (`sky-light-passing: true` у всех блоков) без правки движка.
- **Свет неба в мирах gpu_worldgen был артефактом**: чанк освещается, пока соседи пустые (небо 15 генератора пустоты), свет

## gpu_worldgen — потолок прохода и чанков на кадр (13.10, gpu_cap)
- **Размер GPU-прохода не брать по окну**: шейдер платит за каждый пиксель картинки, а чтение (`assets.to_canvas`) — за весь
  фрейм, сколько бы плиток ни было занято. Проход 2048×2048 при 24 чанках — 25–30 мс кадра против 8 мс у 768×432.
  Фиксированный потолок + настройка; картинку прохода подгонять под пакет (несколько `<image>` в фрейме, `pos`/`size`).
- **Строки FBO фрейма ↔ UI-координаты картинки**: строки [a, b) (0 — низ) = `pos.y = H − b`, высота `b − a` (камера UI
  перевёрнута, `Frame::draw` прижимает фрейм к низу окна).
- **Чанки в очередь пака подаёт движок, и не быстрее ≈ load-speed / 1.3 мс** (≈ 24 пустых чанка за кадр при 32 мс): прежде
  чем растить «окно» GPU, мерить, сколько чанков к нему вообще приходит (`raw`-темп и перезапись загруженных чанков
  разделяют проход и подачу).
- **Темп по fps душит запись, когда fps опускает сам движок** (полёт: создание пустых чанков) — 1 ч/кадр при очереди 2700.
- **Дальность 80 (максимум настройки) на этом ПК не запускать**: ≈ 0.6 МБ на чанк у процесса, ld 80 ≈ 12 ГБ. Перед прогоном с
  большой дальностью смотреть свободную память (`Get-Process`/`Win32_OperatingSystem`).
- **`lab sysload` во время своей аренды почти всегда «GPU busy»** — это сам движок аренды; занятость ПК судить по снимкам
  до/после и посторонним процессам.


## Пак blackhole на 0.32.1 (15.10, агент blackhole)
- **`audio.play_stream` в 0.32.1 навсегда занимает источник OpenAL.** `audio::update` удаляет динамик потока только при
  `!manuallyStopped && isStopOnEnd()`, у `play_stream` `stopOnEnd = false`, после `audio.stop` динамик тоже остаётся: после
  ~255 вызовов «attempted to create new source, but limit is 255». Короткие звуки — `audio.PCMStream(rate,1,16)` →
  `:feed(pcm)` → `:create_sound(имя)` → `audio.play_sound(имя, ...)` (динамики удаляются по концу; `get_duration` у них 0).
- **`player.get_all_in_radius(c, r)` 0.32.1 = радиус `sqrt(r)`**: `Players::getAllInRadius` сравнивает `length2` с `radius`.
  Брать `player.get_all()` и считать расстояние самому.
- **Имена предметов и сущностей в 0.32 — одно пространство**: предмет и сущность `pack:grenade` → `load_content` падает
  «name pack:grenade is already used» (exit 0xC0000409 в аренде).
- **`vec3.cross` в 0.32 нет**; `mat4.rotate(axis, deg)` / `mat4.mul(a, b)` есть.
- **Звук в аренде `wasmrt`**: `--param audio='"true"'` (строка JSON: булево `true` подставляется в TOML как `True` и
  движок падает на разборе settings.toml), громкость — `app.set_setting("audio.volume-master", 0)` из сценария.
- **Снимок по маркеру лога опаздывает на 0.5–3 с** (опрос `lab logs` через Windows-Python; синхронный `lab sysload` в
  драйвере держит очередь маркеров): держать камеру до квитанции — драйвер после `f2f shot` пишет
  `artifacts/lab/inst/<аренда>/export/<файл>`, сценарий ждёт `file.exists("export:<файл>")`. Маркер искать по точному
  шаблону (`view X: cam`), иначе строка «view X held» даёт второй снимок с другой камеры.
- **Без vsync**: `display.framerate = -1` — vsync (144 Гц предел), `0` — без ограничения; для замера стоимости в аренде
  `app.set_setting("display.framerate", 0)`. `lab sysload` считает GPU всего ПК — свой экземпляр без vsync сам даёт «GPU busy».
- **`VoxelFragment:place` не ставит воздух** (пропускает вокселы с runtime-id 0): стирать фрагментом — только своим
  невидимым заменяемым блоком (`blackhole:void`, как `fastblock:empty`). `place` пишет все ненулевые клетки фрагмента и
  считает свет на каждой — у поверхности (воздух в оболочке) он медленнее `block.set`; выигрыш стирания фрагментом в паке —
  в отказе от сущности-обломка на каждый блок. Песок над `void` осыпается (void заменяемый).
- **Звук `block.place` без ограничения голосов**: каждый `block.place` (и приземление `base:falling_block`) — звук материала;

  установку блоков — `block.set(..., noupdate)` или квота звуков.
- **G-буфер в пост-эффекте 0.32**: `u_position` (видовые координаты) есть только при `graphics.advanced-render` (в шаблоне
  аренды `wasmrt` он выключен; сценарий включает `app.set_setting` до мира). Небо — нули (`w = 0`) или направление · 1e6.
  Без G-буфера сэмплер `u_position` не привязан — флаг передавать параметром (`vc.get_setting`).
- **Кадр «на середине» быстрого процесса**: снимок по маркеру лога опаздывает на 0.5–0.9 с — процесс замораживать на время
  снимка (в паке `core.time_scale = 0`), а не ловить моментом.
- **Флуд `[E]` в логе прячет маркеры сценария**: драйвер читает `lab logs --tail 600 --grep` — тысячи строк ошибок вытесняют
  `view X: cam`, кадр не снимается (`held 15.00 s, ack false`).

## Olife — каретка редактора и TTF-шрифты 0.32 (olife_caret, 16.10)
- **`<textbox>` 0.32 с TTF: каретка/выделение/клик = символы × `size/2`, а текст — с FreeType advance.** Для шрифта с флагом
  `FIXED_WIDTH` `FontMetrics::calcWidth` = `n × glyphInterval` (`size/2`), `draw_text` шагает `xAdvance` (пробел — `size/2`).
  Моноширинный TTF совпадёт, только если его advance ровно 0.5 em (DejaVu Sans Mono — 0.602 em → 10 px при 16, каретка
  уезжает на 2 px за символ). Обход — пересобрать шрифт под 0.5 em (fontTools: контуры × k по x, advance = upm/2, хинтинг
  долой). Немоноширинный шрифт (`isFixedPitch = 0`) не спасает: выделение, клик и прокрутка меряют от начала всего текста.
- **0.32 рисует битмап глифа TTF с позиции пера, без `bitmap_left`** (`Glyph` = только `yOffset`, `xAdvance`): все буквы
  прижаты к левому краю ячейки. Нулевой контур (3 совпадающие точки) в x = 0 расширяет рамку контура до пера — глиф стоит, как
  задуман.
- **`node.focused = true` у уже сфокусированного узла СНИМАЕТ фокус** (`p_set_focused`: ветка `else if (isFocused)
  defocus()`). Ставить через `if not node.focused then node.focused = true end` (проба теряла каретку и Shift+End через раз;
  в `editor.xml` поправлен `onclick` поля кода; `chat.lua` ставит `prompt.focused = true` после отправки — там поле уже без
  фокуса после Enter, но правило то же).
- **Каретка мигает (0.5 с вкл/выкл от последнего `setCaret`)**: для снимка ставить `caret` каждый кадр (каждый `setCaret`
  обновляет `caretLastMove`), иначе кадр попадает на «выкл». Выделение не мигает — его мерить надёжнее.
- **Документ пака в меню без мира**: страница `layouts/pages/<имя>.xml` тестового пака с `<iframe src="<пак>:<документ>">`
  + `menu.page = "<имя>"` показывает настоящий макет HUD/оверлея (редактор) без сервера; свои элементы — `gui.root.root:add(xml)`.
- **`gui.get_viewport()` возвращает таблицу** `{w, h}`, а не два числа (`local vw, vh = gui.get_viewport()` дал `vw` = таблица).

## Olife — игра с друзьями по сети (olife_friends, 16.10)
