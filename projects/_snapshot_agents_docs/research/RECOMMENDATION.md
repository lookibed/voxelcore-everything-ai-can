# Сводная рекомендация: «взрослая» тестовая инфраструктура AlphaMine (01.10)

Три исследования (`ORCHESTRATION.md`, `MCP_REDESIGN.md`, `DETERMINISM.md`) независимо пришли к одной архитектуре.
Ниже — что строить, в каком порядке и что это закрывает из десяти проблем (нумерация — из отчёта «что не так в MCP»).

## Решение в одну строку
**Лабораторный демон `labd` на Windows-Python 3.13 (только 127.0.0.1) + тонкий stdio-мост MCP в WSL + тестовый
патч Java-сервера `f2f-server` с пошаговым тактом.** Правок рабочего движка не требуется; всё остальное —
Python, сценарии, манифесты.

## Почему именно так (проверенные факты)
- Windows 10 22H2 (19045): зеркальная сеть WSL недоступна, реле из WSL к `127.0.0.1` Windows неустранимо
  настройкой. Поэтому управляющий процесс должен жить на стороне Windows. Образец уже есть у пользователя:
  EdenSpark — stdio-мост `C:\Python313\python.exe` → HTTP на 127.0.0.1.
- Процессы, запущенные через WMI/PowerShell из WSL, не попадают в Job Object; владеть деревом процессов может
  только тот, кто сам их создаёт на Windows (`CreateProcess` + Job с kill-on-close). Это и есть «аренда экземпляра».
- Холодный `powershell.exe` 0.68 с, холодный `python.exe` 0.06 с, тёплое соединение F2F 0–10 мс: дорого установление,
  а не протокол. Постоянный пул соединений в демоне убирает 1–2 с на вызов.
- В `C:\Python313` уже есть pywin32, psutil, FastAPI, uvicorn, pytest, numpy, pillow, matplotlib, Jinja2.
- Недетерминизм Java/Java (70/73 кадров) — потоки сети сервера и его ГСЧ (файлы и строки в DETERMINISM §1–2);
  лечится только пошаговым сервером с барьерами, «VCR» пакетов — надстройка над ним, не замена.

## Порядок и сроки (оценки агентов, без параллели; при 2–3 агентах короче)
1. **Демон, аренды, пул F2F, мост MCP** — 5–6 дней (первая польза с 4-го дня: аренды и прямые вызовы).
2. **Единый интерпретатор сценариев + каталоги прогонов + golden-манифесты** — 4 дня (побайтно те же sha, что у старых раннеров — критерий приёмки).
3. **История, ворота, `index.html`, `lab play`, ночные ворота через Планировщик (условие «ПК простаивает»)** — 3 дня.
4. **`f2f-server` + хэши по тактам + контрольный кадр сессии** — 3.5–4 дня.
5. **Перф: `perf` в тестовой сборке, повторитель нагрузки, Perfetto** — 2 дня.
6. **Запись потока пакетов, видео/тепловая полоса/мерцание в отчётах** — 2 дня.
Итого ≈ 20 дней последовательно; этапы 1–3 и 4 независимы и параллелятся. Старый MCP остаётся рядом до конца этапа 2.

## Что сохраняется
Протокол F2F и патчи клиента, форматы сценариев JSON, `compare.py`/`e2e_compare`/`perflib`, журнал JSONL
(с новыми полями `instance`, `run`, `agent`), PSWorker для старых `.ps1`, инструменты `eag_*`.
Удаляются: `f2f_relay.ps1`, собственные запуски процессов в раннерах, pid-файлы, 9 копий exe «по буквам».

## Решения, которые остаются за пользователем
- Запуск этапов (и сколько агентов параллельно; этап 1 — один агент, он создаёт фундамент).
- `f2f-server` — тестовый патч оригинального сервера (аналог F2F в клиенте): разрешить?
- Тестовые правки движка: `perf` фазы кадра, сброс `u_timer` в `mode`, экранирование не-UTF-8 в ответах F2F,
  `GL_RENDERER` в `hello` — все в духе правила «только тестирование».
- Отдельно (из перф-отчёта): все блоки пропускающими свет для движка и/или бюджет записи чанков в кадр.

## Риски
Демон — единая точка отказа (намеренно: его падение гасит тестовые экземпляры, чтобы не было сирот); переход
на один интерпретатор должен дать побайтно те же sha; гибридная графика ноутбука (выбор GPU по пути exe —
фиксировать `GL_RENDERER`); рост `runs\` (271 МБ за два дня — ротация); Claude Code не переподключает
stdio-мост сам — мост умирает, демон живёт.
