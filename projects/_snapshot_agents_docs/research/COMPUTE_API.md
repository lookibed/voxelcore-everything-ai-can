# Пак `gpu_compute`: API «compute-шейдера» средствами стокового VoxelCore (дизайн, 12.10, главная сессия)

Обобщение двух рабочих костылей: генерация чанков на GPU (`content/gpu_worldgen`, `modules/gpu.lua`) и инференс LLM на GPU
(`content/smollm_gpu`, `modules/llm.lua`, `matvec.lua`). Оба делают одно и то же руками: рисуют фрейм `gui.create_frame`
со своим `shaders/ui.glslf`, подают данные текстурами, читают результат `assets.to_canvas` (0.31 и 0.32; на 0.32 ещё
`gui.screenshot`). Задача пака — вынести общее в библиотеку, чтобы третий потребитель (например, Half-Life/Quake-растеризация,
физика, шумы) не писал это заново, и **снять конфликт одного `ui.glslf` на мир**: сейчас два пака с вычислениями вместе не
включаются. Движок не меняется; всё — Lua + GLSL пака.

## Примитивы (проверены числами в SMOLLM_GPU.md и GPU_WORLDGEN.md)
| примитив | как сделано сейчас | цена |
|---|---|---|
| программа | `ui.glslf` пака: по цвету-маркеру картинки (`#FE03FF80` worldgen, `#FF<режим>FF80` llm) ветвится в вычислительный режим | один `ui.glslf` на мир |
| буфер на GPU | `file.read_bytes` → `Canvas:_set_data(адрес)` → `create_texture` (RGBA8; 138 МБ за 0.18–0.3 с, max 32768) | — |
| параметры | текстура 256×4 (worldgen) / картинка-токен (llm), uniform через `a_color` маркера | — |
| проход | фрейм W×H (≤ окна), в нём `<image>` с маркером; движок рисует все фреймы каждый кадр в порядке хеш-таблицы; порядок стабилен, определяется пробой и кешируется | GPU 0.01 мс/плитка 256² |
| цепочка проходов | фрейм B читает текстуру фрейма A по имени; в порядке отрисовки — до 418 зависимых проходов за один кадр (llm) | — |
| чтение | `assets.to_canvas(<текстура фрейма>)` RGB (альфа теряется): 256² 0.06–0.09 мс, 1024² 0.73–2.5 мс; сразу после тяжёлого кадра ждёт GPU 7–29 мс; конвейер «submit в кадре N, read в N+1» не ждёт | — |
| точность | выход RGBA8 → float = 2 текселя (RGB×2), int8 ×3 на тексель; fp64-расширение в шейдере даёт деление/корень/exp бит в бит с C | — |
| простой | фреймы перерисовываются всегда: после работы картинки скрывать, иначе экземпляр грузит GPU | — |

## API пака (Lua, `gpu_compute:compute`)
```lua
local gc = require("gpu_compute:compute")
local prog = gc.program{ id = "noise3d", glsl = file.read("mypack:shaders/noise3d.glsl") }   -- тело режима (функция main_<id>)
local buf  = gc.buffer{ id = "weights", bytes = bytearray_or_string, width = 768 }          -- RGBA8-текстура из байт
local prm  = gc.params{ id = "p", words = 1024 }                                             -- текстура параметров (u32/f32 слова)
local pass = gc.pass{ id = "gen", program = "noise3d", width = 768, height = 431, inputs = { buf }, params = prm }
gc.submit(pass, { seed = 1, scale = 0.01 })   -- параметры в текстуру, картинки показать; рендер — в этом кадре
local data = gc.read(pass)                    -- nil, пока кадр не нарисован; иначе Bytearray RGB (+ серийный номер пакета)
gc.chain{ passes = { a, b, c } }              -- зависимые проходы; библиотека сама упорядочивает фреймы по пробе порядка
gc.idle()                                     -- скрыть картинки (GPU в простое)
gc.codec.f32_to_rgb / rgb_to_f32 / i8x3 / u16 -- упаковка значений (общие с llm/worldgen)
gc.budget{ ms_per_frame = 6, fps_floor = 50 } -- сколько проходов/чтений пускать за кадр
```
- **Один `ui.glslf` на всех**: пак `gpu_compute` держит `shaders/ui.glslf` с диспетчером по маркеру `#FD<prog>FF80`
  (R=253: не пересекается с `#FE…` worldgen и `#FF…` llm); тела режимов паков-клиентов подключаются **сборкой шейдера в Lua**
  из `gc.program{glsl}` в один исходник (`assets`/`gfx` перезагрузка шейдера — проверить, что умеет 0.32: если шейдер
  читается только при загрузке контента, то сборка на этапе `preload`/первого запуска мира с перезаписью `ui.glslf` в
  `world:content/gpu_compute/shaders/` + переоткрытие, как у «паков на лету» Olife). Клиенты worldgen и llm переводятся на
  `gc.program` (их маркеры остаются как режимы), после чего включаются вместе.
- **Проба порядка фреймов** — одна на мир, кешируется в `config:gpu_compute/order.json`; `gc.chain` раздаёт роли по ней.
- **Чтение**: по умолчанию конвейер N/N+1 (как worldgen); `gc.read(pass, { sync = true })` — ждать (как llm).
- **Ограничения, которые API честно показывает**: `gc.limits()` → `{ max_pass_w, max_pass_h }` = окно; одна входная текстура на
  проход (`u_texture`) — буферы и параметры склеиваются в одну страницу библиотекой (`gc.page{...}`); RGB-выход.

## Клиенты и проверка
1. `gpu_worldgen` → `gc.pass` + `gc.codec` (ожидание: те же 420 чанков/с, хэш области тот же).
2. `smollm_gpu` → `gc.chain` из 418 проходов (ожидание: те же 40–45 ток/с, логиты бит в бит).
3. Новый пример-клиент `examples/` в паке: 3D-шум в текстуру и чтение (учебный), и `bench` (мс на проход, чтение) —
   сценарий лаборатории `gpu_compute_check.py` на v031/v032: пример, оба клиента вместе в одном мире, числа не хуже их README.

## Что остаётся движку (апстрим, из обоих документов)
рисование фрейма по требованию; 2+ сэмплера в UI-шейдере; float-выход фрейма без смешивания; явный порядок фреймов;
фрейм больше окна; асинхронное чтение (PBO); хук генератора с полным массивом вокселей; загрузка шейдеров пака на лету.

## Сделано / отклонения от дизайна (12.10, агент gpu_api)
Пак `content/gpu_compute` (README пака — API, пример, числа), клиенты `gpu_worldgen` и `smollm_gpu` переведены; **оба
работают в одном мире** (`tools/scenarios/gpu_compute_both.py v031|v032`: хэш генерации `b3e5e930`, ответы LLM == C,
второй ответ — одновременно с генерацией новой области, её хэш `b06935b9` == прогону без LLM).
- **Сборка шейдера — заранее, а не в Lua** (отклонение): в 0.31/0.32 нет Lua-API загрузки/перезагрузки шейдеров (в `assets`,
  `gfx`, `gui`, `app`, `core` нет ничего с `shader`), каталог пака из Lua не пишется (`is_writeable=false`, `write=false`) —
  проверено в движке `gpu_compute_check.lua` на обеих версиях. Путь «перезаписать `world:content/.../ui.glslf` и переоткрыть»
  не проверялся: шейдер UI нужен и меню, а пересборка на каждый мир не даёт выигрыша перед сборкой при установке.
  Поэтому `tools/gpu_compute_build.py` собирает `gpu_compute/shaders/ui.glslf` из `content/<пак>/shaders/gpu_<имя>.glsl`
  (директива `// @gc program=… marker=… codes=…`, функция `gc_main_<имя>(int code)`) и реестр `data/programs.json`;
  `gc.program{id}` берёт маркер из реестра (поле `glsl` дизайна не нужно). `--check` — актуальность сборки.
- **Маркеры**: банк = R (`FD` — пак и новые клиенты, `codes=auto`; `FE` — worldgen; `FF` — llm, коды 0–255), код = G,
  B = 255, A = 128; прежние маркеры клиентов сохранены — их Lua почти не менялся.
- **API**: как в дизайне, плюс `gc.frame(id, w, h)` (кадры цепочки нужного размера), `gc.show/hide`, `gc.read` с
  `serial_texel` (эхо пакета) и `canvas = true`; `gc.chain` возвращает ids в порядке отрисовки, роли раздаёт клиент;
  кеш порядка — `config:gpu_compute_order.json` (а не `config:gpu_compute/order.json`).
- **Цена общего шейдера — регистры** (в дизайне не было): один фрагментный шейдер = одно число регистров на все программы.
  Тело worldgen с пресетами замедлило LLM 38.6 -> 31.4 ток/с; правки тела без изменения результатов (параметры пресета
  чтением текстуры вместо массива `g_p[44]`, битовые маски вместо bool-массивов, ветка пресета с константой) вернули
  35.3–36.8 ток/с; остаток ~5% — пресет islands (опыт `--exclude`/заглушки: без islands 38.0). Хэши пресетов те же.
- **Числа** (854×480, F2F realtime): пример noise — 0.047 мс на проход 256², ~207 проходов в кадр 60 fps, 64 фрейма
  цепочки — проба 0.95 с, из кеша 0.07 с; worldgen classic — A/B с кодом до API подряд: 307 против 309 ч/с в среднем
  (сегодняшний ПК, README пака 420–432 ч/с 11.10 с ним не сравнимы), в мире с LLM 392–421 ч/с до ответа; LLM в мире с worldgen 35.9–36.0 ток/с, во время генерации 33.7–34.0 ток/с.
- Не сделано: `gc.budget` клиентами не используется (у worldgen свой бюджет кадра); генерация во время ответа LLM
  проседает до ~70 ч/с (кадр токена 25–40 мс съедает её fps-пол); остаток цены регистров от islands.
