# Olife: антифрод и бан по IP при входе по нику (16.10, агент olife_antifraud)

Постановка пользователя 16.10: «авторизация по нику, нужен бан по ip и антифрод система». Решение §8 п.3 `OLIFE_UX.md`:
вход по нику + вайтлист, **без пароля**. Значит, ник — не секрет, и защищать надо сервер и чужие ники **лимитами,
квотами и автоматикой, прозрачными для опа** (кредо §9: не запреты возможностей). Записка — до кодирования; статус
реализации и проверки — в конце (§5).

## 1. Угрозы → меры
| # | угроза при входе по нику | мера | где |
|---|---|---|---|
| 1 | вход под чужим ником, пока владелец играет | ник уже в игре с другого IP → отказ `nick_in_use` (билет) / `Disconnect 18` (шлюз). С **того же** IP — прежнее поведение (новый вход выбивает старый, код 12: падение клиента) | сервис билетов → supervisor (`olife_fraud`), оба шлюза |
| 2 | «перехват» ника сразу после выхода владельца | ник закреплён за последним IP на `nick_grace_s` (300 с) после последнего признака жизни (билет или живая сессия в `gw_sync`) → `nick_in_use`; оп снимает `fraud clear nick:<ник>` | supervisor |
| 3 | имперсонация похожим ником (`Admin`/`admin`, `аdmin` кириллицей, `d_e-v`, `adm1n`) | «скелет» ника (регистр, гомоглифы кириллица/греческий → латиница, `0→o 1→l 3→e 5→s`, без `_ . -`) совпал со скелетом существующего аккаунта или зарезервированного имени → `nick_similar`; список зарезервированных (`admin, op, operator, server, root, system, console, world, olife, moderator, mod, owner, support, null, guest`) → `nick_reserved` | supervisor; шлюзы — имя в `Hello` только ASCII `[A-Za-z0-9_.-]` (§6 п.6 `OLIFE_GATEWAY_SECURITY.md`) |
| 4 | перебор/спам выдачи билетов с одного адреса | ведро билетов на IP (20/мин) и на подсеть /24 (IPv6 /64, 60/мин) → `rate_ip` / `rate_net` | supervisor (ник и токен: сервис билетов спрашивает `olife.ip_check`) |
| 5 | мультиаккаунт: много ников с одного IP | разных ников с IP за окно > `nicks_per_ip` (4 за 600 с) → `multi_account` | supervisor |
| 6 | толпа сессий с одного IP | живых сессий с IP > `sessions_per_ip` (3) → `Disconnect 13` (шлюз), `sessions_ip` (билет) | оба шлюза (+ сводка `gw_sync`) |
| 7 | флуд соединений с подсети | ведро соединений на /24 у шлюза (60/с, всплеск 180) поверх ведра на IP (20/с) → 13 | оба шлюза |
| 8 | упорный нарушитель | каждое превышение п.4–7 = «страйк» IP → **автобан IP** `autoban_base_s × 2^(страйк−1)` (60 с, 120 с, 240 с … ≤ 24 ч), запись «автобан, причина» в `bans` (`by = fraud`), события и аудит; страйки забываются через 24 ч | supervisor |
| 9 | флуд в игре (чат, команды, действия сверх тарифа, спам инжектов/спавнов, переподключения в цикле) | **скоринг аккаунта** в мире: очки за событие отказа (веса), экспоненциальное затухание (полураспад 30 с); пороги × доверие: 10 предупреждение (тост+звук), 20 throttle 15 с, 35 kick, 50 автобан аккаунта (5 мин × 2^страйк), 2-й автобан аккаунта → автобан его IP | мир `fraud.lua` + supervisor (`report`) |
| 10 | ложное срабатывание | оп снимает одной командой (`/fraud clear <игрок>`, `lab olife fraud clear`, кнопка панели): очки 0, автобаны аккаунта/его IP сняты, страйки 0, **доверие ×2** (пороги ×2, до ×8) | supervisor + мир |
| 11 | бан, который не видно | бан по IP — одна таблица `bans` (kind `ip`, адрес или CIDR, срок, причина): сервис билетов (`ip_banned`, «бан по IP до …»), шлюзы ещё до `Hello` (Disconnect 5 с причиной), выдача бана = немедленный kick сессий с IP (мир — сразу, шлюзы — `gw_sync` ≤ 2 с) | supervisor, мир, шлюзы |
| 12 | повтор билета / замена IP при живой сессии / смена ника в цикле | 15 (было) / `nick_in_use`+18 / `multi_account`+автобан | негативные ветки `tools/olife/fraud_check.py` |

**Исключения.** `exempt` (по умолчанию `127.0.0.1/32`: локальный игрок `lab play`, боты лаборатории) — для автоматики
п.4–8 (лимиты и автобаны), не для ручных банов. В проде — `lab olife fraud set exempt ""`.

## 2. Коды отказов
| где | код | когда | экран статуса клиента |
|---|---|---|---|
| сервис билетов | `ip_banned` | IP в активном бане (адрес/CIDR) | `[banned ip_banned] бан по IP <сеть> до <время>: <причина>` |
| сервис билетов | `rate_ip` / `rate_net` | ведро билетов IP / подсети пусто | `[antifraud rate_ip] …` |
| сервис билетов | `multi_account` | > N ников с IP за окно | `[antifraud multi_account] …` |
| сервис билетов | `sessions_ip` | живых сессий с IP ≥ лимита | `[antifraud sessions_ip] …` |
| сервис билетов | `nick_in_use` | ник в игре / в grace с другого IP | `[nick nick_in_use] …` |
| сервис билетов | `nick_similar` | скелет ника = чужой/зарезервированный | `[nick nick_similar] похож на «…»` |
| сервис билетов | `nick_reserved` (было: ник аккаунта с токеном) | + зарезервированное имя | `[ticket nick_reserved]` |
| шлюзы | `Disconnect 5` banned | бан по IP ещё до `Hello` / в сессии | `[banned 5] banned by IP …` |
| шлюзы | `Disconnect 13` limit | сессий с IP, соединений с /24 | `[refused 13]` |
| шлюзы | **`Disconnect 18` nick_in_use** (новый) | аккаунт уже в игре с другого IP | `[refused 18] ник уже в игре с другого адреса` |
| мир | `Notice 13` (новое событие) | предупреждение антифрода (код 22) | тост + звук `fx_throttle` |
| мир | `Notice 14` (новое событие) | throttle антифрода (код 22) | тост + звук |
| мир | kick 10 / ban 5 с причиной `antifraud: …` | порог kick / ban | как кик/бан оператора |
| мир (OpResult) | 22 | ответ `/fraud` с ошибкой супервизора | — |

Схема протокола не меняется (новые значения `Disconnect.code`/`Notice.event` — только в комментариях `client.yaml`).

## 3. Устройство
- **Источник правды — БД supervisor** (общая): `bans` (kind `ip`, value — адрес или CIDR в каноническом виде),
  настройки и доверие — `account_settings` (`_fraud:cfg`, `_fraud:trust`, `_fraud:strike`), события — кольцо в плагине +
  `artifacts/lab/olife/fraud_events.jsonl`, аудит — `fraud_audit.jsonl`. Логика — модуль плагина
  `tools/lab/projects/olife/olife_fraud.py` (горячая перезагрузка; ядро демона не меняется, кроме секции панели).
- **Возможности:** `olife.ip_check` (сервис билетов, вход по токену), `olife.auth_name` (вход по нику: +IP, ник, лимиты),
  `olife.gw_sync` (шлюзы раз в 2 с: сессии `[account, ip]` и события лимитов → баны с причиной/сроком, настройки, kick),
  `olife.fraud` (status|events|set|clear|trust|report|cfg|ipban|unban|bans), `olife.ban --ip` (CIDR, kick).
- **Шлюзы** (gateway_dev.py — эталон, Rust — прод): `gw_sync` вместо `GET /sup/bans` (запасной путь — он же); CIDR;
  проверка бана IP на accept; `sessions_per_ip`, ведро /24; `nick_in_use` 18; имя ASCII.
- **Мир** `content/olife_world/modules/fraud.lua`: события из точек отказа (чат 20, команды 9, блоки сверх ведра,
  запросы редактора/инструментов 9, спавн 52, переподключения), очки на аккаунт, пороги, Notice, throttle, kick, бан;
  настройки и доверие — `POST /call/olife.fraud {action: cfg}` раз в 5 с (`--opts sup=`); без супервизора — умолчания.
  `/fraud`, `/ban ip`, `/unban ip`, `/bans`, `/players` (IP: админ — полностью, игрок — `a.b.x.x`).

## 4. Проверка
Сценарии `olife_ipban` и `olife_antifraud` (vc и `--impl rs`), пробы — `tools/olife/fraud_check.py` с исходящих адресов
127.0.0.2–127.0.0.254 (Windows отдаёт весь 127/8 петле; сервер видит адрес источника — проверено). `127.0.0.1` и
`127.0.0.0/24` целиком не банятся никогда; экран статуса меню-клиента проверяется через TCP-проброс с исходящим адресом
127.0.0.x. После сценария баны, страйки, доверие и тестовые аккаунты снимаются.

## 5. Статус (16.10, сделано; подробно — `agents/OLIFE.md` «Антифрод и бан по IP»)
| мера | где реализовано | как проверено (F2F 0.32, vc и `--impl rs`) |
|---|---|---|
| бан по IP/CIDR, срок, причина; kick сразу | `olife_fraud.ipban` (+ F2F `kick_ip {nets, ban}` всем шлюзам), мир `/ban ip` (kick своих сессий) | `olife_ipban` 26/26 ×2: kick 0.15–0.2 с, `ip_banned` у билета (ник и токен), Disconnect 5 до Hello, CIDR /26 внутри/снаружи |
| экран статуса игрока | клиент `login.lua`/`status.lua` (виды `banned`, `nick`, `antifraud`, код 18) | меню через TCP-проброс с адреса 127.0.0.77: `[banned ip_banned] бан по IP … до …`; в игре — `[banned 5] бан по IP … до …` |
| ник: зарезервированные, похожие, ASCII, в игре/grace, мультиаккаунт | `olife_fraud.nick_precheck/nick_postcheck` (из `olife.auth_name`), шлюзы (имя ASCII, 18) | `olife_antifraud` шаг `olife_fraud_nick` 15/15 |
| частоты IP и /24, сессии с IP, соединения /24 у шлюза, автобан ×2 | `olife_fraud.ip_check/autoban_ip/gw_sync`, шлюзы `admit`/`sessions_per_ip` | шаг `olife_fraud_limits` 14/14: автобаны 60 с → 120 с |
| скоринг в игре, пороги, доверие | мир `fraud.lua` (+ `report`/`cfg` в супервизор) | шаг `olife_fraud_score` 15/15 |
| обход | — | шаг `olife_fraud_negative` 5/5 (15, 18, `multi_account` → `ip_banned`, `clear ip:`) |
Итого `olife_antifraud` 50/50 (vc и rs), `olife_ipban` 26/26 (vc и rs).

**Отличия от плана.** Адреса из `exempt` (127.0.0.1 — локальный игрок и боты лаборатории) в мире получают очки и
предупреждения, но **без** throttle/kick/автобана: иначе отрицательные тесты лаборатории (`editor_neg` нарочно упирается в
ведро запросов) сами себя глушили. Сессий с IP сверх лимита — отказ и событие (автобан — только через события шлюза ≥ 5 за
сводку). Живое (окна частот, привязки ников, присутствие) — в памяти демона: рестарт демона их обнуляет (баны, страйки,
доверие, настройки — в БД). Время в причине бана у Rust-шлюза — UTC (у gateway_dev.py — местное).
