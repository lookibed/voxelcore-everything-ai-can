# smollm — чат с языковой моделью Ru-Small-Instruct в VoxelCore

Языковая модель **Ru-Small-Instruct** (LongTime Devs, MIT; 94.4M параметров: LlamaForCausalLM, 12 слоёв, hidden 768,
12 голов / 4 KV-головы (GQA), контекст 512, словарь 24576, ByteLevel BPE) работает **внутри движка на Lua**: инференс на C по
`runq.c` из llama2.c, собран wasi-sdk в WebAssembly и оттранслирован Spider в Lua (`modules/smollm.lua`, 851 КБ), запускается
рантаймом `wasmrt`. Нативных библиотек, сети и GPU нет — только LuaJIT движка.

## Запуск
Меню «Сценарии» → `smollm`: страница чата. Поле внизу — сообщение, Enter или «Отправить»; модель печатает ответ по токенам,
строка статуса показывает фазу (загрузка весов, обработка промпта, генерация, готова), токенов/с, число токенов в контексте
из 512 и пометку «прогрев JIT» на первом ответе. «Стоп» прерывает генерацию (и обработку промпта), «Очистить» сбрасывает
контекст и ленту, «Назад» — в главное меню. Диалог многоходовый: реплики копятся в контексте, при переполнении 512 токенов
контекст сбрасывается (статус «контекст сброшен»).

Шаблон промпта — из README модели: `<|юзер|>\n{вопрос}\n<|юзерзакончил|>\n<|я_начал|>\n`, ответ заканчивается
`<|я_закончил|>`; BOS не добавляется (так делает HF-токенизатор модели). Между репликами вставляется `\n` (в README модели
многоходовый формат не описан — это допущение). Генерация детерминированная: temperature 0 (argmax); параметры
(`temperature`, `top_p`, `max_new` = 120) — в `modules/llm_host.lua` (`M.params`), сэмплер top-p есть, repetition penalty
из README модели не реализован.

Во время разработки — прямой запуск при старте: `tools/scenarios/smollm_chat.lua` (см. `tools/scenarios/README.md`),
проверка в лаборатории — `tools/scenarios/smollm_check.py`.

## Как это устроено
- Веса читаются обычным `fopen`/`fread` через WASI кусками по 4 МБ в линейную память модуля (табличная память Spider:
  32-битные слова в таблице Lua). Загрузка в движке — **0.7 с**.
- Модель main: `_start` в корутине; wasmrt даёт программе кванты по 12 мс за тик (точки уступки Spider в циклах), поэтому
  кадр не зависает, а статус и текст обновляются между квантами. Промпт попадает в программу через `vc.llm_poll`, каждый
  токен ответа — `vc.llm_token` (в лог `[smollm] gen <id> pos <p>`) и текст `vc.llm_emit` (с буфером неполных символов UTF-8).
- Матвек: веса читаются словами по 4 int8 (`MATMUL=1` в `build.sh`) — так в Lua одна загрузка слова вместо четырёх побайтовых;
  результат бит в бит с `runq.c` (целочисленные суммы групп те же).

Как сделано:
- **Ядра хоста** (`modules/llm_kernels.lua`, импорты `vc.llm_matmul` / `vc.llm_attention`, C зовёт их из `k_matvec_q8` /
  `k_matmul_q8` / `k_attention`, при отказе (`0`) считает сам): цикл прямо по словам табличной памяти модуля
  (`memory[1].__w`, 4 int8 в слове), группа из 64 весов развёрнута (код ядра генерируется строкой и `loadstring`), сумма группы
  в double точна, а три операции над float на группу (`ival*ws`, `*xs`, `val+`) округляются до binary32 (Veltkamp) — так же, как
  в C, поэтому результат бит в бит. Матвек — **1.14–1.18 GMAC/с** в стоковом LuaJIT против 0.12 у трансляции (шаг 1).
- **Батч prefill**: `model_forward_batch` в C (слой за слоем для 16 токенов, порядок операций над float на токен тот же);
  ядро пар кладёт два токена в одно число `x_a + x_b·2^21` (сумма группы < 2^20, итог < 2^42 — точен), слово весов
  разбирается один раз на 16 токенов: матвек prefill 64 → 27–32 мс/токен (2.4 GMAC/с). Логиты считаются только у последнего
  токена промпта (раньше — у каждого, это и есть 155 → 1 мс в таблице).
- **Внимание**: кэш K/V слоя декодируется в числа Lua один раз на строку (ключ — адрес кэша; строки ≥ pos считаются
  переписанными, так переживается сброс контекста), `fm_exp` из `fmath.c` повторён на Lua теми же операциями (биты те же).
- Кадр не блокируется: ядра уступают квант через `ctx.slice_yield` (новое поле `ctx` в wasmrt) примерно каждые 256 К MAC.
- Переключатели для замеров: `export:smollm_kernels.txt` (`c`/`lua`), `export:smollm_batch.txt` (N), в `smollm_check.py`
  — `--kernels`, `--batch`, `--kprof`.

## Ограничения
- ~9 токенов/с генерации и ~45 мс на токен промпта (11.10; до этого ~1 токен/с и ~0.9 с на токен промпта).
- Ручные ядра работают только с табличной памятью Spider (`--memory table`); с `bytearray` ядро отказывается и считает C.
- Нет repetition penalty и сэмплирования по умолчанию (детерминированный argmax, чтобы ответ воспроизводился и проверялся).
- Текст ленты — моноширинный шрифт движка, без увеличения; длинное тире модели показывается как «-» (в шрифте нет глифа).
- Контекст сбрасывается целиком при переполнении 512 токенов (без скользящего окна).

## Диалог и семплирование (11.10, главная сессия) — сверка с карточкой модели
Карточка: https://huggingface.co/longtimedevs/Ru-Small-Instruct (LongTime Devs, MIT; `config.json` там совпадает с нашим —
12 слоёв, 768, vocab 24576; таблица в README карточки с «16 слоёв / 896 / 28 672» не совпадает с её же `config.json`).
Что в карточке и что теперь делает пак:
- **Шаблон** одноходовый: `<|юзер|>\n{q}\n<|юзерзакончил|>\n<|я_начал|>\n`, конец — `<|я_закончил|>` (id 7), BOS не
  добавляется — у нас так и было. Формата многоходового диалога в карточке нет; с накопленной историей модель (и нативный
  эталон, не только пак) съезжает на предыдущую тему или копирует прошлый ответ (после «Кто такой слон?» на «А кто такой кит?»
  отвечает про слонов; «2+1 → 3», затем на любой пример «3»). Поэтому **по умолчанию контекст сбрасывается перед каждым
  вопросом** (лента остаётся), флажок «помнить диалог» на панели включает прежнее поведение.
- **Семплирование по карточке**: temperature 0.25, top_p 0.85, repetition_penalty 1.15, max_new 120 — теперь умолчания пака
  (раньше temperature 0 без штрафа — отсюда зацикливания вида «с хоботом и пушистым хоботом»). Штраф за повторы — HF-семантика
  по всем токенам текущего контекста (`main_vc.c`, param 7). Паритет лаборатории по-прежнему при `0 0.85 1 120`
  (`export:smollm_params.txt`, пишет `smollm_check.py`): логиты бит в бит, токены = эталон (v031 `20261011_233412_…`, v032
  `…233421_…`).
- Прогон диалога: `python3 tools/scenarios/smollm_dialog.py v031 [--remember] [--params "t top_p rep max_new"] -- "вопрос" …`
  (11.10, умолчания пака, без истории: слон → «…с хоботом и пушистым хвостом», кит → ответ не про слонов; с `--remember`
  второй ответ снова про слонов — `20261011_233152_…` и `…233212_…`).
- Арифметику и факты модель не знает (94M): «7-1» → «7-1», «кит» → «млекопитающее семейства псовых» — это её потолок,
  не ошибка инференса.
