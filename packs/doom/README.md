# DOOM для VoxelCore

DOOM ([doomgeneric](https://github.com/ozkl/doomgeneric)), собранный из C в WebAssembly и
оттранслированный в чистый Lua транслятором Spider. Работает в обычном окружении VoxelCore,
без нативных библиотек. В комплекте первый эпизод Shareware-версии (`doom1.wad`).

## Запуск

Меню «Сценарии» → `doom`, выберите WAD и нажмите **Start**.

| Клавиша | Действие |
|---|---|
| W/S, ↑/↓ | вперёд / назад |
| ←/→ | поворот |
| A / D | шаг влево / вправо |

## Свои WAD-файлы

Положите IWAD в папку

```
<папка VoxelCore>/config/doom/wads/
```

Имя файла должно быть стандартным: по нему DOOM определяет игру. Подходят `doom.wad`,
`doom2.wad`, `plutonia.wad` или `tnt.wad`. Файлы появятся в списке с пометкой `[config]`.

## Ограничения

- Нет звука и музыки.
- Сохранения не работают, настройки не запоминаются между запусками (записывать файлы некуда).
- Нет мыши.
- Выход через меню DOOM (Quit Game) завершает сессию; снова запустить можно кнопкой **Start**.

По умолчанию лок частоты выключен (**35 fps lock: OFF**): у этого порта один кадр равен
одному игровому тику, поэтому без лока ускоряется и сама игра, а счётчик fps показывает предел
машины. Кнопкой **35 fps lock** включается родная частота DOOM — 35 тиков/с. На слабых машинах в тяжёлых
сценах кадров может быть меньше, игровая логика при этом не замедляется. Счётчик fps
показан сверху.

## Кнопка JIT tuning

Кнопка **JIT tuning** (по умолчанию ON) на время работы страницы настраивает LuaJIT под
оттранслированный код: увеличивает кеш трасс (`maxtrace=8000`, `maxmcode=65536`) и отключает
loop-оптимизацию (`-loop`). Модулям Spider нужно несколько тысяч трасс, а стандартный кеш
вмещает 1000; при переполнении LuaJIT сбрасывает всё скомпилированное и компилирует заново.
С настройкой декодер видео и Doom работают в 3.5–5 раз быстрее, эмулятор — в 3–4 раза.
Настройка глобальная для движка, поэтому при выходе со страницы возвращаются значения по умолчанию.

## Запуск через wasmrt

Тот же DOOM как обычная C-программа на общем рантайме `wasmrt`: модуль
`modules/doom/doom_wasmrt.lua`, манифест `wasm.json` (игра) и `wasm_timedemo.json` (бенчмарк).
Никакой своей обвязки: WAD открывается обычным `fopen` через WASI из каталога `wads`, кадр
отдаётся `vc_gfx_present`, клавиши опрашиваются `vc_key_down`. Запуск в меню —
`require("wasmrt:app").set_pending("doom:wasm.json")` и `menu.page = "wasmrt_app"`
(см. README пака wasmrt).

## VoxelCore 0.32.1 (порт 06–07.10)
Без правок пака. На тестовой сборке 0.32 (res 0.32.1, окно 854×480, realtime): страница `doom` (свой хост) — 144 fps без лока,
`doom:wasm.json` через wasmrt — 69.1 fps (в игре один кадр на тик движка, как в 0.31), `doom:wasm_timedemo.json` —
`timed 5026 gametics in 872 realtics (201.7 fps)`, окна по 5 с 158 → 188 → 205 → 229 fps (прогрев JIT; ПК был занят другими
задачами, замер `contended`; 0.31: 221–224). На экране компьютера `pc_wasmrt:pc` в мире fineltest — 69.0 fps (0.31: 56–69).
