# gpu_compute — «compute-шейдер» для паков на стоковом VoxelCore (0.31 / 0.32)

Библиотека-пак: общее из двух рабочих вычислителей на GPU — генерации чанков (`gpu_worldgen`) и инференса LLM
(`smollm_gpu`) — и **один общий `shaders/ui.glslf` на мир**, в котором живут программы всех паков-клиентов. До пака
каждый клиент подменял `ui.glslf` своим, и вместе они не включались (движок берёт файл одного пака). Движок не
менялся: проходы — фреймы `gui.create_frame` (рисуются в текстуру каждый кадр), буферы — canvas-текстуры, чтение —
`assets.to_canvas`. Дизайн и отклонения от него — `agents/research/COMPUTE_API.md`.

Клиенты сейчас: `gpu_worldgen` (программа `gpu_worldgen`, маркер `#FE03FF80`), `smollm_gpu` (программа `smollm_gpu`,
маркеры `#FF<режим>FF80`), пример пака `examples/noise` (программа `noise`, `#FD04FF80`) и служебная `core`
(`#FD01..03FF80`: COPY / INC / ECHO для пробы порядка фреймов). **Оба клиента работают в одном мире** — проверка
`tools/scenarios/gpu_compute_both.py` (ниже).

## Как клиент добавляет программу
1. Тело программы — файл `content/<пак>/shaders/gpu_<имя>.glsl`; первая строка — директива
   `// @gc program=<имя> marker=<банк R, hex> codes=<auto|N|A-B>`, в теле — функция `void gc_main_<имя>(int code)`
   (пишет `f_color` или `discard`; доступны `a_textureCoord`, `a_color`, `u_texture`, `gl_FragCoord`). Своего
   `ui.glslf` у клиента нет; `#extension` из тела поднимается в заголовок общего шейдера.
2. `python3 tools/gpu_compute_build.py` — собирает `content/gpu_compute/shaders/ui.glslf` (тела всех `gpu_*.glsl`
   установленных паков + диспетчер по цвету картинки) и реестр `data/programs.json` (банк, коды, пак, sha1 тела);
   проверяет коллизии маркеров и синтаксис (glslangValidator). `--check` — только сверить, что собранное актуально
   (код 1, если нет); `--exclude a,b` — собрать без программ/паков (замеры A/B).
3. В пак-клиенте `"dependencies": ["gpu_compute"]`; в Lua — `gc.program("<имя>")` (ошибка с подсказкой, если программа
   не собрана) и проходы через API ниже.

**Почему сборка заранее, а не в Lua при загрузке мира** (как предлагал дизайн): движок читает `shaders/ui.glslf` один раз
при загрузке ассетов (берётся файл последнего пака в списке, у кого он есть), Lua-API загрузки/перезагрузки шейдера в
0.31 и 0.32 нет, а каталог пака из Lua не пишется. Проверено в движке сценарием `gpu_compute_check.lua` (обе версии):
`lua shader api: none` (поиск `*shader*` в `assets`, `gfx`, `gui`, `app`, `core`), `pack dir writeable:
is_writeable=false, write=false`. Значит, общий шейдер — артефакт сборки, который лежит в паке и пересобирается при
добавлении клиента (как `generated/` у wasmrt).

Маркер картинки: цвет `#RRGGBB80` с B = 255, A = 128 — вызов программы, R — банк, G — код. Банки: `FD` — программы
gpu_compute и новые клиенты (`codes=auto` раздаёт коды по порядку), `FE` — gpu_worldgen, `FF` — smollm_gpu (прежние
маркеры клиентов сохранены). Обычная картинка рисуется как в движке (`a_color * texture`), UI не ломается.

## API (Lua, `require "gpu_compute:compute"`)
```lua
local gc = require "gpu_compute:compute"
local prog = gc.program("noise")                                   -- из data/programs.json: bank, g0..g1, marker(code)
local prm  = gc.params{ id = "my_params", words = 256 }            -- слова u32 (prm:set(i, v), prm:setf(i, f32))
local buf  = gc.buffer{ id = "my_buf", width = 768, bytes = ba }   -- RGBA8-текстура из Bytearray/строки (4 байта на тексель)
local pg   = gc.page{ id = "my_page", width = 768, parts = { {name="w", bytes=ba}, {name="x", rows=1} } } -- склейка в одну текстуру
local pass = gc.pass{ id = "my_out", program = prog, width = 256, height = 256, input = prm }  -- фрейм = выход W x H
local serial = gc.submit(pass, prm, { [1] = 5, [2] = { f = 0.03125 } })  -- слово 0 = serial, update(), картинка видна
local data, info = gc.read(pass, { serial_texel = 256 * 256 - 1 })      -- кадр submit: nil "same_frame"; со следующего — Bytearray RGBA
gc.idle(pass)                                                      -- скрыть картинки: GPU не считает проход каждый кадр
local ch = gc.chain{ id = "sgf", n = 418, ticks = ticks }          -- n фреймов в порядке отрисовки (проба, кеш)
local root, doc = gc.frame(ch.ids[k], w, h)                        -- k-й фрейм цепочки нужного размера (рисуется k-м)
gc.limits()   -- { max_pass_w, max_pass_h } = окно, inputs = 1, out = "rgb8" (3 байта на тексель), max_texture = 32768
gc.codec      -- u32_bytes, f32_bits/bits_f32, rgb_to_f32/f32_to_rgb (float = 2 текселя), u24_at, i8x3, u16, raw
gc.budget{ ms_per_frame = 6, fps_floor = 50 }  -- b:begin(), b:allow(ms) — сколько проходов/чтений пускать за кадр
```
В шейдере программы: `gc_word(i)` / `gc_wordf(i)` — слово параметров (из `gpu_core.glsl`), `gc_rgb24(v)` — выход u24.
`gc.read(pass, { sync = true })` читает сразу (ждёт GPU; так argmax у smollm_gpu), по умолчанию — конвейер N/N+1
(так gpu_worldgen: эхо serial в текселе подтверждает, что прочитан этот пакет).

## Цена общего шейдера (регистры)
Один фрагментный шейдер = одно число регистров на все программы (максимум по ветвям), поэтому тяжёлая программа
замедляет соседей, даже если её ветка не исполняется. Замер smollm_gpu (`smollm_gpu_check.py v032`, промпт 1, 12.10):

| общий ui.glslf | ток/с (декод) | prefill мс/токен |
|---|---|---|
| без тела worldgen (`--exclude gpu_worldgen`) | 38.6 (42.2) | 23.0 |
| worldgen как был (параметры пресета массивом `g_p[44]`, bool-массивы, пресет — переменная) | 31.4 (34.3) | 28.7 |
| + параметры через `GP(i)` (чтение текстуры) | 33.6 (36.7) | 26.6 |
| + маски вместо `bool T[10], C[10], s[9]` | 34.3 (37.4) | 26.7 |
| + вызов пресета с константой (`gw_preset_main(1|2|3, …)`) — **текущий** | 35.3–36.8 (38.5–40.1) | 24.6–25.2 |
| (опыт) без islands / без mountains | 38.0 (41.5) / 36.9 (40.2) | 24.1 / 24.8 |
| (опыт) циклы пресетов без развёртки | 35.9–36.0 (39.1–39.3) | 24.8–25.0 |

Остаток ~2 ток/с (5%) — пресет islands (3 слоя островов: 15 значений столба живут через весь пиксель). Хэши пресетов
после правок те же (`47a776dd` / `8589c44b` / `d1b78513`, 12.10 02:23), GPU-цена чанка mountains/caves упала
0.087 → 0.054 и 0.070 → 0.042 мс (тело LLM с fp64 в том же шейдере тоже давит на worldgen). Правило для клиентов:
не держать в программе большие массивы и параметры в регистрах, ветки со специализацией по константе.

## Ограничения движка (что API честно показывает)
- проход не больше окна (`Frame::draw` ставит фрейм проекцией главного окна) — `gc.limits()`;
- одна входная текстура на картинку (`u_texture`) — несколько буферов склеиваются в страницу `gc.page`;
- выход RGBA8 со смешиванием SRC_ALPHA: данные только в RGB (float = 2 текселя, int8 ×3 на тексель);
- все фреймы рисуются каждый кадр в порядке хеш-таблицы движка — цепочкам нужен `gc.chain` (проба, кеш
  `config:gpu_compute_order.json`), простаивающие проходы скрывать `gc.idle`;
- один `ui.glslf` на мир: программы собираются заранее (`tools/gpu_compute_build.py`), регистры общие (см. выше).
Чего не хватает в апстриме — `agents/research/COMPUTE_API.md` «Что остаётся движку».
