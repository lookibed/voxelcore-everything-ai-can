# Half-Life (wasmrt)

Half-Life 1 на движке **Xash3D FWGS** (открытая GoldSrc-совместимая реализация, GPL-3) с игровым кодом
**hlsdk-portable** (лицензия Half-Life 1 SDK) как обычная C/C++-программа: собрано wasi-sdk в один
WebAssembly-модуль (движок + рендер `ref_soft` + `filesystem_stdio` + серверная `hl` и клиентская `client`
«DLL» статически), оттранслировано Spider в Lua (`lua-no-ffi`, `--f32 number`) и запущено паком `wasmrt`.
Данные — бесплатная демо Valve **Half-Life: Uplink** (1999), карта `hldemo1` (лицензии — `LICENSES/README.txt`;
`data/` в git-репозитории не кладётся, как `*.wad` Doom и `*.pak` Quake).

Состояние (12.10): **854×480 — 18–22 fps** в мире (было 8.8; разгон hl_gpu 04:30, см. «Замеры»); карта `hldemo1` грузится за ~5 с и играется — ход (F2F `W` проверен кадрами), взгляд мышью
с захватом курсора, HUD, титры, NPC и физика сервера; программный рендер `ref_soft` в кадр **854×480**
(родное разрешение по умолчанию). Показ — новый импорт wasmrt `vc_gfx_present_rgb16`: 16-битный кадр
`ref_soft` уходит в текстуру как есть (2 пикселя в тексель), цвет считает шейдер UI на GPU (как палитра Quake),
32-битного blit на CPU нет (`"env": {"HL_PRESENT": "rgba"}` — старый путь `vc_gfx_present`). Не собраны: звук
(SNDDMA — заглушка), меню Xash (mainui) и VGUI клиента (`src/hl_client_novgui.cpp` — заглушки), сеть (только
loopback), видео AVI. Игра стартует сразу с карты.

## Манифесты и кнопка «Рендер»

| манифест | внутреннее разрешение | назначение |
|---|---|---|
| `wasm.json` | 854×480 (как выход) | по умолчанию; меню «Сценарии» → `halflife` |
| `wasm_640.json` | 640×360 | явный выбор меньшего разрешения (картинка 1:1 в центре страницы) |
| `wasm_480.json` | 480×270 | то же, ещё меньше |
| `wasm_profile.json` | 854×480 | + `"profile": true` (профиль стека wasmrt в лог) |
| `wasm_dev.json` | 854×480 | `-dev 2`: подробный лог Xash (и строки уведомлений на экране) |

Кнопка **«Рендер: WxH»** на странице (расширение `modules/hl_host.lua`, импорт `vc.hl_resolution`) переключает
внутреннее разрешение по кругу 854×480 → 640×360 → 480×270 сразу в запущенной игре (cvar `width/height` +
`host.renderinfo_changed` → `VID_SetMode` → `ref_soft` пересоздаёт буфер); выбор хранится в
`config:halflife/resolution.txt` и перекрывает манифест. По умолчанию — родные 854×480; меньшее — только явно.
В игре курсор захвачен: кнопку нажимать во время загрузки карты или из консоли Xash (Esc в этой сборке
открывает/закрывает консоль вместо отсутствующего меню; через F2F `input` Esc до программы не дошёл — проверено
только нажатие кнопки до входа в карту, `halflife_check.py --button`).

Во всех манифестах `"slice_ms": 50` (квант программы за тик движка). Аргументы Xash: `-ref soft -width W -height H
+exec default.cfg +mlook +map hldemo1` (`valve.rc` Uplink не выполняет `default.cfg` — без него нет привязок
клавиш). `"cache_files": true` — новое поле wasmrt: WASI держит прочитанные файлы пака в памяти (Xash открывает
`pak0.pak` 79 МБ заново на каждый файл внутри).

## Управление

Привязки `default.cfg` Uplink: W/S/A/D и стрелки — ход/поворот, мышь — взгляд (`+mlook`; курсор захвачен, пока
идёт игра: `cls.key_dest == key_game` и `ca_active`), ЛКМ/Enter — огонь, Space — прыжок, Ctrl — присесть,
Tab — использовать, 1–5 — оружие, F — фонарик, Esc — консоль Xash (в консоли курсор отпускается).

Итог против цели 10–18 fps (до 03:25): **854×480 — 8.8–9.2 в установившемся режиме (ниже цели), 640×360 — 10.5–11.2,

**После разгона hl_gpu (04:30): 854×480 — 18.3 fps на свободном ПК (18.8–21.7 в других прогонах, разброс между
запусками ±1.5), 640×360 — 22.5.** Картинка та же: хэши всех 845 кадров вне движка (`run_luajit.lua 845`,
виртуальные часы) совпадают со сборкой до правок на каждом шаге. Главное — не сами спаны, а то, что ~50% кадра
LuaJIT исполнял **интерпретатором** (`luajit -jp=vF`: «Interpreted 49–57%»): горячие функции рендера
(`R_ClipEdge`, `R_RecursiveClipBPoly`, `TriVertex3f`, `R_SetupFinalVert`, `TransformVector`) не становятся трассами
(рекурсия, внутренние циклы вызываемых функций → «loop unroll limit», «inner loop in root trace», чёрный список), и
каждая операция float в них — вызов помощника Spider (`rt_multiply_f32` → `round_f32`, `rt_load_f32` →
`buffer_read_i32` + `from_bits_f32`). Поэтому дало больше всего то, что дешевле в интерпретаторе.

Что сделано (hl_gpu, 12.10; каждый шаг — A/B в движке и хэши кадров вне движка):
- **Ядра спанов на Lua** (`modules/hl_kernels.lua`, импорт `vc.hl_spans(mode, pspan, params)` из `r_scan.c`, как
  `matvec` smollm): `D_DrawSpans16` (0), `D_AddSpans16` (1, луч света у старта), `D_DrawZSpans` (2) целиком — список
  спанов, перспектива через 8 пикселей с округлением каждой операции до binary32 (`rnd`), пары пикселей словом;
  прямо по `memory[1].__w`. Вне движка: вступление 50 → 12 мс/кадр, мир 142 → 92 мс; в движке 7.9 → 11.8 fps.
  `"env": {"HL_SPAN_KERNEL": "0"}` в манифесте — старые циклы C (A/B).
- **Studio-модели в два прохода** (`r_studio.c` `R_StudioDrawNormalMesh` + `r_triapi.c`
  `VC_TriVertexStore/Replay`): сначала цвет/текстура/преобразование всех вершин полосы (цикл без внутренних
  циклов — становится трассой), потом треугольники в том же порядке. `TriTexCoord2f` — `fmod` через точное
  частное в double вместо `fmodf` libc (проверено на 362 млн float — 0 расхождений). Вне движка мир −21%.
- **`tools/f32_inline.py`** (шаг `build.sh` после Spider, `HL_F32_INLINE=0` — выключить): в помощниках f32
  `+ - * /` округление нормального диапазона прямо в функции, `rt_load_f32`/`rt_store_f32` — доступ к слову и
  перевод битов в одной функции (быстрый путь для выровненного адреса), то же для `rt_store_i32`, `rt_load_i32_from_u16/u8`,
  `rt_saturate_f32_to_s32`. Те же результаты бит в бит; в интерпретаторе на 1–2 вызова меньше на операцию.
  В движке 14.8 → 17.4 → ~21 fps.
- **`"jit_opt": ["maxtrace=40000", "maxmcode=262144"]`** во всех манифестах: на ~60-й секунде число трасс
  переходило 8000 (`JIT_TUNED`), LuaJIT сбрасывал все трассы — fps падал с 22 до 12 (`"jit_stat": true` в манифесте —
  строка `halflife: jit traces started N, flushes F, aborts A` раз в 5 с, `modules/hl_host.lua`).
- Пробовал без эффекта (вне движка, в пределах шума): параметры JIT `loopunroll/instunroll/maxrecord/recunroll/
  callunroll/hotexit`; отложенная вставка рёбер в `R_EmitEdge` (цикл сортировки вне пути `R_ClipEdge`) — функции
  остались интерпретируемыми; `R_RecursiveClipBPoly` без рекурсии (явный стек) — тоже; «быстрый» `into_bits_f32`
  без деления (в трассе одинаково, 13 нс/вызов). Эти правки откатаны.
- GPU-растеризация (мир/модели через `gfx_tris`) не начата: при 18–22 fps на CPU она уже не нужна для цели 10–18,
  остаётся путём к 30+ fps (план ниже).

Профиль после разгона (вне движка, мир, кадры 760–845, `-jp=GF`, по включению): рендер 84% — studio 27%,
brush-модели (`R_DrawSolidClippedSubmodelPolygons` → `R_RecursiveClipBPoly` → `R_RenderBmodelFace`) 26%,
`R_ScanEdges` 16% (из них ядро спанов 7–8%), `R_RenderWorld`/`R_ClipEdge` 12–17%; сервер 6%.

Что дало скорость:
- `--f32 number` (Spider: f32 — число Lua, без перевода в биты на каждой операции): в LuaJIT вне движка 40 кадров
  6.5 с → 1.4 с, в движке 6.7 → 10.1 fps (640×360). Трассы рвались в хелперах `into_bits_f32`/`from_bits_f32`
  («loop unroll limit», «register coalescing too complex», `luajit -jv`).
- кадр `pixel_t` 16 бит → текстура, цвет на GPU (`vc_gfx_present_rgb16`): нет 32-битного blit (`R_BlitScreen`
  ~12% кадра в профиле) и вдвое меньше копирования (present 2.1–2.9 мс/кадр при 854×480).
- `D_DrawSpans16` (WASI): пары пикселей одной 32-битной записью (16-битная запись в памяти Spider — чтение+запись
  слова), строка текстуры шагом с переносом дробной части вместо `(t >> 16) * cachewidth` на каждый пиксель.
- `"slice_ms": 50`, `-O3` — в пределах разброса.
- Проверено без эффекта: `jit_opt ["+loop"]` (8.2), `spider-cli -o` (в пределах шума), снятие точек уступки из
  внутренних циклов растеризатора (в пределах шума).

Корректность: вне движка (`run_luajit.lua`, виртуальные часы) хэши кадров 1–845 совпадают между сборками
«f32 bits» / `--f32 number` (кроме одного кадра загрузки, 12-го), между путём blit RGBA и rgb16 (формула шейдера
сверена со всеми 65536 значениями таблицы `R_BuildScreenMap`) и после правок `D_DrawSpans16`. После ~845-го кадра
кадры расходятся и между двумя запусками одной сборки — игра берёт случайные числа от реального времени.

Профиль кадра в мире (854×480; `luajit -jp=GF` вне движка на реальных часах, кадры 300–500, по включению):
`R_RenderScene` 62% (`R_ScanEdges` 34%, из них `D_DrawSpans16` 20%; модели studio `R_StudioDrawPoints` +
TriAPI на каждую вершину 13%; brush-модели 6%; обход BSP 5%), сервер `Host_ServerFrame` 20% (физика, `PM_PlayerMove`,
дельты сообщений), предсказание клиента 6%. В профиле wasmrt (точки уступки, в движке) ещё видны `D_AddSpans16`
(аддитивный «луч света» у старта, 13%) и `R_RecursiveClipBPoly` (10%). Постоянная часть кадра (не зависящая от
разрешения) — ~70 мс из ~110 мс при 854×480.

## Что не сделано / как продолжить

- **GPU-растеризация** (цель «рендер на GPU»): сделан только перевод цвета на GPU. Дальше — как Eaglercraft
  (`graphics: "tris"`): свой ref (`ref_vc`) по образцу `ref_gl` (GL 1.x: `glBegin`/`glVertex`, лайтмапы вторым
  проходом) поверх эмуляции GL, которая отдаёт треугольники и текстуры `gfx_tris.lua` (атлас 2048², до 32768
  треугольников, шейдер `ui.glslf`; умножение на лайтмапу — режим смешивания `mul`). Это снимет `R_ScanEdges`,
  studio и спаны (~60% кадра). Промежуточный вариант — studio-модели через `tris` поверх кадра ref_soft.
- CPU (после hl_gpu): оставшиеся интерпретируемые горячие функции — `R_ClipEdge`/`R_EmitEdge`,
  `R_RecursiveClipBPoly`/`R_RenderBmodelFace`, `R_StudioDrawPoints`: следующий шаг — ядра на Lua, как спаны, или
  инлайн вызовов-помощников в местах вызова (Spider: сравнения/арифметика i32 тоже вызовы); кэш отсечения
  неподвижных brush-моделей; сервер (`SV_Physics`, дельты) — общий для всех.
- Звук (`SNDDMA_*` поверх `vc_audio_*`), меню mainui (C++, статически как `menu`), VGUI клиента (freevgui),
  сохранения (WASI пишет в память — нужен вывод в `config:`), проверка Esc/консоли живой клавиатурой.

## Сборка

Spider, `tests/manual/real-world-halflife/` (`build.sh` → `build.py`: инкрементальная параллельная сборка
wasi-sdk ~400 файлов C/C++ в `obj/`; `tools/wasm_localize.py` делает символы каждой «DLL» локальными после
`wasm-ld -r` — вместо `ld -r` + `objcopy -G` статической сборки Xash, которых для wasm нет; таблицы экспорта
`src/gen/*_exports.c` — по `llvm-nm`, в т.ч. 336 функций-классов сущностей сервера). Хост — `src/vc_platform.c`
(видео/ввод/время на `vc.h`, кнопка разрешения, заглушки звука, AVI, HTTP, голоса), `src/compat/` (setjmp,
bzip2/MultiEmulator/pwd заглушки, `platform.h` с `XASH_VC`, сокеты-заглушки). Правки upstream —
`patches/xash3d-fwgs.patch` (`filesystem/sys.c`: без `dup` на WASI; `ref/soft/r_glblit.c`: альфа и путь rgb16;
`ref/soft/r_scan.c`: спаны, вызов ядер `vc.hl_spans`; `r_studio.c`/`r_triapi.c`/`r_local.h`: studio в два прохода,
`TriTexCoord2f` без `fmodf`). Размеры: wasm 3.07 МБ, Lua 34.1 МБ (`--f32 number --memory-helpers notail
--yield-every 20000`, затем `tools/f32_inline.py`). Раскладка: `<Spider>/Hosts/VoxelCore/pipeline/deploy.sh halflife`. Вне движка:
`luajit run_luajit.lua N` (хэши кадров; `HL_DUMP=x.ppm`, `HL_REALTIME=1`, `HL_PROF=from,to,file`,
`HL_PROF_MODE=vF` — доля интерпретатора; JIT как `JIT_TUNED` wasmrt, `HL_JIT=default` — стоковый, `HL_JIT=opt,..` —
добавить; `HL_JITSTAT=1` — счётчики трасс; ядра спанов берутся из пака, `HL_PACK=<каталог пака>`). Без `JIT_TUNED`
(maxtrace 1000) вне движка мир шёл ~300 мс/кадр — сравнивать только с ним.

Запуск при разработке — аренда `tools/lab/lab lease wasmrt engine_rt --param manifest=halflife:wasm.json
--param packs=wasmrt,halflife --start` или `tools/scenarios/halflife_check.py`.
