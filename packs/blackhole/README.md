# blackhole — чёрная дыра на максималках (VoxelCore 0.32.1, стоковый движок)

Пак `blackhole` (creator Andryha, зависимость `base`). Движок не менялся: всё — Lua, пост-эффект GLSL, ассеты пака.
Волна 1 — граната, дыра, обломки, звук, пост-эффект-линза; **волна 2 (15.10)** — сверхмассивные дыры через слияния,
процедурный диск и преломление трассировкой луча в пост-эффекте, схлопыватель, instant-спавн с импульсом, движение по
инерции, ударная граната, мягкое слияние, быстрое стирание блоков фрагментами.

Сущности снарядов называются `*_thrown`: в 0.32 имена предметов и сущностей — одно пространство (`load_content` падает
«name blackhole:grenade is already used»).

## Как играть
- «Black hole grenade» → ПКМ: граната летит по взгляду камеры (скорость 15 + половина скорости игрока), прыгает по полу и
  от стен, тикает ~2.5 с, затем рождается дыра.
- «Black hole impact grenade» → ПКМ: без отскоков; первое касание пола (`on_grounded`), стены (горизонтальная скорость упала
  больше чем на 85 % за шаг физики) или сущности (ближе 0.7; бросивший игрок первые 0.3 с не считается) — сразу дыра.
- «Black hole collapser» → ПКМ: снаряд (скорость 22); попал в горизонт дыры (расстояние до центра < горизонт + 0.6) —
  её коллапс немедленно (проверяют и снаряд в `on_physics_update`, и сама дыра в своём такте).
- «Black hole (instant)» → простой ПКМ (`on_use`, без блока под прицелом; по блоку — то же): дыра в 3 блоках перед глазами со
  скоростью `1.2 · |player.get_vel| · player.get_dir` — на бегу дыра улетает вперёд и тормозит (см. «Движение дыры»).
- Из сценария/другого пака: `local blackhole = require "blackhole:api"`; `blackhole.spawn({x, y, z}, mass, vel, axis)` → uid,
  `blackhole.throw(pos, vel, fuse, kind)` (`kind` — `grenade_thrown` | `impact_thrown` | `collapser_thrown`),
  `blackhole.state(uid)` → таблица дыры (`mass`, `vel`, `phase`, `center`, `path`, `rings`, `eaten_blocks`, …), `blackhole.all()`.

## Устройство дыры (`scripts/components/hole.lua`)
Тело `static`: позицию задаёт только `transform` (kinematic в 0.32 падает под гравитацией — LESSONS «волна 4a»).
Фазы: **birth** (1 с: видимый масштаб 0 → 1, поедание с темпом 0.4) → **feed** → **collapse** (2 с) → удаление;
**merging** — меньшая дыра втекает в большую. Коллапс — когда `mass ≥ max_mass`, возраст `≥ L(m)` или попал схлопыватель.

### Масса → радиусы и время (`modules/core.lua`)
- радиус всасывания блоков `R(m) = min(max_radius, 2 + 8 · cbrt((m − 1) / 1500))`, `max_radius = 32` (было 10):
  кубический корень — съеденный объём ~ R³ ~ масса, воронка растёт, как шар из съеденного: R(1) = 2, R(1500) = 10,
  R(12000) = 18, R(80000) = 32 (строка `w2 formulas` в логе);
- горизонт (тень пост-эффекта) `rh(m) = 0.6 + 0.17 · R(m)` — 0.94 … 6.04 блока;
- радиус притяжения сущностей и игрока `Rp(m) = 1.8 · R(m) + 4`;
- темп поедания `rate(m) = min(max_rate, 14 + 0.1 · m) · power` блоков/с, `max_rate = 1500`;
- **время самосхлопывания** `L(m) = lifetime · (1 + ln(1 + m / lifetime_mass_scale))`, `lifetime = 90`,
  `lifetime_mass_scale = 500`: 90 с при m ≈ 1, 161 с при 600, 215 с при 1500, 345 с при 8000 — чем массивнее, тем дольше
  живёт (логарифм: сверхмассивная не становится вечной); коллапс также при `m ≥ max_mass` (50000);
- масса: +1 за проглоченный обломок или блок, +4 за чужую сущность, +1 за украденный обломок, при слиянии — сумма.

### Движение дыры
Тело `static` (kinematic в 0.32 падает), позицию ведёт сам компонент: импульс `p = m · v`, гравитации на дыру нет.
- **Съеденное покоится**: `add_mass(dm)` сохраняет импульс — `v ← v · m / (m + dm)`; при слиянии импульсы складываются.
- **Затухание падает с массой**: `v ← v · exp(−c(m) · dt)`, `c(m) = damping / (1 + m / damping_mass)` = 0.594 1/с при m = 1,
  0.055 при 1000. Скорость формально никогда не обнуляется.
- Проверка (итоговый прогон `20261015_225714_…`): дыра массы 1 брошена в землю со скоростью (4, −6, 2) = 7.48 блока/с:
  5 с — масса 64, скорость 9.78·10⁻³; 15 с — масса 354, 1.76·10⁻⁴; 30 с — масса 1730, 1.26·10⁻⁵ блока/с; всего сдвинулась
  на (2.5, −3.8, 1.3) и стоит на дне своей воронки (строки `t=5s/15s/30s: … speed … pos …`). Без поедания (дыра из
  `hole_egg` в воздухе): 6.29 → 3.47 блока/с за 1 с = `exp(−0.594)`.

### Блоки: слои-кольца изнутри наружу, два пути стирания
`core.shell(k)` лениво строит оболочку k — клетки с `floor(|d|) = k`, по расстоянию (при равенстве — нижние: воронка), кеш.
Дыра идёт курсором по оболочкам 0 … floor(R); сдвинулась на другой воксель — кольца заново. Квота копится с темпом
`rate(m)`; бюджет такта `budget_ms / число дыр`. Пропускаются воздух, жидкости, `base:bazalt`, `core:obstacle`,
неразрушаемые, многоблочные и сам `blackhole:void`.
- **Путь `set`** (волна 1): каждый съедобный блок — `block.set(x, y, z, 0)` и сущность-обломок с текстурами блока. Ждёт, если
  живых обломков уже `max_debris` — темп упирается в оборот обломков (~150–260 блоков/с у сверхмассивной).
- **Путь `fragment`** (волна 2): кольцо сканируется `block.get` (по бюджету, может растянуться на несколько тактов: счёт
  съедобных, равномерная выборка `fast_debris + 32` клеток, список несъедобных), затем одним вызовом
  `VoxelFragment:place(угол, 0)` ставится заранее собранный фрагмент-«стёрка» этой оболочки, несъедобные возвращаются
  `block.set`. Обломками-визуалом становятся только `fast_debris` (12) блоков кольца, остальные проглатываются сразу.
  Фрагмент оболочки k собирается один раз: `bjson.tobytes({version = 1, size = {S, S, S}, voxels, ["block-names"] =
  {"core:air", "blackhole:void"}})` → `generation.load_fragment(bytes)` (S = 2k + 3; 2.0 мс при k = 8, 9.0 мс при k = 14).
- **Почему `blackhole:void`, а не воздух**: `VoxelFragment::place` (`src/world/generator/VoxelFragment.cpp`) ставит только
  вокселы с ненулевым runtime-id — воздух всегда пропускается, стереть фрагментом воздухом нельзя (в движке: клетка после
  `place` — `blackhole:void`, `is_replaceable_at = true`). Как `fastblock:empty` в паке пользователя: невидимый
  (`model none`, `hidden`), не препятствие, пропускает свет, заменяемый — игрок ставит блоки поверх, выброшенные коллапсом
  блоки встают на его место. Заменять его потом воздухом не стали: это снова `block.set` на клетку.
- **Авто-выбор** (`erase_path = "auto"`): на пути set измеряется EMA мс на блок вместе с обломком; когда
  `rate(m) · dt · мс_на_блок` больше бюджета дыры — переключение, строка
  `hole 45 erase path -> fragment: block.set 0.0428 ms/block x 491 blocks/s = 1.05 ms/tick > budget 1.00 ms (R 13.77, mass 4773)`
  (прогон `20261015_224440_…`). Падающий песок (`base:falling_block`) в зоне тяги сразу становится обломком дыры (или
  проглатывается) — см. «Ограничения».
  `erase_path = "set" | "fragment"` — принудительно.

### Обломки: сходящаяся спираль и аккреционный диск
Каждая дыра имеет свой наклонённый на 6–22° диск (нормаль `N`, базис `U, V`). Обломок хранится в полярных координатах
плоскости диска: `r` (расстояние в плоскости), `θ`, `h` (высота над плоскостью), `r0` (стартовое `r`). Каждый кадр
(`on_render`, `dt` кадра), `c = 1 − r / r0` (0 у старта, 1 у центра), `ramp = min(1, t / 0.7)` (плавный отрыв):
- радиальная скорость `vr = (1.2 + 7 · c²) · (1 + m / 800) · ramp` — падение ускоряется к центру;
- угловая скорость `ω = min(16, 1.4 · (r0 / max(r, 0.4 · rh))^1.5) · ramp` — по Кеплеру, растёт к центру;
- сплющивание в диск `h ← h · exp(−dt · (0.8 + 5c) · ramp)`;
- размер `s = 0.92 · clamp((r − 0.55 rh) / (2.2 rh), 0.08, 1)` — уменьшается перед поглощением;
- собственное вращение `90 + 600c` °/с вокруг случайной оси;
- проглатывание при `r ≤ 0.55 · rh`.
В фазе коллапса всё падает втрое быстрее.

### Сущности и игрок
`entities.get_all_in_radius(center, Rp)`: каждой чужой сущности с телом `dynamic` (предметы `base:drop`, гранаты, выброшенные
блоки других дыр) — `rigidbody:set_vel(v + dir · a · dt + tang · 0.35 · a · dt)` (притяжение плюс закрутка по диску),
`a = min(45, power · 160 · (1 + m/150) / max(d, 0.7)²)`; на земле — подброс `vy ≥ 2.5`; при `d < max(0.6, 0.8 rh)` —
`despawn`, масса +4. Обломки других дыр забираются, если ближе `1.6 · rh` (или их хозяин исчез).
Игрок — `player.get_all()` и своя проверка расстояния (см. «Ограничения»), `player.set_vel` с
`a = min(45, power · 400 · (1 + m/150) / d²)`: у игрока затухание 10/с (`core:mob`), установившаяся скорость ≈ a/10 —
на 6 блоках от дыры массы ~400 это ~4 м/с, быстрее шага (2.7 м/с), бегом можно уйти. Ближе `rh + 0.9` — отброс от центра
14 м/с (вверх не меньше 4), игрок не убивается и не застревает.

### Несколько дыр: притяжение и слияние
- **Притяжение**: дыра A тянет B, если `|AB| < 2 · R(m_A)` (радиус взаимодействия = 2 радиуса всасывания, растёт с массой):
  `a_B = min(30, 2 · hole_gravity · m_A / d²)`, `hole_gravity = 0.15` (с 1.0 четыре дыры по 2000 слипались за ~0.6 с —
  перехода не видно; с 0.15 — 2.7 с). В лог — первое притяжение каждой дыры (`attracted by … distance 14.04 < 2R 21.61, a 3.05`).
- **Слияние**: `|AB| < rh(m_A) + rh(m_B)` → меньшая (при равенстве — больший uid) в фазе merging ~1 с: центр по smoothstep к
  движущейся большей, её горизонт в пост-эффекте `rh_vis → 0`; в конце большая получает массу, импульс, счётчики, обломки
  (пересчитываются в её диск), список съеденных; её `rh_vis` плавно догоняет новый горизонт. Строки `merge start: …` и
  `merge hole X (mass …) -> hole Y: mass now …, radius R0 -> R1, horizon … -> …`.
- **Мягкий переход в шейдере**: горизонты всех дыр — одно поле расстояний, объединённое smooth-min (`k = 0.5 · min(rh)`),
  линзирование — сумма отклонений: при сближении тени сливаются «перешейком», меньшая втекает и тает (кадры `merge_a`
  при u = 0.2, `merge_b` при u = 0.6, `merge_after`; на время снимка сценарий ставит `core.time_scale = 0` — время дыр
  замирает, кадр точно на середине перехода).
- Проверка «4 → 1» (прогон `20261015_225714_…`): 4 дыры по 2000 (R 10.80, горизонт 2.44, 2R 21.61) в углах квадрата
  14 × 14 → через 2.8 с одна, `mass 8733` (8000 + съеденное), `radius 10.80 -> 16.39`, горизонт 2.44 → 3.39, 3 слияния
  (`merge hole 6054 (mass 6338) -> hole 6053: mass now 8733, radius 11.35 -> 16.39, horizon 2.53 -> 3.39`); через 12 с —
  масса 11432, R 17.74.

### Коллапс
2 с: видимый масштаб `1 − u²` с дрожью, сила эффекта `·(1 + 2t)`, тембр гула вверх. В конце — выброс
`min(max_eject, round(absorbed · eject_fraction))` проглоченных блоков (из кольцевого буфера последних 600) плюс все ещё
летящие обломки как `blackhole:ejecta`: динамические тела со скоростью 7–16 (+масса) наружу и 4–9 вверх, вращаются,
`on_grounded` — ставятся там, где упали (или на 1–2 выше, если место занято), через 12 с — где есть; первые 24 блока
коллапса — `block.place` (со звуком), остальные — `block.set` без обновления соседей (см. «Ограничения»). Падающий песок
в зоне тяги проглатывается в момент коллапса. Итог в лог:
`collapse <uid> returned blocks: placed P of N`. Вспышка коллапса (1.8 с), звук `collapse`, 340 искр.

### Частицы
`gfx.particles.emit(uid дыры, -1, ...)` — постоянные искры вокруг; каждый такт — по 2 короткие вспышки на двух рукавах
логарифмической спирали `θ = φ(t) + 2.2 · ln(r / rh)` с касательной и центростремительной скоростью; всплески при
поглощении сущности, слиянии, коллапсе. Текстуры — `textures/particles/bh_spark*.png` (атлас `particles`).

## Пост-эффект: преломление и диск трассировкой луча (`shaders/effects/blackhole.glsl`, `modules/fx.lua`)
Слот `blackhole:holes`, эффект `blackhole`. `scripts/hud.lua` → `on_hud_render` → `fx.render()` каждый кадр: до 8 ближайших дыр
(дальше 160 блоков или с зоной влияния целиком за камерой — не берутся) и вспышки коллапса упаковываются
`byteutil.pack("<ffff")` → `gfx.posteffects.set_array`:
- `u_holes[i] = (x, y, z, rh)` — **мировой** центр и радиус горизонта (`rh_vis`, плавный);
- `u_info[i] = (nx, ny, nz, k)` — ось диска (наклон 6–22° или `axis` из API) и сила `k = (0.35 + 0.65 · mnorm) · vis`;
- `u_info2[i] = (spin ±1, flash, outer, merge)` — вращение, яркость вспышки (> 0 — запись-вспышка), внешний радиус диска
  `5.5 + 1.5 · min(k, 2)` в rh, фаза втекания;
- `u_count`, `u_depth` (1 — есть G-буфер, см. «Глубина»).
Камера — штатные униформы эффекта того же кадра (`u_cameraPos`, `u_view`, `u_inverseView`, `u_projection`,
`PostProcessing::configureEffect`): базис и fov не нужно дублировать `#param`, и нет отставания на кадр.

На пиксель:
1. луч `rd0 = inverse(view) · (ndc · tan(fov/2), −1)`; пересечение со сферами влияния `8 · rh` — отрезок [tStart, tEnd];
   не задел ни одну — пиксель как есть (стоимость — 8 пересечений сферы);
2. raymarch не более **72 шагов**, шаг `clamp(0.3 · (r − rh)_min, 0.04 rh, 3 rh)`; **изгиб луча** — как
   `rd = mix(rd, bdir, …)` в эталоне onigiri, но суммой по дырам: `rd ← normalize(rd − Σ K · rh · q / |q|³ · ds)`,
   `K = 1 + 0.5 · min(k, 2)`, затухание к краю зоны; вне зон — прыжок до следующей зоны;
3. горизонты — smooth-min расстояний `|q| − rh`; < 0 — луч поглощён (чёрный);
4. **диск — тонкий, процедурный**: при пересечении лучом плоскости диска (смена знака `dot(q, n)` между шагами) — три октавы
   3D-шума (`bh_noise`, как `noise(c)` в onigiri) в цилиндрических координатах диска с дифференциальным вращением
   `φ − spin · 2.4 · r^−1.5 · t` (внутри быстрее) и волокнами вдоль орбиты, от внутреннего края 2.1 rh до `outer`. **Цвет
   свой, без жёлтой заливки `getGlow`**: бело-голубой горячий внутренний край → оранжево-розовый → тёмно-красный холодный
   внешний; доплер — приближающаяся сторона ярче и синее (`g = 1 / (1 − β cos)`, `β = 0.5 · sqrt(2.1 / r)`, яркость `g³`).
   Изогнутый луч пересекает диск и над, и под тенью — «крылья», как у Interstellar;
5. не поглощённый луч уходит в экран по **новому** направлению (`u_view` → uv) — это и есть преломление сцены; за краем
   экрана — плавно в `u_skybox`; хроматическая аберрация пропорциональна отклонению;
6. вспышки коллапса — кольцо и гало.

**Глубина**: при `graphics.advanced-render = true` (у пользователя — так) есть G-буфер `u_position` (видовые координаты; небо —
нули или направление · 10⁶). Пиксель, чья поверхность ближе точки наибольшего сближения луча с центром дыры, остаётся как
есть: стена или склон перед дырой не линзируются и закрывают тень и диск. Без advanced-render G-буфера нет, `u_depth = 0`,
эффект поверх всего (как в волне 1). `fx.lua` читает `vc.get_setting("graphics.advanced-render")` при открытии HUD и раз в

## Процедурный звук (`modules/sfx.lua`)
Готовых файлов нет. WAV 16 бит, **моно**, 22050 Гц синтезируется в Lua (детерминированный шум LCG), пишется
`file.write_bytes("config:blackhole/sfx/<имя>_v1.wav", ...)` один раз — при входе в мир, если файла нет (кеш по имени и
номеру версии синтеза). Синтез всех шести — ~20–45 мс (лог `sfx ... synthesized`).
- `hum` — петля 4 с: 41.25/55/82.5/123.75/27.5 Гц (целое число периодов за 4 с — шов без щелчка), AM 0.5 и 0.25 Гц,
  низкочастотный шум, склеенный кроссфейдом 0.25 с; питч `1.25 − 0.55 · mnorm`, громкость `0.35 + 0.65 · mnorm`,
  позиция `audio.set_position` каждый такт;
- `gulp` — тон 490 → 70 Гц + полосовой шум, 0.3 с; питч варьируется ±15 % и падает с массой; не чаще 10 раз/с;
- `tick` — щелчок 2300/3450 Гц для фитиля (питч растёт к взрыву), `bounce` — глухой удар гранаты;
- `merge` — два тона сходятся (95→60 и 42→60 Гц) с шумовым вдохом и ударом; `collapse` — всасывающий подъём 0.4 с,
  удар суб-баса 55 → 22 Гц, шумовой взрыв и рокочущий хвост 3.2 с.

Проигрывание: файл → `audio.PCMStream(22050, 1, 16)` → `:feed(байты после заголовка)` → `:create_sound("bh_<имя>_v1")` →
`audio.play_sound(...)` с 3D-позицией. Почему не `audio.play_stream(путь)`: путь с точкой входа движок принимает
(`play_stream("config:blackhole/sfx/hum_v1.wav", …)` в проверке — speaker 2, `is_playing` true, `get_duration` 4.00 с), но
в 0.32.1 динамик потока не удаляется никогда (см. «Ограничения»): после ~255 звуков OpenAL перестаёт создавать источники
(«attempted to create new source, but limit is 255» — так было в первом прогоне). У звуков-ассетов динамики удаляются по
окончании (в прогоне `count_speakers` держится 2–7 при сотнях проигрываний).

## Ограничения (движок 0.32.1, обходы — в паке)
- **`audio.play_stream` течёт источниками OpenAL**: `audio::update` (`src/audio/audio.cpp`) удаляет динамик потока только при
  `!manuallyStopped && stream->isStopOnEnd()`, а у потока из `play_stream` `stopOnEnd = false` — динамик живёт вечно, даже
  после `audio.stop`. Обход — звуки-ассеты через `audio.PCMStream:create_sound` + `audio.play_sound`; WAV-файлы в `config:`
  остаются кешем синтеза. `audio.get_duration` у динамика звука-ассета возвращает 0 (длительность знает только поток).
- **`player.get_all_in_radius(center, r)` сравнивает квадрат расстояния с радиусом** (`Players::getAllInRadius`:
  `glm::length2(relativePos) <= radius`) — действующий радиус `sqrt(r)`. Обход — `player.get_all()` и своя проверка.
- **Имена предметов и сущностей — общее пространство** → сущность гранаты `blackhole:grenade_thrown`.
- **Свет сущностей**: движок берёт освещение обломка в точке сущности; обломок, пролетающий через ещё не освещённую
  полость, выглядит чёрным, пока не выйдет к свету (в тестовой аренде `graphics.backlight = false`, у игрока обычно
  включено — темнее, но не в ноль). Своего «светящегося» режима у сущностей нет (только `lighting-mode` solid/bone-based).
- `vec3.cross` в 0.32 нет — `core.cross`. `on_use` предмета повторяется, пока ПКМ зажата, — пауза 0.45 с между бросками.
- Глубина в пост-эффекте есть только при `graphics.advanced-render` (G-буфер): без него дыра за стеной видна поверх стены.
  Чёрные линии рамки выбранного блока под прицелом линза растягивает в дуги.
- **`VoxelFragment:place` не ставит воздух** (пропускает вокселы с runtime-id 0) — стирание фрагментом оставляет невидимый
  заменяемый `blackhole:void` (сохраняется с миром; блоки ставятся поверх как в воздух).
- **Звук установки блоков без ограничения голосов**: `block.place` из Lua играет звук материала (`LevelFrontend`,
  `listenBlockInteraction`); осыпание песка `base:falling_block` тоже ставит блоки `block.place`. После коллапса
  сверхмассивной и при стирании фрагментом (песок над `blackhole:void` осыпается: void заменяемый) сотни блоков
  приземлялись разом → «attempted to create new source, but limit is 255» (прогоны `223556`, `224216`, `225059`, `225330`);
  после переполнения `audio.count_speakers()` так и оставался 255 до конца — динамики без источника, похоже, не удаляются,
  и звук пропадает совсем. Обход в паке: (1) падающий песок в зоне тяги живой дыры сразу становится её обломком или
  проглатывается (`225330`: 224 блока песка, динамиков 5); (2) 20 с после коллапса падающий песок в радиусе воронки
