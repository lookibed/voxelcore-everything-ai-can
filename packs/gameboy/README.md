# Gameboy — эмулятор Game Boy / Game Boy Color для VoxelCore

Эмулятор [binjgb](https://github.com/binji/binjgb), собранный из C в WebAssembly
и оттранслированный в чистый Lua транслятором Spider. Работает в обычном
окружении VoxelCore, без нативных библиотек.

## Запуск

- **Из меню:** «Сценарии» → `gameboy`.
- **В мире:** включите пак в мире, и эмулятор откроется HUD-оверлеем.

Выберите ROM и нажмите **Start**.

## Управление

| Клавиша | Кнопка Game Boy |
|---|---|
| Z / X | A / B |
| Enter | Start |
| Backspace, правый Shift | Select |
| Стрелки | крестовина |
| Пробел | пауза / продолжить |
| `.` (точка) | один кадр (на паузе) |

Звук по умолчанию выключен, включается кнопкой **Audio**.

## Свои ROM-ы

В пак входит только свободный тестовый ROM `cgb-acid2.gbc`. Свои `.gb` / `.gbc`
положите в папку

```
<папка VoxelCore>/config/gameboy/roms/
```

Они появятся в списке с пометкой `[config]`.

**Пресет** — встроенный сценарий нажатий на первых кадрах. `auto` сам выбирает `acid2`
для cgb-acid2 и `tetris-start` для ROM-ов, чьё имя начинается с `tetris`;
для остальных пресет не нужен (`none`).

## Для скриптов

Запустить ROM из своего сценария или пака (страница или оверлей эмулятора должны быть открыты):

```lua
events.emit("gameboy:open_rom", "config:gameboy/roms/game.gb")        -- пресет auto
events.emit("gameboy:open_rom", "gameboy:roms/cgb-acid2.gbc", "none") -- явный пресет
```

Модуль эмулятора без UI: `require "gameboy:emulator"`, дальше
`create_session(path, options)`, `session:start()` и `session:step_frame()`.
Кадр приходит в поле `frame.rgba` (Bytearray RGBA).

## Производительность

Эмуляция идёт на Lua, поэтому скорость зависит от игры и машины. По умолчанию частота
ограничена родной для Game Boy (≈59.7 кадра/с, кнопка **59.7 fps lock: ON**). Без лока
эмулируется столько кадров, сколько успевает машина: игра ускоряется, счётчик fps внизу
показывает предел. Звук без лока идёт с опережением, поэтому его лучше выключить.

## Калибровка JIT при старте ROM

После **Start** эмулятор несколько секунд (обычно 2–5, не больше ~5 с процессорного времени)
калибрует JIT: статус показывает `JIT calibration ... roll N`. Скорость эмуляции в LuaJIT
случайно попадает в один из режимов, которые различаются в 1.3–2.5 раза (например, Super Mario Land
70 или 180 кадров/с), и режим решается в первые кадры. Калибровка несколько раз запускает ROM
с начала, сбрасывает скомпилированный код, замеряет скорость первых кадров и останавливается
на быстром режиме; затем игра стартует с начала. В замерах: Super Mario Land и Kirby — быстрый
режим в 8 запусках из 8 (без калибровки — 2 из 6), Tetris — примерно в 6 из 8.

## Кнопка JIT tuning

Кнопка **JIT tuning** (по умолчанию ON) на время работы страницы настраивает LuaJIT под
оттранслированный код: увеличивает кеш трасс (`maxtrace=8000`, `maxmcode=65536`) и отключает
loop-оптимизацию (`-loop`). Модулям Spider нужно несколько тысяч трасс, а стандартный кеш
вмещает 1000; при переполнении LuaJIT сбрасывает всё скомпилированное и компилирует заново.
С настройкой декодер видео и Doom работают в 3.5–5 раз быстрее, эмулятор — в 3–4 раза.
Настройка глобальная для движка, поэтому при выходе со страницы возвращаются значения по умолчанию.
