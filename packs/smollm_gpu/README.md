# smollm_gpu — Ru-Small-Instruct целиком на GPU стокового VoxelCore

Модель Ru-Small-Instruct (Llama 94M, Q8_0 — та же, что в паке `smollm`, где она идёт на CPU через wasmrt) считается
на видеокарте **внутри стокового VoxelCore 0.31 и 0.32 только средствами пака**: фреймы GUI в текстуру
(`gui.create_frame`) служат страницами памяти, свой `shaders/ui.glslf` — вычислительными ядрами, `assets.to_canvas` —
чтением результата в Lua. Весь токен (12 слоёв, логиты, argmax) — один кадр движка; логиты бит в бит с нативным C.
Разбор, все числа и план: `agents/research/SMOLLM_GPU.md`.

**Через `gpu_compute` (12.10)**: своего `ui.glslf` у пака больше нет (прежний — `shaders/ui.glslf.api.bak`); режимы —
программа `smollm_gpu` (`shaders/gpu_smollm.glsl`) в общем `ui.glslf` пака `gpu_compute`, порядок фреймов — `gc.chain`
(кеш `config:gpu_compute_order.json`), чтение — `gc.read`. Пак работает в одном мире с `gpu_worldgen`
(`tools/scenarios/gpu_compute_both.py`); общий шейдер стоит ~5% ток/с (регистры, `content/gpu_compute/README.md`).

## Запуск
- Пользователю: меню **«Сценарии» → smollm_gpu** — **чат** (12.10): поле внизу — сообщение, Enter или «Отправить»; модель
  печатает ответ по токенам (**один токен = один кадр движка**: весь forward 12 слоёв — один кадр GPU), строка статуса —
  фаза (загрузка/сборка конвейера, обработка промпта, генерация, готова), ток/с и контекст из 512. «Стоп» прерывает
  (и prefill), «Очистить» сбрасывает контекст и ленту, флажок «помнить диалог», «Демо» — прежнее демо (три эталонных
  промпта 1, 2, 4 с ответом, prefill мс/токен, ток/с и совпадением с эталоном C; «Назад» — обратно в чат), «Назад» — в
  главное меню. Первый запуск на экземпляре — ~13–16 с на загрузку и поиск порядка фреймов (дальше кеш
  `export:smollm_gpu_order.txt`: повторный вход в чат — конвейер за 0.75 с на v032).
- Разработка (лаборатория, без кликов): `tools/scenarios/smollm_gpu_chat.lua` — чат при старте (флаги ниже);
  `smollm_gpu_check.py` / `smollm_gpu_dialog.py` — проверка и диалог (раздел «Чат»); `tools/scenarios/smollm_gpu_demo.lua` —
  демо при старте; пробы и замеры — `LAB_OWNER=<имя> python3 tools/scenarios/smollm_gpu_run.py v031|v032 --probe q12|matvec|llm|all
  [--variant v1|v2] [--noprofile] [--shot NAME]` (аренда `wasmrt engine_rt`, вывод — строки `[sg] …` из latest.log).

## Чат (12.10, агент llm_gpu_chat)
Ход: вопрос → шаблон карточки `<|юзер|>\n{q}\n<|юзерзакончил|>\n<|я_начал|>\n` (без BOS) → **BPE на Lua** → prefill по
токену за кадр с текущей позиции → первый токен → генерация до `<|я_закончил|>` (7) / `<|endoftext|>` (3) / `max_new` /
«Стоп» / 512. Конец ответа (7) кладётся в KV-кэш (+1 кадр), как `main_vc.c` CPU-пака.
- **Токенизатор** `modules/bpe.lua` (+ `modules/unicode_tables.lua`): перенос 1:1 `real-world-smollm/src/tokenizer.c` —
  спецтокены отрезаются до BPE (самый длинный в позиции), регэксп GPT-2 `'s|'t|'re|'ve|'m|'ll|'d| ?\p{L}+| ?\p{N}+|
  ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+` по таблицам Unicode 13 (\p{L} 622, \p{N} 133, \s 10 диапазонов, двоичный поиск),
  слияния по рангу (все вхождения лучшей пары слева направо), без byte_fallback/NFC. Таблица GPT-2 `bytes_to_unicode` уже
  обращена при экспорте `tokenizer.bin` (словарь — сырые байты), поэтому в Lua её нет. Загрузка 10 мс, 26 фраз — 4 мс.
  Чистый Lua без API движка: тот же файл гоняет стенд на стоковом luajit (Spider `tests/manual/real-world-smollm-gpu/chat/`).
- **Паритет токенизатора**: 26 фраз `tok_check.py` (0 расхождений C с HF) + 300 случайных (кириллица/латиница, цифры,
  пунктуация, пробелы/`\n`/`\t`, спецтокены, `'s`, эмодзи, CJK, NBSP) — ids бит в бит с C-кодером `run_native --tok-test`:
  стенд luajit **326 фраз / 7623 токена, 0 расхождений**; в движке (export-флаг, `smollm_gpu_check.py`) **v031 и v032 — 326
  фраз, 7623 токена, 0 расхождений**, decode == вход (байт в байт) везде; промпты 1, 2, 4 с шаблоном → `data/proto/ref_prompts.json`.
- **Семплирование** (`modules/chat.lua`, по карточке https://huggingface.co/longtimedevs/Ru-Small-Instruct): умолчания
  temperature 0.25, top_p 0.85, repetition_penalty 1.15, max_new 120. Логиты целиком — фрейм LG одним `get_data`
  (FFI-указатель Bytearray, 24576 float из 2 текселей) → штраф HF по всем токенам текущего контекста (`logit > 0 ? /p : *p`)
  → softmax(logit/T) → top-p как `sample_token` в `model.c` (отсечка (1−p)/(n−1), сортировка, накопление до > p,
  монета·cum) — в double; ГПСЧ Park–Miller, seed 1 на сессию (ответы воспроизводимы: v031 и v032 дают одни и те же).
  **argmax-режим** (temperature 0 и penalty ≤ 1, паритет лаборатории `0 0.85 1 120`): индекс максимума считает GPU (AM2,
  1 тексель), логиты не читаются — как демо.
- **Контекст**: по умолчанию сбрасывается перед каждым вопросом (pos 0; модель одноходовая — с историей копирует прошлую
  тему/ответ, как и нативный C, см. `content/smollm/README.md`); «помнить диалог» — продолжение с текущей позиции, ход с
  новой строки (`\n<|юзер|>…`), переполнение 512 → сброс. KV-кэш живёт во фреймах KA/KB/VA/VB: между ходами `llm.idle(true)`
  скрывает все картинки, кроме копирования KA↔KB / VA↔VB (иначе скрытый фрейм очищается и кэш пропадает), KVPUT скрыт.
  «Сброс» = pos 0 (строки ≥ pos не читаются). «Демо» пишет кэш с позиции 0 → после него контекст сбрасывается.
- Флаги прямого запуска (`export:` экземпляра, `tools/scenarios/smollm_gpu_chat.lua`): `smollm_gpu_params.txt` — «t top_p rep
  max_new»; `smollm_gpu_remember.txt` — «1»; `smollm_gpu_prompt.txt` — автовопрос после сборки; `smollm_gpu_dump_logits.txt`
  — логиты первого токена каждого ответа → `export:smollm_gpu/last_logits.f32`; `smollm_gpu_toktest.txt` — фразы →
  `export:smollm_gpu_toktest_out.txt`. Лог: `[smollm_gpu] prompt: / prompt tokens (n, from pos p): / prefill … / reply tokens: /
  reply: / reply timing: decode N frames … / reply done: …`.

## Состав
- `shaders/ui.glslf` — шейдер UI движка + режимы вычислений: картинка с цветом `#FF<режим>FF80` (R=255, B=255, A=128)
  считает режим, номер — байт G; параметры — `region="P,Q,P,Q"`. Точная арифметика — fp64 (`GL_ARB_gpu_shader_fp64`).
- `modules/llm.lua` — вся модель: загрузка страниц весов, 418 ролей-фреймов, порядок отрисовки, токен/позиция, argmax,
  логиты целиком (`logits_f32`), простой/пробуждение (`idle`/`wake`), `ensure_pipeline`, проверки, профиль, `M.demo`.
- `modules/chat.lua` — чат: состояние страницы, BPE-ход, prefill/генерация по кадру, семплер, KV между ходами, `launch`.
- `modules/bpe.lua`, `modules/unicode_tables.lua` — BPE-кодировщик и классы Unicode регэкспа GPT-2 (чистый Lua). `modules/matvec.lua` — прототип матвека и проба точности; `modules/probe.lua` — чтение
  пикселей и порядок фреймов.
- `layouts/pages/smollm_gpu_chat.xml(.lua)` — страница чата; `layouts/pages/smollm_gpu.xml(.lua)` — страница демо;
  `scripts/app/smollm_gpu.lua` — пункт «Сценарии» (чат).
- `data/gpu/` — `weights.bin` (117 canvas-образов RGBA 768 × rows, 3 байта данных на тексель), `index.json`, `tok.bin`
  (эмбеддинги int8 + масштабы), `rope.bin`; `data/proto/` — страницы и эталоны проб, `ref_prompts.json`, логиты C;
  `data/tokenizer.bin` — словарь BPE (кодирование вопроса и показ текста). Сборка данных — Spider `tests/manual/real-world-smollm-gpu/` (README).

## Ограничения
- Контекст 512, при переполнении «помнить диалог» сбрасывается целиком (без скользящего окна). NFC-нормализации нет (как у
  C-кодера; ввод движка — уже NFC). Семплер в double, а не во float C: в режиме семплирования с CPU-паком совпадает
  распределение, а не конкретный ответ (ГПСЧ свой); бит в бит — argmax-режим.
- Шрифт движка: нет «—» (показывается «-»), лента без масштабирования.
- Пак заменяет `ui.glslf` целиком: цвет `#FF??FF80` у любой картинки UI станет вычислением. Нужен fp64 в шейдерах.
- Фреймы рисуются движком каждый кадр: веса копируются в страницы каждый кадр (~4 мс), пока экземпляр открыт — GPU
  нагружена (после демо картинки скрываются; GPU 43–49 % против 25–40 % фона рабочего стола). Выход из страницы
  (`app.reset_content`) снимает фреймы.
- Первый запуск на экземпляре — 12–13 с на поиск порядка фреймов (порядок хеш-таблицы движка).
