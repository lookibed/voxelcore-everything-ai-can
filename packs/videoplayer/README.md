# Video Player — MP4 (H.264) видеоплеер для VoxelCore

Декодер [h264bsd](https://github.com/oneam/h264bsd) и демуксер
[minimp4](https://github.com/lieff/minimp4), собранные из C в WebAssembly и
оттранслированные в чистый Lua транслятором Spider. Кадры выводятся на canvas.

## Запуск

- **Из меню:** «Сценарии» → `video_player`.
- **В мире:** включите пак в мире, и плеер откроется HUD-оверлеем.

Выберите видео и нажмите **Open**. Видео декодируется потоково, прямо во время
просмотра: кадры готовятся в фоне на полсекунды-секунду вперёд и держатся в кэше
(до 384 МБ), окно при этом не замирает.

| Клавиша | Действие |
|---|---|
| Пробел | воспроизведение / пауза |
| ← / → | предыдущий / следующий кадр |

Воспроизведение идёт с частотой из таймкодов mp4 (кнопка **fps lock: ON**); если декодер
не успевает, плеер ждёт следующий кадр. Без лока каждый кадр показывается сразу, как только
декодирован, а в строке статуса видна достигнутая частота. Звук не поддерживается.

## Свои видео

В пак входит только короткий тестовый ролик `sample.mp4`. Свои `.mp4` положите
в папку

```
<папка VoxelCore>/config/videoplayer/videos/
```

Они появятся в списке с пометкой `[config]`.

Поддерживается только H.264 **baseline** profile без B-кадров. Любое видео
можно перекодировать так (звук отбрасывается):

```
ffmpeg -i input.mp4 -an -c:v libx264 -profile:v baseline -pix_fmt yuv420p -bf 0 output.mp4
```

Декодирование идёт на Lua: ролик 432×240 декодируется примерно за 30 мс на кадр
(быстрее реального времени), 1280×720 — около 0.2 с на кадр вместе с переводом в RGBA
(зависит от машины; цифры при включённой кнопке JIT tuning). Большие ролики
проигрываются медленнее реального времени.

## Для скриптов

Открыть и декодировать видео из своего сценария или пака (страница или оверлей плеера должны быть открыты):

```lua
events.emit("videoplayer:open_video", "config:videoplayer/videos/clip.mp4")
```

Флаг `true` вторым аргументом сразу включает воспроизведение:
`events.emit("videoplayer:open_video", path, true)`.

Декодер без UI: `require "videoplayer:decoder"`, дальше `create_session(path)`,
`session:open()` и `session:next()` (следующий кадр или `nil` в конце). Кадр
приходит в поле `frame.rgba` (Bytearray RGBA). Если `next()` вызывается из
корутины, назначенной через `session:set_driver(co)`, декод длинного кадра сам
уступает управление по истечении кванта `session:begin_slice(секунды)`.

## Кнопка JIT tuning

Кнопка **JIT tuning** (по умолчанию ON) на время работы страницы настраивает LuaJIT под
оттранслированный код: увеличивает кеш трасс (`maxtrace=8000`, `maxmcode=65536`) и отключает
loop-оптимизацию (`-loop`). Модулям Spider нужно несколько тысяч трасс, а стандартный кеш
вмещает 1000; при переполнении LuaJIT сбрасывает всё скомпилированное и компилирует заново.
С настройкой декодер видео и Doom работают в 3.5–5 раз быстрее, эмулятор — в 3–4 раза.
Настройка глобальная для движка, поэтому при выходе со страницы возвращаются значения по умолчанию.
