# model_ref — модели из Blender в VoxelCore: экспорт и покадровое попиксельное сравнение

Инструмент лаборатории (07–08.11.2026). Два вопроса:
1. Как получить из любой сцены Blender файлы движка: VCM, PNG, VCA.
2. Выглядит ли экспорт в движке так же, как в Blender, кадр за кадром.

MCP (сервер `voxelcore`):
- `vc_model_export {blend, anims?}` — только экспорт.
- `vc_model_ref {blend, anims?}` — экспорт и сравнение. Возвращает вердикт OK/FAIL с причинами и костями, таблицу,
  разницу с прошлым прогоном и худший кадр картинкой.

```bash
python3 -m vclab.model_ref.model_ref --blend hero.blend                        # экспорт + сравнение
python3 -m vclab.model_ref.model_ref --blend hero.blend --anim walk=0-24 --anim run=@Run
python3 -m vclab.model_ref.model_ref --blend hero.blend --export-only          # только файлы движка
python3 -m vclab.model_ref.model_ref --blend b.blend --vcm m.vcm --png t.png --anim walk=walk.vca@0   # свой экспорт
# сравнение — тяжёлая задача: heavy --label model_ref -- ...  (MCP vc_model_ref сам идёт через heavy)
# код выхода: 0 — все кадры в пределах порогов, 1 — есть провалы, 2 — сам прогон не удался
```

Подробности запуска:
- **Каталог результатов** по умолчанию `<work_root>/model_ref/<имя>`, обязательно на диске Windows: Blender — программа Windows.
- **Blender** ищется так: `machine.toml` → ключ `blender`, затем `$BLENDER`, затем обычные места установки.
- **Демон для аренды** — `--daemon`, по умолчанию 25802 (свой изолированный, не игровой).

## Экспорт (`blender_export.py`)

Риги:
- **Иерархия объектов.** Каждый анимированный объект (empty, меш и т. п.) становится костью. Статичные меши
  прицепляются к кости, на которой висят.
- **Armature.**
  - Кости переносятся как есть.
  - Меш, привязанный к кости, жёсткий.
  - Меш со скиннингом (модификатор Armature) делится по треугольникам: каждый треугольник уходит к кости с наибольшим весом.
    В VCM нет скиннинга, поэтому смешанные веса попадают в предупреждения.
  - Кости без геометрии ниже себя отбрасываются.

Покой:
- У Armature — REST.
- У объектов — кадр `--rest-frame`, по умолчанию начало сцены. При `--rest identity` (по умолчанию) поворот
  анимированных объектов в покое сбрасывается, а позиция остаётся.

Анимации — `--anim`:
- `имя=НАЧАЛО-КОНЕЦ` — отрезок таймлайна, конец включается.
- `имя=@Action` — action ставится на арматуру; если арматуры нет — на анимированные объекты.
- Без `--anim` берутся маркеры таймлайна: каждый маркер открывает отрезок до следующего маркера, маркер `_…`/`end` только
  закрывает отрезок. Если маркеров нет — весь диапазон сцены.
- Каждый кадр запекается (`curve linear`), поэтому на кадрах интерполяция Blender воспроизводится точно.

Соглашения движка, проверенные сравнением на 0.32.7:
- **Оси.** VC `(x, y, z)` = Blender `(x, z, -y)`. Плоскость z = 0 Blender — это y = `root_y` (-0.5) от сущности.
- **Позы и вершины.**
  - Поза кости — `translate(t) · Rx·Ry·Rz`; в VCA это градусы, порядок XYZ, что равно Euler 'ZYX' в Blender.
  - Опорная точка (pivot) — начало кости. `@bone move` задаётся относительно родителя, точки `@tri` — относительно кости.
  - Лицевая сторона треугольника — обход против часовой стрелки. UV в `@tri` такие же, как в Blender.
- **Текстуры.** Картинка материала (лучше та, что подключена к Base Color) уходит в PNG `$i` без цветокоррекции. Материал без картинки даёт
  сплошной PNG цвета Base Color в sRGB.

На выходе:
- `<имя>.vcm`, PNG, `<anim>.vca`;
- `export.json`: кости, опорные точки, текстуры, анимации, предупреждения;
- с `--poses` — ещё `<имя>_poses.json`: позы костей на каждом кадре и полукадре, в осях VC.

## Сравнение

- **Движок.**
  - F2F-аренда `vc/vctest_window`: окно hidden, 854×480, часы virtual, ввод изолирован; флаги проверяются.
  - `stand.lua` создаёт мир с паком `refview/`: одна статичная сущность и камера.
  - F2F-команда `ref` (из мирового скрипта пака) грузит модель так же, как игровой клиент:
    `assets.parse_model` со скелетом из именованных `@bone`, `load_texture`, `parse_animation`.
  - F2F `render`: только слой `entities`, без освещения (fullbright), фон `#FF00FF`; `graphics.ssao = 0`
    (`--ssao 1` — как в игре).
  - Поза: `reset_pose()` и дорожка в точное `t = k/fps`, затем `step` и `shot`.
- **Blender** (`blender_frames.py`):
  - та же камера, без сглаживания, прозрачный фон (альфа = силуэт), Raw;
  - повторяется затенение моделей движка: `тексель × (0.8 + 0.2·dot(нормаль грани, SUN))`, где
    `SUN = (0.411934, 0.863868, -0.279161)` (`ModelBatch::draw`); для скиннинга берётся нормаль деформированной грани;
  - задние грани отсекаются;
  - `--shading flat` — только тексели.
- **Метрики кадра:**
  - IoU силуэтов и пиксели, которые есть только с одной стороны (геометрия, поза);
  - внутри общего силуэта — ошибка цвета (текстура, UV, затенение): средняя, p95, доля пикселей с ошибкой > 24/255.
- **Выход:**
  - `blender/`, `engine/`;
  - `diff/<кадр>.png` — Blender | движок | карта: красный — только Blender, голубой — только движок, жёлтый — цвет
    расходится больше чем на 24, серый — мелкая разница;
  - `sheet_<anim>_<ракурс>.png`, `summary.json`, `report.md`, `progress.log`, `history.jsonl`;
  - `report.html`: вердикт, таблица, разница с прошлым прогоном; проваленные кадры обведены красным.

## Ракурсы, вердикт, история

- **Ракурсы.**
  - Экспортёр пишет `track.json`: габариты модели за все кадры всех анимаций, а для каждого кадра — опорную точку
    кости и центр её геометрии.
  - Камера для каждого ракурса ставится так, чтобы шар, описанный вокруг габаритов, целиком помещался по
    вертикальному углу обзора 40°. Поэтому модель любого размера занимает кадр.
  - `--views`: по умолчанию `front34,back34`; ещё есть `front`, `back`, `left`, `right`, `top`. Перед модели —
    сторона −Z, как у сущностей движка.
  - `--cam` задаёт одну свою камеру вместо ракурсов.
- **Вердикт по кадру.** Кадр проваливается, если выполнено хотя бы одно:
  - `IoU < --min-iou` (по умолчанию 0.999);
  - доля пикселей с ошибкой цвета больше 24/255 превышает `--max-bad-color` (по умолчанию 1 %);
  - средняя ошибка цвета больше `--max-color-mean` (по умолчанию 3/255).

  У проваленного кадра указаны кости: пиксели расхождения отнесены к ближайшему на экране отрезку
  «опорная точка → центр геометрии» кости. Там, где кости перекрывают друг друга на экране, оценка приблизительная.
- **История.**
  - Прошлый `summary.json` в том же `--out` (или `--baseline`) служит эталоном. Для каждой пары анимация@ракурс
    сравниваются IoU min, средняя ошибка цвета и число проваленных кадров; ухудшение помечается `WORSE` и попадает в
    строку вердикта.
  - Каждый прогон дописывается в `history.jsonl`, предыдущая сводка сохраняется в `summary.prev.json`.
  - С `--vcm` (свои файлы) `track.json` берётся из каталога VCM, если он там есть.

Пример (порча: нога в `walk.vca` повёрнута на лишние 5°, сравнение с прошлым прогоном):

```
FAIL: 12 of 36 frames below the thresholds; worst walk_000_front34: IoU 0.9832 < 0.9990 (741 px only one side)
  — bones leg_l 95%, leg_r 3%, body 1% | WORSE than the previous run: walk@front34 IoU 0.9999->0.9832, ...
```

## Образцы и эталонные числа (`samples/`)

```bash
blender -b --factory-startup --python vclab/model_ref/samples/walker.py  -- <каталог>   # иерархия объектов
blender -b --factory-startup --python vclab/model_ref/samples/critter.py -- <каталог>   # Armature + скиннинг
```

Ракурсы front34 и back34, все кадры:

| образец | что проверяет | кадров | IoU мин. | пикс. с одной стороны, макс. | ошибка цвета, макс. | плохой цвет, макс. | вердикт |
|---|---|---|---|---|---|---|---|
| walker (маркеры walk/idle) | empties-кости, текстура в .blend | 144 | 0.9999 | 5 | 0.47 | 0.1 % | OK |
| critter (`wag=@Wag nod=@Nod`) | Armature с поворотом в покое и roll, скиннинг, меш на кости, сплошной цвет, кватернионы, actions | 80 | 0.9999 | 2 | 0.57 | 0.1 % | OK |

Экспорт walker совпадает с первым рукописным экспортом этого персонажа с точностью до 1e-5.

Проверка чувствительности: ногу walker повернули в VCA на лишние 5°. Результат — FAIL, IoU 0.9832, 741 пиксель,
кость leg_l (85–100 % расхождения), WORSE против прошлого прогона, код выхода 1.

Что нашлось при настройке:
- без выключения SSAO ошибка цвета 3.5/255 и тени в углах;
- без затенения граней — 17/255;
- если Blender не отсекает задние грани, видны внутренние грани там, где детали входят друг в друга.
