# Агенту в этом репозитории

Среда и инструменты лаборатории VoxelCore. Паки и проекты лежат только на диске (`packs/*`, `projects/*` в `.gitignore`);
у проекта свой git, свой `CLAUDE.md` и свои скиллы (`projects/<имя>/.claude/skills`). Этот репозиторий и проекты друг в
друга не проникают (`docs/RULES.md` 5.7).

Прочитать перед работой: `docs/ONBOARDING.md` (начало сессии, свой изолированный демон), `docs/RULES.md` (правила
пользователя с причинами), `docs/AGENT_PRACTICES.md` (как довести задачу до принятого результата). Скиллы:
- `lab-engine-test` — **до первого запуска движка в сессии**;
- `lab-cli` — демон, аренды, прогоны сценариев, `heavy`, чтение отчётов;
- `engine-source` — как отвечать «как это устроено в движке» по исходникам нужной версии;
- `model-ref` — модели и анимации из Blender: экспорт и покадровое сравнение по пикселям;
- `session-recovery` — после сжатия контекста или обрыва сессии.

Жёстко, без исключений:
- Движок — только арендой Lab (`lab_lease` + `lab_f2f`), тестовая сборка F2F. Стоковый `VoxelCore.exe` запускает
  пользователь. Ввод ОС запрещён.
- Окно аренды — `hidden`, кадр 854×480, часы `virtual` (кадры по `step`), звук 0 (его гарантирует ядро). Перед словами
  «скрыто/изолировано» сверить `hello.flags` из ответа аренды. Увидел `window: normal` без просьбы — сразу `lab_release`.
- Чужой/скачанный проект — вид `vc user_project` (`params.src` = копия под `D:\…\work\`), не `vc_start` и не установка
  пользователя.
- Сначала состояние (логи аренды, отчёт прогона, F2F `state`, позиция курсора F2F — стартует в 0,0), потом гипотезы.
  Ждать — `step` и условия, не `sleep`.
- Чужие аренды и демоны не трогать; свои — освободить. Ничего не убивать без ведома пользователя. Перезапуск демона,
  на котором работает пользователь, — только с его «да». Хук `.claude/hooks/guard.py` пользователя ни о чём не
  спрашивает: запреты (ввод ОС, стоковый exe) отклоняет, перед рискованным напоминает агенту правило; git не трогает.
- Коммит и пуш — только по просьбе; в коммит — только свои файлы поимённо.
